## 1. 关卡概述

机器人从起点出发，在右侧区域找到约 10cm 见方的**蓝色软海绵**（无 AprilTag，纯颜色识别），双臂抱起后转向左侧目标板（竖贴 AprilTag ID=38），靠近并放置，最后根据终点立牌上的 AprilTag ID=26 调整方向走出出口。裁判系统靠自身的红外对射与重量传感器独立打分，**机器人与裁判之间零网络耦合**——机器人不上报任何消息。

核心考察点：颜色识别、AprilTag 定位、双臂抓取、行走控制与多动作配合。

## 2. 关卡要求

### 2.1 任务流程

```
起点(入口红外) ──► 右侧区域: 寻找蓝色海绵(~10cm³, 无Tag) ──► 双臂抱起
      ──► 左侧区域: 目标板(22.5cm 亚克力板靠墙, 上方墙面竖贴 Tag 38) ──► 靠近并放置
      ──► 终点: Tag 26 立牌, 调整方向后走出出口(出口红外) ──► 结算
```

- 货物：蓝色软质海绵，约 10cm×10cm×10cm，**不贴任何标签**。
- 目标板：约 22.5cm×22.5cm 黑色亚克力载物板，紧靠墙面放置，板上方墙面贴 Tag 38（tag36h11）。
- 终点：贴 Tag 26 的立牌。
- 场地：左右两区，中间设红色循迹线（说明书称用于辅助进场或出场）；红外对射分别在出入口。

### 2.2 评分规则（满分 10）

| 项目 | 分值 | 判定方式 |
|---|---|---|
| 货物分 | 6 | **结算瞬间** HX711 检测到稳定增重（原始值增量 ≥ 阈值、连续 5 次采样）才得分。注意：放上又拿走会丢分 |
| 时间分 | 4 | 入口红外触发计时：≤120s 得 4 分；≤180s 得 3；≤240s 得 2；≤300s 得 1；超 300s 得 0 |

超五分钟任务强制结算，但已完成的项目照常计分。

### 2.3 裁判系统

- 硬件：ESP32-S3-WROOM-1-N16R8 + HX711 重量采集模块（装在载物板下方）+ 入口/出口两路红外对射。
- 接线：HX711 DOUT→GPIO4、SCK→GPIO5；入口红外 OUT→GPIO6；出口红外 OUT→GPIO7。红外模块 5V 供电时 OUT 必须**分压后**接入 ESP32（GPIO 不耐 5V）。
- 流程：`start` 命令后 HX711 采 40 个空载值建基线 → 入口红外被遮挡开始计时 → 出口红外被遮挡（或 300s 超时）结算。
- 网络裁判：ESP32 主动连上位机 TCP 8765（`network_judge_server.py`，纯标准库回显控制台）；**断网不影响本地评分**，重连后补发缓存的 FINISH JSON。

### 2.4 文档与代码的矛盾点（现场必须实测确认）

| 项 | 说明书 | judge.ino 代码 | 结论 |
|---|---|---|---|
| 红外极性 | LOW=通光、HIGH=遮挡（两路一致） | 入口 GPIO6 **LOW=遮挡**，出口 GPIO7 **HIGH=遮挡**（两路相反） | 必有一方不符，现场实测定案 |
| Wi-Fi SSID | `eelab901_2` | `eelab901b_2`（多一个 b） | 二者其一过时 |
| 默认上位机 IP | 占位 `192.168.1.100` | `" 192.168.31.145"`（**带前导空格，connect 必失败**） | 首次使用必须 `net host` 重设 |
| 命令列表 | 含 `set 1 <us>` / `add 1 <us>` | 代码无这两条（回 unknown_command） | 旧版残留 |
| 巡线 | README 称开机沿红线走到海绵区 | **巡线整套是死代码**（见 §4.1） | 实际全靠视觉+开环步数 |

## 3. 参考实现分析

### 3.1 总体架构

```
机器人端 (apriltag_sorting_task.py, 1145 行)        裁判端
┌────────────────────────────┐              ┌──────────────────────────┐
│ 主线程: 视觉(读帧→去畸变→蓝色   │   无任何网络   │ ESP32-S3: 红外计时 + HX711 │
│ 检测+Tag PnP → 加锁写共享变量) │ ◄── 零耦合 ──► │ 称重 + 评分 + FINISH JSON  │
│ 动作线程: 五态状态机          │              │ PC 端: TCP 8765 回显服务器 │
└────────────────────────────┘              └──────────────────────────┘
```

### 3.2 机器人端逻辑（apriltag_sorting_task.py）

**平台与依赖**：TonyPi 树莓派，Python 3 + OpenCV + NumPy + Hiwonder SDK（`ActionGroupControl` / `apriltag` / `ros_robot_controller_sdk` / `yaml_handle`）。640×480 视频流，标定 npz 去畸变后 PnP 用新内参+零畸变。路径硬编码 `/home/pi/...`，启动时停系统服务并强杀四个可能占用串口的进程。

**状态机**（初始 `SEARCH_OBJECT`，动作在 daemon 线程执行）：

```
SEARCH_OBJECT ──颜色对正+凑近──► PICK_OBJECT ──move_up抱起+夹爪闭合──► 低头验证
                                   ├─ 验证失败(≤3次): 后退重来
                                   └─ 成功: 左转9次+前进5步(开环, 全程锁臂)
                                          ──► SEARCH_TARGET_AREA
SEARCH_TARGET_AREA ──PnP闭环接近Tag38──► PLACE_OBJECT ──put_down+后退5步──► FINISH
FINISH ──► 找Tag26: 小步转对正 yaw∈(-15°,5°) ──► 大步直行10步穿过出口
```

**蓝色海绵检测**：缩到 320×240 → 高斯模糊 → BGR→LAB → 按 `lab_config.yaml` 的 `"blue"` 阈值 inRange → 开闭运算 → 最大轮廓（面积下限 500）→ minAreaRect。cx/cy/角度/面积各过一路卡尔曼滤波。不做立体检测，直接用颜色中心点定位。

**AprilTag 位姿**：`hiwonder.apriltag` 检测（tag36h11），物方点按 5cm 边长构造，`solvePnPGeneric(IPPE)` 取双解，**选 pitch 绝对值最小的解**（利用"Tag 竖直贴墙、平视拍摄"先验），由 `-R.T @ tvec` 导出四个量：distance（3D 距离）、offset（水平偏移）、forward（纵深）、yaw（朝向偏差）。

**对齐逻辑（四套）**：
1. `approach_color`：四步状态机——转身对中（|dx|>80 大转）→ 横移（|dx|>40）→ 微调（|dx|>20）→ 小步凑近（cy 分区 250/340/390），像素基准 CENTER_X=350（画面几何中心 320，差值是相机安装偏移）。
2. `creep_to_pick_distance`：最多 30 次迭代，到达条件面积 ≥8000 或 cy≥380；cy≥420 判太近后退。
3. `approach_tag`：纯 PnP 距离分带——≥0.33m 远区（转身对正→前进，0.6m 以上用大步）；0.25~0.33m 近区（小转→平移 30→小平移→到位）；<0.25m 后退。阈值含 8cm 板厚补偿（`BOARD_DEPTH_M`）。PnP 失败退化为像素 cy 控制。
4. `navigate_to_end_tag`：头部打平视脉宽 → 最多 30 次小步转直到 yaw∈(-15°,5°) → 重置卡尔曼 → 直行 10 大步，每步检查 yaw 越界补一小转。

**抓取/放置/验证**：
- 抓取：头回中 → 前进 2 小步 → `move_up` 抱起 → 直接下发 8/16 号舵机脉冲闭合夹爪（`GRIP_SCALE=1.0` 时 8→0、16→1000）→ 后续行走动作全部传 `LOCK_SERVOS`（6/7/8/14/15/16 号舵机固定位）锁臂。
- 抓取验证：头部下压采 15 帧（100ms 间隔），连续 3 帧看到蓝色且面积>2000 判定"没抓到"。
- 放置：前进 1 小步 → 解锁 → `put_down` → `back_fast`×5 → stand。

**搜索**：`scan_head_or_turn` 照搬官方 Transport——头部按 0.5s 步进左右/上下扫描，扫完原地 `turn_right` 两大步换视野。

### 3.3 裁判端逻辑

**judge.ino（ESP32-S3）**：状态机 `IDLE → CALIBRATING → ARMED → RUNNING → FINISHED`。红外每 10ms 采样、连续 3 次同向确认边沿（时间戳取首次检测时刻）；HX711 开跑前 40 点建基线，运行中 5 点滑动平均 + 迟滞带（`max(500, threshold/5)`，默认阈值 10000 raw），连续 5 次超阈值判"货物在秤上"。评分：先记时间满分 4，按耗时档位扣成 penalty；结算那一刻 `stableAboveBaseline` 为真才加货物 6 分。

**通信协议**（一行一条、`\n` 结尾，串口与网络同源）：
- 上行事件：`EVENT sensor=S1 type=ROBOT_DETECTED event_ms=...`、`TIMER_STARTED`、`EVENT sensor=WEIGHT type=STABLE_ABOVE_BASELINE ...`、`CALIBRATION_BEGIN/DONE`、`SETTLEMENT reason=... time_score=... cargo_score=... final_score=...`。
- 结束消息（具身智能课程关卡接口标准 v1）：`{"module_id":1,"robot_id":1,"device_ip":0,"event":"FINISH","timestamp":68,"penalty":0,"score":10}`；断线时缓存，重连随 hello 补发。
- 下行命令：`start`、`status`、`stream on/off`、`net host/port`、`weight set <raw>`、`ids <module> <robot> <ip>`、`time <unix_seconds>`。

**network_judge_server.py**：仅是"串口监视器的网络版"——回显收到的一切、把键盘输入原样转发给裁判模块，不解析不存库。

## 4. 不足之处

### 4.1 参考代码缺陷（均已亲自读码核实）

1. **PnP 失败可在任意距离触发提前放置**（`apriltag_sorting_task.py:621`）：`distance==0`（PnP 失败）进入远区分支后，若 Tag 大致居中且 `cy>235`，落到 `:636-638` 的 else 分支直接 `return True`（"已到位"）触发放置。此时横向偏差可达 150px、距离未知，海绵可能放不到秤上——直接丢 6 分。
2. **`distance` 与 `forward` 共用同一个卡尔曼滤波器**（`:435` 与 `:437` 都是 `self.kf_dist`）：两个不同物理量交替喂入互相污染，属于真实建模错误，仅因二者数值接近才"碰巧能用"。
3. **FINISH 语义过载**：抓取重试超限 → `FINISH`（`:985`），而 `run()` 只见 `FINISH` 就走出终点（`:1077`），不区分是否完成放置。空手机器人照样冲出口。按评分规则这反而能捡到时间分，但属**无意识的巧合而非设计**。
4. **搜索转身方向参数被忽略**：`scan_head_or_turn(turn_direction="left")` 传入（`:607`），函数体内写死 `turn_right`（`:333`）。左转过头的回找恰好靠右转兜住，纯靠巧合。
5. **无任何时间管理**：没有总超时、没有按 120/180s 档位的策略，凑近失败无限重试，全靠裁判 300s 兜底——而时间分占 4/10。
6. **文档与代码严重不符**：README 宣称的红线巡线整套代码（约 150 行 HSV 巡线 + `--line-initial-steps` 等 3 个参数）是**死代码**，无调用点；另有从未被调用的 `place_custom`、定义未用的 `TAG_NEAR_Y`/`END_FORWARD_TOL` 等。
7. **写死的场地假设**：抓后走位"左转 9 次+前进 5 步"纯开环计数；Tag 尺寸 5cm、板厚 8cm、全部阈值面向该场地一次标定；路径硬编码，换场地/换机器需全部重标。

### 4.2 与本仓库平台的差异（不可照搬项）

- **视觉获取方式不同**：参考代码用 640×480 视频流连续闭环；本仓库既定决策是 fswebcam 静态拍照（D2，`core/robot_core.py` 的 `capture_frame`）。所有对齐逻辑需改造为"拍照→决策→动作→再拍照"节奏——nine_grid 的 APPROACH→ENTER→CONFIRM 三段闭环已在此节奏下真机验证，可行。
- **抓取动作组零标定**：`move_up`/`put_down`/`back_fast` 及夹爪舵机在本仓库机器人上从未实测（`docs/比赛相关材料/机器人调用说明.md` 明确警告这些动作未标定位移且可能大幅摆动）。这是全关卡唯一的全新硬件能力，也是最大风险项。
- **蓝色阈值来源不同**：它读 `lab_config.yaml`；按本仓库架构铁律，颜色阈值等决策常量应放关卡文件内（参照 nine_grid 的 `COLOR_THRESHOLDS` 模式）。
- 它没有仿真、没有测试、没有调试基础设施——这些是本仓库的标准流程，是我们的优势。

### 4.3 值得保留的优点

- IPPE 双解选最小 pitch 的先验消歧（单贴墙 Tag 场景）。
- 分区分层对齐（大转→小转→平移→微调）。
- 低头视觉验证抓取结果（低成本高收益的自检）。
- 行走全程锁臂（`lock_servos` 机制）。
- 裁判端断线缓存补发协议。

## 5. 开发方案（基于本仓库平台）

### 5.1 打分策略（先行确定）

- **6 分货物分是主目标**：抓取与放置的可靠性优先于速度。
- **4 分时间分要求全程紧凑**（≤120s 才满分）：全程维护比赛计时器，按剩余时间动态收紧各阶段重试预算。
- **显式降级策略**：抓取重试超限后不恋战，直接转出口拿时间分（最多 4 分）——把参考代码"歪打正着"的行为变成写进状态机的策略。
- **保护货物分**：放置完成后先低头验证、倒退远离目标板再出场（货物分按结算瞬间秤上有无增重判定，碰掉即丢 6 分）。

### 5.2 总体设计

复用本仓库已有能力，新建关卡文件（暂定 `levels/cargo_transport.py`，注册进 `main.py` 的 `LEVELS`）：

| 环节 | 方案 | 复用 |
|---|---|---|
| 蓝色海绵检测 | LAB/HSV 色块检测 + **地面单应**把像素观测转为机器人坐标系位置，闭环接近 | `vision/` 检测器模式 + `core/ground_homography.py`（nine_grid 已真机验证） |
| 海绵检测备选 | 现场光照导致色块不稳时，走 YOLO 自训链路 | `tools/train` 全套（football_goal 流程照搬） |
| Tag 38/26 定位 | `RobotState.solve_pnp_pose` + 物理合理性门控；单贴墙 Tag 双解用"最小 pitch"先验做期望选支 + 多帧门控；必要时 `locate_with_scan` 联合求解 | `core/robot_core.py` + `core/multiview_pose.py` |
| 观测滤波 | 每个物理量独立滤波器（修正参考代码共用 bug） | — |
| 状态机 | nine_grid 范式：显式 phase 标签 + 方法交棒 | `levels/nine_grid.py` |

### 5.3 状态机设计

```
SEEK_CARGO → APPROACH_CARGO(单应闭环) → PICK → VERIFY_PICK(低头看蓝色)
    ├─ 失败: 重试(预算内) / 超限 → EXIT(显式降级, 拿时间分)
    └─ 成功 → TRANSIT(优先用 Tag38 观测闭环修正航向; 不可见退化为开环步数)
          → APPROACH_BOARD(PnP 距离分带 + 横移精调, 含板厚补偿)
          → PLACE → VERIFY_PLACE(低头确认海绵在板上, 失败可补放一次)   ← 参考代码没有的环节
          → EXIT(对正 Tag26 yaw → 直行穿过出口红外)
```

- 每个 phase 设重试预算与看门狗；全局比赛计时驱动降级决策。
- VERIFY_PLACE 放置后低头确认，既兜底 PnP 歧义也兜底放置动作失误。

### 5.4 分阶段实施计划

**Phase 0 — 现场勘察与动作标定（最高风险先行，go/no-go 决策点）**
1. 实机验证 `move_up`/`put_down` 抱起、放下 10cm 海绵的可行性与位移；标定夹爪舵机闭合量与锁臂舵机位；实测 `back_fast` 步幅。**若 TonyPi 臂展抱不住 10cm 海绵，整体方案需重议（如改用 `grab_*` 系列动作组），故此步必须最先做。**
2. 场地测量：红线/海绵区/目标板/终点几何关系；Tag 38/26 实际尺寸与粘贴朝向（PnP 物方点参数依赖它）。
3. 裁判联调：实测两路红外极性（§2.4 矛盾定案）、`net host` 配置、HX711 现场标定与阈值。

**Phase 1 — 视觉模块**（阈值与决策常量全部留在关卡内）
按 §5.2 实现蓝色检测+单应定位、Tag 检测+独立滤波；用调试服务器采集现场样本调阈值。

**Phase 2 — 状态机**：按 §5.3 实现，接入比赛计时器与降级策略。

**Phase 3 — 仿真与测试**
`sim/cargo_sim.py` 合成蓝色立方体+Tag 帧（沿用"只桩 I/O 不桩算法"原则），断言状态迁移与降级策略分支；真机前清单照 `数字宫格开发实录.md` 方法论。

**Phase 4 — 真机集成**
`tools/sync_to_robot.py` 同步 → `debug.sh` + 调试服务器（需新增"蓝色色块"分析器）→ TRACE 记录轨迹 → 分级实测：dry-run 视觉观察 → 单段测试（抓取段/放置段/出场段分别验）→ 全流程计时跑，对照 120s 档位优化节奏。

### 5.5 风险表

| 风险 | 等级 | 缓解 |
|---|---|---|
| 抱不起 10cm 海绵 / 动作组不可靠 | 高 | Phase 0 最先验证，备选 `grab_*` 动作组 |
| 场地光照下蓝色阈值漂移 | 中 | 现场标定 + YOLO 备选链路 |
| 单贴墙 Tag 双解歧义致距离误判 | 中 | pitch 先验 + 多帧门控 + VERIFY_PLACE 兜底 |
| 放置/出场碰掉货物丢 6 分 | 中 | 放置后低头验证、倒退出场 |
| 全程超 120s 档丢时间分 | 中 | 计时器驱动预算收紧 + 降级策略 |
| 裁判红外极性与文档不符 | 低（但对分） | Phase 0 实测定案 |
