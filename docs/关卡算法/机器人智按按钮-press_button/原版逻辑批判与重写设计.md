# 原版逻辑批判（`reference code/机器人智按按钮/`）

对象：`robot/press_final.py`（167 行，现场发货版）、说明书、`hardware/esp32_score.ino`。
每条带证据；结论直接决定新流程（见 `新流程设计稿.md`）。

## 一、关卡与硬件事实

- 1m×1m 场地，四角各一块 30×30cm、高约 15cm 的水平按钮面板；面板**后部竖板**贴 tag36h11（黑框 5cm）；
  面板**中央**是微动开关（距边缘约 10cm）。机器人依次按压 102、101。
- ESP32 计分端：GPIO13/14 + `INPUT_PULLUP`，按下 +10 并锁存，HTTP POST 上报。
  ⇒ **Pi 侧读不到"是否真按下"**，唯一真值是场地计分。
- 按压靠身体前倾惯性（说明书 §2.2），不是手。

## 二、原版逻辑（= 移植版保留的部分）

- **纯视觉闭环伺服**，不用里程计、不解释世界坐标、不做 PnP；`tag_poses` 留空是设计选择。
- 观测量：`cx`（`corners[:,0].mean()`）与 `w`（`corners[1][0]−corners[0][0]`，顶边 x 投影长度，非真实边长）。
- 判定顺序即设计：偏左左转 / 偏右右转 / 居中但 `w` 不够则前进 / `w` 够了就 press×2 → back_fast×6。
- 主流程：`stand` →【任务1】`turn_left×2` → 对准按压 102 →【任务2】`turn_right×2` → 101 → 收尾 `turn_right×2`，
  `finally` 回正头 + stand；`__main__` 另有 `go_forward×5` 退场（移植版裁定不保留）。

## 三、必须推翻的设计

**1. 转向步长被当成常数，而收敛精确依赖它。**
原版能对准，唯一依靠 `0 < |turn_right − turn_left| < 2×死区半角`（本仓库：3.7° < 4.77°，移植版文件头已算清）。
副作用：左右**等大** ⇒ 79% 起始方位死循环；差太小 ⇒ 步数暴涨到 150+；差超窗口 ⇒ 跳过对准区。
而 `22.0/25.7` 只是**一次实机标定的抽样值**（`goodluck.py:126-127`），换地面/电量/动作组就变。
⇒ 新流程把步长变成**在线观测量**，并按"大步粗修 + 小步精修"逼近。

**2. 搜索环"发现即丢失"。**
头转 ±27° 看见目标 → 回正头 + 身体固定转一步（`press_final.py:78-91`）。目标绝对方位此时
∈[0°,56°]，身体只转 22° ⇒ 约 **40% 概率"发现"的下一步就丢**，白花 3 张照片 + 1 次转向。
且单轮绝对覆盖 `[−36°,+56°]`，**背后 ~244° 完全没扫**，每轮却固定左转 44°（单侧偏置）。

**3. 死区 ±81px 小于单帧噪声量级。**
±81px = ±2.385°，而 `cx`/`w` 是单帧单次检测、不滤波 ⇒ 抖动 ≥ 死区时输出在左右之间跳，
不需要任何打滑就能自激。

**4. 判距离只看 `w`，斜视时系统性偏乐观。**
`w` 按法线与光轴夹角收缩。实测（真实场地几何）：侧偏 0cm 时 30cm 读 30.2cm；
侧偏 20cm 读 43.4cm；**侧偏 30cm 读 59.9cm（+100%）** ⇒ 判"还远"继续压 ⇒ 撞面板。
⇒ 新流程：距离判据**只在姿态达标后**启用（那时误差 0.2%）。

**5. 横向准了就按 = 盲按。**
只有 `cx` + `w` 两个判据；标签中心对齐只保证"光轴对准标签"，不保证开关可触及。
免费可用的信息（标签的**纵向**位置 = 相机与标签是否等高）原版完全没用。

**6. 俯仰姿态没有强制。**
全文无 `set_pitch`；`RobotState.__init__` 只把 `current_pitch_pulse` 记为 1500 **不发指令**
（`robot_core.py:189`、`:268-269`）⇒ 上一关抬过头之后，本关的几何前提（光轴水平）不成立。

**7. 失败不重试。**
无失败出口（只有 `return True` 与抛异常）；任务1 失败直接跳到任务2。按顺序计分规则，
第一颗没触发则后面全部作废。

**8. 护栏与记账。**
原版是裸 `while True`（无任何上限）；移植版加了 40 步/10 轮/400 张，但 `_turn()` 把**预置转向**
也计进单目标预算（口径被缩小），且没有墙钟出口。

## 四、与说明书不一致处（以代码为准，仅留痕）

- §5.3 写 `for task in TARGET_TASKS: turn_left×2` 循环；代码是硬编码两段（任务1 左转、任务2 右转、收尾右转）。
- §4.1.3 伪码写 `i<3`、`scores[3]`；`.ino` 实际是 2 个按钮。
- 评分表写"每按钮 50 分、满分 100"；ESP32 每次触发只 +10（20/20），100 是赛制换算。
- §5.2.2 说脉宽 1800 是"左转约 30°"；本仓库映射（`SERVO_DEG_PER_US=0.09`）是 27°。
