# L1 感知层

**取角点，不做任何图像预处理。**

```python
results = state.detect_apriltag(path)        # 真机：apriltag 库直接给 corners[4][2]
# PC 兜底（未装 apriltag）：cv2.aruco.detectMarkers(gray) → 角点显式规范成 TL/TR/BR/BL
```

规则：

1. **检测在原始畸变图上做**。不要先 `cv2.undistort` 整图——remap 2592×1944 既慢，又会重采样、
   削弱 apriltag 的亚像素角点精度（约 0.5px）。整图校正的畸变模型是否与设备端一致也未验证。

4. 拍照失败（返回 `None`）与检测链路异常要分开处理：前者重试，后者才降级到 aruco 兜底。

# L2 测量层：四个标量 + 距离

## 2.1 去畸变（只 8 个点）

```python
pn = cv2.undistortPoints(corners.reshape(-1,1,2), K, D).reshape(-1,2)   # 归一化坐标
u  = fx * pn[:,0] + cx0      # ★ 必须乘回焦距
v  = fy * pn[:,1] + cy0
```

**必须做**：宽度与中心偏移受径向偏差影响 4%~11%（见下表）。
**只做这一步**：8 个点的 `undistortPoints` 是微秒级；不做整图 remap（理由见 L1）。

径向偏差实测（k1=−0.384，尺度因子 ≈ `1+k1r²+k2r⁴`，r 为主点归一化半径）：

| 标签位置 | r | 尺度 | `w` 误差 | 折算距离误差 |
|---|---|---|---|---|
| 画面中心 | 0.35 | 0.960 | −4% | +1.2cm |
| 偏 30° | 0.50 | 0.939 | −6% | +1.9cm |
| 偏 40° | 0.65 | 0.923 | −8% | +2.5cm |
| 边角 | 0.80 | 0.891 | −11% | +3.8cm |

## 2.2 四个标量

设去畸变后 `TL, TR, BR, BL`（理想像素）：

| 量 | 定义 | 正对时 | 依赖 |
|---|---|---|---|
| **Ψ** | `‖BL−TL‖ / ‖BR−TR‖`（左竖边 ÷ 右竖边） | **1.000** | **无**：比值把内参、标签边长、畸变残差全部约掉（共模） |
| **β** | `mean(四角 x) − cx₀` | 0 px | 只要主点 |
| **γ** | `mean(四角 y) − cy₀` | 0 px | 只要主点 |
| **w** | **上下两条横边的平均**：`(|TR_x−TL_x| + |BR_x−BL_x|)/2` | — | 无需标定 |

**w 为什么取上下两边的平均**：标签上下俯仰（上远下近）时，两条横边一长一短，
但它们的**平均恰好等于以标签中心深度为基准的宽度**（实测见 2.2b）。取单条边会引入俯仰偏差。

**Ψ 的物理含义**：标签绕自身竖直轴偏航时，近边投影长、远边短。
因为相机与标签等高、标签是竖直平面上的正方形，图像的垂直方向不携带深度信息
⇒ **"对边斜率差"恒为 0，不可用作判据**（合成实测三种姿态斜率差全为 0.0000），
只有"左右竖边长度比"可用。

## 2.2b 标签俯仰（上远下近）的影响——已实测，结论是"不需要特殊处理"

标签绕**水平轴**倾斜（上远下近，即 `n` 有竖直分量）时，宽度方向 `U` 仍是水平的
（竖直平面绕水平轴倾斜不改变水平线方向）⇒ **宽度测量与俯仰无关**。合成实测（z=30cm）：

| 标签俯仰 | 顶边 | 底边 | 上下之比 | 上下均值 | 均值反推 z（真值 30） |
|---|---|---|---|---|---|
| 0° | 322.4 | 322.4 | 1.000 | 322.4 | 30.16（+0.5%） |
| 5° | 320.1 | 324.8 | 0.986 | 322.5 | 30.16 |
| 10° | 317.9 | 327.2 | 0.972 | 322.5 | 30.15 |
| 20° | 313.7 | 331.9 | 0.945 | 322.8 | 30.13（+0.4%） |
| 30° | 309.9 | 336.5 | 0.921 | 323.2 | 30.09（+0.3%） |

**三条结论**：

1. **俯仰不改 `z`**：上下均值反推的纵深在 0°~30° 俯仰内稳定在 30.09~30.16（真值 30）。
   只用顶边则会随俯仰漂移（313.7 → 反推 31.0），所以 2.2 规定取**上下均值**。
2. **俯仰不影响 Ψ**：左右竖边之比在俯仰 20° 前后完全一致（0 → 1.000，20° 偏航 → 1.045）；
   偏航 20° 时俯仰 0°/20° 分别给 1.058 / 1.045，仍单调反映偏航。
3. **俯仰会引入一个轻微"当近"偏置**（均值略偏大 ⇒ 反推 z 略小于真值，本例 −0.3%~−0.5%），
   方向是**提前一点停**，属安全侧；`z*` 现场实测标定会一并吸收。

**顺带得到的诊断量**：`上下之比` 是俯仰的指示器（0°→1.000，30°→0.921）。
它不驱动动作，但每轮打印（见 L4.1），用来判断"标签是否贴歪/面板是否被我撞歪"。

**相机自身俯角 `γ_c`（光轴不水平）的影响**（同一份实测）：

| 相机俯角 | 反推 z（真值 30） | 误差 |
|---|---|---|
| 0° | 30.16 | +0.5% |
| 5° | 30.24 | +0.8% |
| 10° | 30.50 | +1.7% |
| 20° | 31.55 | **+5.2%** |

⇒ 光轴水平（`set_pitch(1500)`，见 L6.5）要保持住：俯角 10° 以内误差 <2%，20° 就 5%。


## 2.3 距离 `z`：定义、计算、以及它不是什么

**`z` 是什么**：标签中心沿**光轴**（相机 z 轴）的纵深，单位 cm。它**不是**：

- 不是斜距 `R = ‖t‖`（两者关系 `R = z/cosβ`，β=40° 时差 30%）；
- 不是"机器人到标签的距离"（相机光心与机体旋转中心有偏置，见 L7.1 标定项）；
- 不是"到微动开关的距离"（开关在面板中央、标签在后竖板，纵深不同）。

**怎么算**（四步，全在 L2 内完成）：

```
① 取角点 → 去畸变（2.1）                        → 理想像素 TL,TR,BR,BL
② 量宽度 → w = (|TR_x−TL_x| + |BR_x−BL_x|)/2    ← 上下均值（抗俯仰，见 2.2b）
③ 量姿态 → Ψ = 左竖边/右竖边；β = mean(四角x) − cx₀
④ 换算   → z = fx · s / w · f
            fx = 1944.90（水平焦距）· s = 5cm（标签黑框边长）· f = 实测标定的修正因子（下表）
```

`f` 的取值（真实场地几何实测，z=30cm；工程上查表插值即可，不需要解析式）：

| 工况（机头对准标签靠近时的侧偏） | 画面宽度 | 朴素读数 `fx·s/w` | 真值 | `f` |
|---|---|---|---|---|
| 正对（Ψ≈1.000） | 322.4px | 30.2cm | 30cm | **1.00** |
| 侧偏 5cm | 313.9px | 31.0cm | 30cm | 0.97 |
| 侧偏 10cm | 290.7px | 33.5cm | 30cm | 0.90 |
| 侧偏 20cm | 224.3px | 43.4cm | 30cm | 0.69 |
| 侧偏 30cm | 162.3px | 59.9cm | 30cm | **0.50** |

⇒ **`f` 在最需要它的工况下能到 0.5**：宽度当距离在斜视时不可用。
所以 `f` 只是"修不到位时的残差补偿"，主力是**先把 Ψ 修到 1.000**（那时 `f=1`，实测误差 0.2%）。

### 推导（公式从哪来，以及它的成立条件）

设标签中心沿光轴纵深 `z`，标签偏航 `ψ_app`（法线与视线方向的水平夹角），宽度基线 `U` 与高度方向 `V` 正交，
两端点 `A = t ± (s/2)U`。居中情形（法线与视线共面）：

```
X_A = (s/2)cosψ_app,  Z_A = z − (s/2)sinψ_app
X_B = −(s/2)cosψ_app, Z_B = z + (s/2)sinψ_app
Δu = f·[X_A/Z_A − X_B/Z_B] ≈ f·s·cosψ_app / z        （(s/2)² ≤ 6.25 ≪ z² ≈ 900）
```

⇒ 两条**精确**关系（实现里就是这么用的）：

```
① w 与 ψ_app ：  r = 近边/远边 = [z + (s/2)sinψ_app] / [z − (s/2)sinψ_app]
                 ⇒ sinψ_app = (r−1)/(r+1) · (2z/s)         ★ 依赖 s/z，不是纯比值
② ψ_app 与 z ：  z = fx·s·cosψ_app / w
```

`(Ψ, w)` 两个观测量正好解 `(z, ψ_app)` 两个未知数 ⇒ **联立迭代**（实现 `depth_and_yaw`，3 次收敛），
`f = cosψ_app` 也随之解析可得，不必查表。逐角点核对（z=30cm）：

| 偏航 ψ_app | 精确宽度 | `f·s·cosψ_app/z` |
|---|---|---|
| 0° | 322.44 | 324.15 |
| 20° | 303.33 | 304.60 |
| 40° | 247.97 | 248.31 |
| 60° | 162.37 | 162.08 |

**两条实现纪律**（都是被单测抓出来的）：

1. **不要用"朴素宽度反推的 z"去反演 ψ_app**：偏航 30° 时朴素 z 高估 9%（31.9 vs 30），
   代进 ① 会把 30° 算成 35°。必须用联立解出的 z。
2. **不要用纯比值近似** `|sinψ| ≈ |r−1|/(r+1)·2`（漏了 `2z/s`）：同样 `r=1.042` 在 z=30cm 是 20°、
   在 z=60cm 是 35°；10° 偏航会被算成 1.7°（早期实现就是这个错，被 `test_psi_dev_to_deg_needs_solved_depth` 拦下）。

### 偏离光轴时的实际行为（关键）

上式**只在标签居中时严格成立**。机器人偏离面板法线时，可见的那条"边"发生变化，
实测宽度会**高于** `f·s·cosψ_app/z` 的预测（合成实测）：

| β（偏离视角） | ψ_app | 精确宽度 | 公式预测 |
|---|---|---|---|
| 0° | 20° | 303.33 | 304.60 |
| 20° | 0° | 300.10 | 324.15 |
| 33.7° | 0° | 304.88 | 324.15 |
| 40° | 0° | **393.83** | 324.15 |

⇒ **不要试图用模型去预测斜视时的宽度**（30cm 正对时宽度 322px，在 β=40° 时反而涨到 394px）。
正确做法是**把姿态修到居中**（此时模型严格成立），或直接用实测标定的 `f_corr`。

**边界（实测，已记录不修）**：`f = cosψ` 这个修正**只在 β 小时完整**。极端姿态
（β≈25° 且偏航 30°、距离 15~100cm）下 `z` 系统高估 **+14%**、`ψ` 高估 **+13°**，
且该误差对距离不敏感（与"居中时 0.0~0.6%"形成对比）。
**为什么可以接受**：① 误差方向是"以为更远" ⇒ 只会**提前停**，不会撞面板；
② 控制律本来就把 β 修到 `τ_β=60px≈1.25cm`（@30cm ≈2.4°）才判距离，不会在极端姿态下按。
若将来要在斜视下也准，需要把"偏轴修正"补全（三个姿态角全建模），当前不做。



## 2.4 噪声与容差下限

以去畸变后角点噪声 σ ≈ 1px 计（30cm 处）：

| 量 | 折算误差 | 结论 |
|---|---|---|
| β | 四角均值噪声 ≈0.5px ⇒ **≈0.07°** | 远小于容差，单帧可用 |
| γ | 同上 | 单帧可用（只诊断） |
| **Ψ** | 边长比噪声 ≈0.3% ⇒ **≈3°** | **与容差同量级** |
| z | **≈0.3cm**（60cm 处 ≈0.9cm，按 1/z² 放大） | 近距可用；**远距不要用它判距离** |

**容差下限（两条，取大者）**：

1. **对抗测量噪声**：`τ ≳ 3×噪声`。Ψ 单帧噪声 3° ⇒ 单帧判据不收敛，
   所以用 **3 帧中值**（噪声降到 ~1.7°）再配 `τ_Ψ = 3°`。
2. **对抗执行过冲**：容差必须大于"单步不确定度"，否则会在 Ψ=1 两侧来回过冲成极限环。
   小步实测：左 8.625°±0.625°、右 5.200°±0.05°（L5.2）⇒ **`τ_Ψ` 取 3° 同时满足两条**。

⇒ 流程天然是"先靠近、再精判"：Ψ 的分辨率随 z 减小而提高（信号 ∝ s/z），这是 1/z² 决定的。

**滤波（保持最简）**：每目标保留最近 **3 帧**取中值（抗野值），
收敛判据用**连续两帧达标**。不做 EMA、不做预测、不做状态估计——每轮都是独立闭环。

## 2.5 健全性

| 检查 | 动作 |
|---|---|
| 任一角点距画面边缘 <20px | 不信任 Ψ（只用 β） |
| Ψ 超出 0.3~3.0（值域） | 丢弃本帧（遮挡/角点误配） |
| 单帧野值 | 由 **3 帧中值**压掉（见下） |
| 拍照返回 None | 重试（与"检测链路异常"分开处理） |

> ❌ **"帧间跳变判据"已实测否决**：机器人转一小步（5~9°）本身就让 Ψ 跳 0.02~0.04、
> 大转（25.7°）跳 0.12——与误检**无法区分**（没有运动模型就分不开），会误杀合法帧。
> 抗误检改为三层：值域检查 + 3 帧中值 + 连续两帧达标。

# L3 判据层

| 判据 | 量 | 达标 | 说明 |
|---|---|---|---|
| ① **朝向（主线）** | Ψ | `|Ψ−1| ≤ τ_Ψ` | 唯一定向自由度 |
| ② 横向 | β | `|β| ≤ τ_β` | 体检量（见下） |
| ③ 高度 | γ | `|γ| ≤ τ_γ` | **只诊断/报警**（相机与标签等高由摆位保证） |
| ④ 距离 | z | `|z−z*| ≤ τ_z` | **只在 ① 达标时启用**（否则 `f` 撑不住） |

**为什么 Ψ 是主线、β 是体检量**：`Ψ→1` 时 β 自动→0（正对面板时标签必然居中）；
反之不成立。且原地转向时 β 与 Ψ 同步变化（标签平贴、朝向固定）⇒ 两者**不可能各自独立收敛**，
只能有一条主线，否则同向时冗余、反向时振荡。

**γ 的性质**：严格关系是 `tan γ_meas = tan γ_true · cosβ`（因相机绕竖直轴转 β 后 x'=0）——
β=40° 时 γ 被压缩 22%。所以 γ 只能当"相机与标签是否等高"的校验，不能当横向误差的度量。

# L4 决策层

```
每个循环 = 一张照片 + 一个动作
    拍照 → 检测 → 目标不在本帧则搜索（L6.3）
    去畸变 → 四个标量 → z
    ┌ |Ψ−1| > τ_Ψ             → 转向（大步粗修 + 小步精修，L5）
    ├ |β| > τ_β               → Ψ 达标 ? 横移 : 转向
    ├ |γ| > τ_γ               → 打印告警，继续（高度由摆位保证，只作异常提示）
    ├ Ψ 达标 且 z > z*+τ_z     → 前进一步（完成后立刻重判 Ψ、β）
    ├ Ψ 达标 且 z < z*−τ_z     → 后退 / 报错
    └ 否则                     → press
```

**前进的步长选择**：步长必须 ≤ `2×τ_z`，否则一步就会跨过整条容差带冲进反向死区
（5cm 大步 vs 3cm 容差：35cm 处一步到 30cm 尚可，33cm 处一步到 28cm 就进了"过冲"区）。
实现取 `allow = min(go_forward, 2×τ_z)`：够远且 `allow` 容得下大步才用 `go_forward`，
否则一律用 `go_forward_one_step`（2cm）。单测 `test_forward_step_never_exceeds_allowed_step` 锁死。

**优先级每轮重新裁决，不设分相闸门**，两条理由：
1. Ψ 与 z 的精度都随"斜看程度"下降（L2.4）。若设成"依次通过"，就会在信噪比最差的工况下
   要求最高精度 ⇒ 卡死。
2. 前进本身会改 Ψ（步态偏航/打滑；仓库在 `levels/goodluck.py:263-267` 为此专加"转向后重新定位自纠"）。

**前进对判据的耦合**（要计入预算）：`Δβ = atan(tanβ·Δ/(z−Δ)) − β`（精确）；
β=20°、Δ=5cm、z=30cm ⇒ β 增大约 3.6°。若 `τ_β=5°`，连走两步就越界 ⇒ **每走一步立刻重判**。

**横向纠偏的两条路径**（都可用，按工况选）：

| 方案 | 做法 | 适用 |
|---|---|---|
| A 横移对中 | 机头保持对准面板法线（Ψ≈1），用 `left_move`/`right_move` 压 β | Ψ 已达标、β 偏大 ⇒ 比"转过去再走"省时 |
| B 转─进─终转 | 行进中机头指向标签（β≈0），到位后转向把 Ψ 清零 | 远距/大偏角；最后一步转角 = 横向偏角（30cm 处偏 2cm ⇒ 3.8°） |

## 4.1 逐目标阈值配置（已填首版默认值，现场跑一遍再调）

现场跑关卡时按 L4.2 的打印随手改，不再单独做一轮标定。

```python
# 模块内默认表（可被机器人上的 JSON 覆盖）
DEFAULT_TARGETS = [
```

## 4.2 每轮决策打印

每个循环**恰好一行**，便于现场滚动观察与事后回放：

```
[按按钮][目标102] Ψ=1.038(-) β=+214px γ=-38px w=298px z=31.7cm tilt=1.021 | 判定:Ψ超差 | 动作:turn_left_small ×2 | 累计 转6拍7
```

字段顺序固定，含义：

| 字段 | 内容 |
|---|---|
| `Ψ=..(-/+)` | 比值 + 符号（相对 1.000 偏大还是偏小） |
| `β/γ` | 像素偏差（带符号） |
| `w / z` | 宽度与其换算的纵深 |
| `tilt=..` | **上下边之比**（俯仰指示器，见 2.2b；1.000=标签竖直） |
| `判定:` | 命中了哪条判据（`Ψ超差` / `β超差` / `γ超差` / `太远` / `过冲` / `可按压`） |

| `累计` | 该目标的转向步数 / 拍照数（护栏进度，现场判断"是真卡住还是只是慢"） |

另外三个一次性打印：目标开始（`=== 目标102 开始 z*=30.0 τ=(0.02,60px,80px) ===`）、
目标结束（`结果/用时/拍照数/动作数/失败原因`）、以及**标定表实际加载来源**（默认表 or JSON 路径）。

# L5 动作层

## 5.1 动作集与实测值

| 用途 | 动作 | 单次实测值 |
|---|---|---|
| 粗修朝向（大步） | `turn_left` / `turn_right` | 22.0° / 25.7° |
| **精修朝向（小步）** | `turn_left_small_step` / `turn_right_small_step` | **8.625° / 5.200°** |
| 粗 / 精前进 | `go_forward` / `go_forward_one_step` | 5.0cm / 2.0cm |
| 横移 | `left_move` / `right_move` | 1.9 / 2.2cm |
| 后退 / 按压 / 姿态 | `back_one_step` / `press` / `stand` | 3.2cm（`back_one_step`） |

小步的重复性（每组 20 次 × 2 组，现场实测）：

| 动作 | 单次角度 | 组内 ±3σ | 组间极差 |
|---|---|---|---|
| `turn_left_small_step` | 8.625° | 1.875°（σ≈0.625°） | 25.0°（单组 160.0 / 185.0） |
| `turn_right_small_step` | 5.200° | 0.150°（σ≈0.05°） | 2.0°（单组 105.0 / 103.0） |

## 5.2 转向 = 大步粗修 + 小步精修

**只用上面这张表，不做在线估计**：每轮都重新测量、重新决定转多少，闭环本身就会纠偏——
上一组多转/少转的误差，下一轮立刻在 Ψ 上看到并补回来，不需要额外的估计器。

```
需要转 Δ 度：
    n_big   = |Δ| // 大步角              # 大步吃主体，余量交给小步
    余量    = |Δ| − n_big × 大步角
    n_small = round(余量 / 小步角)        # 小步角按方向取表里的值（左 8.625 / 右 5.200）
```

三条执行规则：

1. **每个方向用各自的常量**：`8.625/22.0 = 0.392` 而 `5.200/25.7 = 0.202`，
   小步/大步比例左右不同，不能互相换算。
2. **单次下发的总转角 ≤ 约 12°**：水平半视场 33.68°，一个大步 25.7° 已占 3/4。
   限制的是**总转角**，不是步数；小步 5~9°，可连发 1~2 次。
3. **转完必须复查一帧**（确认目标仍在画面内）。丢了按 L6.3 的先验方向回扫，不盲目反向。

**若某方向明显偏差**（例如换了地面后总转不到位）：改表里的那个数即可，
不需要算法——`τ_Ψ = 3°` 本身就能吸收 8.625±0.625 这类量级的漂移。
横移同理（标定值 1.9 / 2.2cm，用 β 闭环）。

## 5.3 符号（写错方向 = 正反馈跑飞）

| 量 | 定义 | 动作 |
|---|---|---|
| β | `mean(四角 x) − cx₀`，标签在画面**右**侧为正 | β>0 ⇒ `turn_right`；β<0 ⇒ `turn_left` |
| Ψ | 左竖边 ÷ 右竖边 | **Ψ>1 ⇒ `turn_right`；Ψ<1 ⇒ `turn_left`**（推导见下） |
| γ | `mean(四角 y) − cy₀`，标签在光轴**下方**为正 | 只校验 |
| z | `fx·s/w·f`，恒正 | 大 ⇒ 前进 |

**为什么 β 符号是确定的**：相机系 x 向右；`X=+10cm, Z=30cm` 的点投影到 `u=1906`（主点 1283，画面右侧）
⇒ β>0 必须右转。

**为什么 Ψ 符号也是确定的（不需要现场标定）**：Ψ = 左竖边/右竖边 > 1 ⟺ 左竖边更近 ⟺
标签法线偏向画面**右侧** ⟺ 要让标签法线对齐镜头，机器人须**右转**。
⇒ `Ψ>1 ⇒ turn_right`，与 β 同向、同一个物理含义（都是"目标在我右侧"）。

两者都由合成角点单测锁死：造一个已知偏航（如 `ψ=+20°`）的四角点，
断言 `Ψ>1` 且 `choose_action()` 给出 `turn_right`。

# L6 流程、状态与护栏

## 6.1 单目标循环

`_track_and_press(task)` —— 每轮一拍一动作，唯一出口是"按压完成"或显式失败。

## 6.2 主流程

```
stand → 预置转向 → [目标1 = 102] → 预置转向 → [目标2 = 101] → 收尾转向
finally: 回正头 + stand（任何退出路径都不留歪头/倒姿）
```

## 6.3 搜索（目标不在视野）

```
记忆优先：记住最后在哪一侧、以什么方位看到过该 id，先朝那边转
档位扫描：HEAD_LEFT/RIGHT（±40.5°），必要时 HEAD_WIDE_*（±63°），每档一张
兜底：交替左右各转一步（消除单侧偏置）
复查：每次转完必须再拍一张确认
跨目标：第二个目标搜索时，排除第一个目标期间 seen 里出现过的 id
```

## 6.4 护栏与失败

| 护栏 | 值 | 依据 |
|---|---|---|
| 单目标转向 | ≤40 步 | 实测打滑 p99=36 步、最多 94 步；360°（≈14~16 步）会误杀"只是慢"的样本 |
| 单目标搜索 | ≤10 轮 | 每轮 ≤3 张 |
| 全局拍照 | ≤400 张（≈6~9 分钟） | fswebcam 0.62~0.70s/张 + 检测 0.15~0.6s |
| **墙钟** | 新增 | `AGC.runActionGroup` 卡死时唯一出口 |
| 无进展心跳 | 连续 N=6 轮 `(Ψ,β,z)` 变化 < 阈值 | 打印卡点并转向搜索 |

**失败语义**：超限 → 打印卡在哪一步 → **允许一次重试**（放在 `_task_flow` 的 `try` 内，
不破坏 `finally` 的回正头+站立）→ 仍失败则记录并继续下一个目标。
记录 `(id, ok, 原因, 用时 monotonic, 拍照数, 动作数)`，per-target 计数取全局差分。

## 6.5 开局姿态（否则整层几何不成立）

`RobotState.__init__` 把 `current_pitch_pulse` 记为 1500 **但不发指令**（`robot_core.py:189`），

# 附：已否决的路线（不再讨论）

| 路线 | 原因 |
|---|---|
| 单目位姿 / `solvePnP(IPPE_SQUARE)` | 口径（objp 手性、角点卷绕、镜像分支）写错即静默错 cm~m 级 |
| 闭式解 `u×v` 求法线 + λ 定尺度 | 尺度在斜视下偏 +4%~44%，且仍需手性自检 |
| "标签法线 vs 视线"当朝向判据 | 伪判据：机器人为看到标签必然转向它 ⇒ 该角恒≈0 |
| "对边斜率差"当平行判据 | 等高 + 竖直平面正方形 ⇒ 图像垂直方向不带深度信息，实测恒为 0 |
| 禁用横移/后退 | 依据非实测，且与仓库记录冲突（`goodluck.py:124-125` 有实测值并列为可靠动作） |
| 在线估计单步转角（EMA 等） | 每轮闭环本身就是纠偏器，实测常量 + `τ_Ψ=3°` 足以吸收漂移，不需要估计器 |
| "Ψ→角度"用纯比值近似（漏 `2z/s`） | 10° 偏航会算成 1.7°；必须用 (Ψ,w) 联立解出的 z（见 L2.3 推导） |
| `γ` 超差时"停下不按" | 会造出"无动作"空转路径（撞拍照/墙钟护栏才停）；改为只告警、不阻塞动作 |
| "帧间跳变"当误检判据 | 转向本身就让 Ψ 跳 0.02~0.12，与误检无法区分 ⇒ 会误杀合法帧（见 L2.5） |
