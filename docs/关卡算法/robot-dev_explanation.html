1. 项目概览

robot-dev 是一套部署在 Hiwonder TonyPi（树莓派 + 舵机驱动板 + 高清摄像头）上的 具身智能闯关机器人代码。它的任务是：机器人从赛道入口出发，在 100cm × 100cm 的封闭场地内， 依据墙上粘贴的 AprilTag 标签进行视觉定位，沿规定线路依次停靠若干评分点、完成四次直角转弯， 最终走出出口。

项目的核心是「定位 → 决策 → 行动 → 再定位」的闭环导航框架： 每一步先拍照 + AprilTag 检测 + PnP 求解算出自己在哪儿、朝哪儿，再用贪心算法决定走哪一步， 并在决策中内置避障与防震荡机制。与之配套的还有一个纯软件模拟器 （goodluck_sim.py），可以在 PC 上不接触真机就验证算法、注入噪声做鲁棒性测试。

一句话总结：以 AprilTag 视觉定位为感知、以导航点(路点)为顶层规划、以贪心平移 + 朝向优先 + 避障过滤为底层执行的闭环寻路机器人程序。

5. 核心代码模块

5.1 main.py —— 关卡入口与注册表

main.py 维护一个 LEVELS 字典，把每个关卡的名字映射到它的 tag_poses 与 run_level。新增关卡只需：新建关卡文件 → 实现 run_level(state) → 在字典中注册。

LEVELS = {
    "goodluck": {
        "tag_poses": level_goodluck.tag_poses,
        "run_level": level_goodluck.run_level,
    },
}
state = RobotState(tag_poses=level["tag_poses"])
success = level["run_level"](state)

5.2 robot_core.py —— RobotState 通用核心

RobotState 封装了所有关卡共享的基础能力，是整个系统的「身体接口」。它只负责「感知」和「执行」，不含任何关卡决策逻辑。

类别方法作用
动作执行run_action(name, times)调用动作组（真机走 AGC，模拟器被重写）
set_head(pulse, move_time)转头部舵机，按角度差动态缩放等待时间
视觉定位capture_image()fswebcam 拍照，返回文件路径
detect_apriltag(filename)OpenCV 读图 + apriltag 库检测 tag36h11
PnP 求解solve_pnp()世界坐标 + 图像角点 → cv2.solvePnP → 位置/朝向
compensate_head_offset()头部偏转时，把相机朝向换算回机体朝向
定位策略locate_with_scan()三级头部扫描（回正→右转→左转）
locate_with_retry()扫描失败后身体小步转动重试（最多 5 次）
几何工具distance_point_to_rect()点到矩形的最短距离（纯函数，模块级）

硬件库（hiwonder、apriltag、cv2）全部用 try/except 包裹，PC 上无这些库也能正常 import，模拟器通过继承重写 I/O，不触真机。

5.3 levels/goodluck.py —— 关卡数据 + 导航算法

这是整个项目最核心的文件，包含三部分：

数据 tag_poses（4 张 AprilTag 世界坐标）、WALLS（3 堵墙）、ROUTE（路点表）。

决策 decide_panning_action()（贪心平移）、decide_rotation_action()（转向选择）、navigate_to_target()（导航主循环）、check_segment_clear()（批量直行预检）。

避障 distance_to_walls()（墙距计算）、nearest_safe_point()（安全点螺旋搜索）、assert_corridor_clear()（路点走廊校验）。

入口 run_level(state)（站立 → 头部回正 → 逐路点导航 → 完成）。

5.4 goodluck_sim.py —— 模拟器

模拟器定义 SimState（维护机器人真实位置/朝向/轨迹）、Visualizer（matplotlib 实时绘制赛道与轨迹）、 SimRobotState(RobotState)（重写 I/O 为桩函数）。核心机制是： 

class SimRobotState(RobotState):
    def run_action(self, name, times=1):
        if name == "go_forward_one_step":
            self._sim.apply_forward(gl.FORWARD_ONE_STEP_CM)
        elif name == "turn_left":
            self._sim.apply_turn(gl.TURN_LEFT_DEG)
    def solve_pnp(self):
        pos = self._sim.pos + np.random.normal(0, LOCATE_NOISE_STD, 2)
        self.current_position = pos
        return True

由于算法通过 state.xxx() 调用，桩函数会命中重写方法，无需 monkey-patch，比旧版架构更干净。

6. 视觉定位

6.1 AprilTag 检测 + PnP 求解

① capture_image()：fswebcam -r 2592x1944 --no-banner -S 3 拍高清照片
▼
② detect_apriltag()：灰度化 + apriltag.Detector(tag36h11) 检测标签
▼
③ 收集所有标签的 3D 世界坐标（tag_poses）与 2D 图像角点
▼
④ cv2.solvePnP() 解出相机外参 rvec, tvec
▼
⑤ P_cam = -R⁻¹·t，O_cam = R⁻¹·(ẑ - t) - P_cam，取 x,y 分量归一化

相机内参（已标定）：

K = [[1944.9,    0, 1283.1],
     [   0, 1950.1,  983.2],
     [   0,    0,      1  ]]
畸变系数: [-0.384, 0.285, 0, 0]

6.2 头部偏转补偿

头部舵机转动拍照时，相机随头部转、机体不动，PnP 解出的是相机朝向，需换算回机体朝向。脉宽→角度：θ = (pulse − 1500) × 0.09°（右负左正），再用反向旋转矩阵转回：O_body = R(−θ) · O_cam。

6.3 三级头部扫描定位

回正(1500) → 拍照+PnP → 成功返回
▼失败
右转(600) → 拍照+PnP → 成功则补偿头部偏转 + 回正
▼失败
左转(2400) → 拍照+PnP → 成功则补偿头部偏转 + 回正
▼失败
回正 → 返回 False

6.4 定位重试机制

locate_with_retry() 在头部扫描全失败时，交替执行 turn_left_small_step / turn_right_small_step 让身体小步转动改变视角，最多 MAX_LOCATE_RETRIES = 5 次；全失败则程序终止。

7. 避障系统

7.1 墙距计算

distance_to_walls(pos) 计算位置到最近障碍物的距离：对 3 堵矩形墙用 distance_point_to_rect()，再额外检查外框底边（y=0）与顶边（y=100），取最小值。

def distance_point_to_rect(pos, rect):
    dx = max(x_min - x, 0, x - x_max)
    dy = max(y_min - y, 0, y - y_max)
    return sqrt(dx*dx + dy*dy)   # 点在矩形内返回 0

7.2 安全点搜索

当离墙 < OBSTACLE_THRESHOLD(15cm) 时进入危险区，nearest_safe_point() 以 16 方向、1cm 步长、螺旋式搜索最近的安全点（离墙 ≥ 21cm）。

为什么安全点要 ≥ 21cm？ 安全阈值 = OBSTACLE_THRESHOLD(15) + POSITION_THRESHOLD(3) + SAFE_MARGIN(3) = 21cm。 若安全点离机器人太近（< 3cm），到达后位置差不超过阈值会被误判「已到达」，形成「需逃离但无需导航」的死循环。把阈值抬高，保证安全点足够远、必触发平移。

8. 导航决策算法

8.1 导航主循环 navigate_to_target()

这是核心导航原语，对所有路点（停靠点 / 中间路点）统一使用。每轮循环：

1. 定位：locate_with_retry() 获取机体位置/朝向
▼
2. 危险检测：离墙 < 15cm → 临时目标改为最近安全点（escaping=True）
▼
3. 计算位置差：pd = target − current，dist = |pd|
▼
4. 动态目标朝向：远距用连线方向 / 近距切指定朝向或冻结连线方向
▼
5. 朝向优先：朝向差超阈值 → 转向，回到 1
▼
6. 平移接近：位置差超阈值 → 贪心选最优动作（含批量直行优化）
▼
7. 到达检查：逃离则恢复原目标；否则按需停留 → 返回 True

8.2 贪心平移决策

模拟 5 个候选动作执行后的位置，逐个做避障过滤（执行后离墙 < 15cm 就排除），选「到目标距离」最小的动作。前进类动作额外减一个偏好权重 FORWARD_BIAS，避免原地左右横移震荡。

候选动作位移向量
go_forward_one_step+4.0cm × 朝向
go_forward_one_small_step+2.0cm × 朝向
back_one_step−4.0cm × 朝向
left_move+2.9cm × 左向
right_move+2.1cm × 右向
全部被排除的兜底：若所有候选动作都被避障过滤，说明机器人可能已在危险区——此时不执行动作（按兵不动），交由主循环的危险检测逻辑导航到安全点。

8.3 转向决策

用叉积判方向、点积算角度，选择左/右转及步长：角度差大用大步（turn_left/right），角度差小用小步（turn_left/right_small_step）。

8.4 动态朝向策略（防震荡核心）

距离有效目标朝向说明
dist > ORIENT_FREEZE_DIST_CM(10)连线方向动态更新，转弯段斜切接近更平滑
dist ≤ 10 且有指定朝向指定朝向保证停靠点评分朝向精确
dist ≤ 10 且无指定朝向冻结连线方向首次进入近距离时记录，之后固定，防震荡
逃离危险区None跳过朝向修正，优先平移离开
防震荡原理：接近目标时定位噪声会让连线方向抖动（1cm 噪声在 3cm 处约 18°）。把近距离的朝向「冻结」后， 方向不再随位置噪声变化，消除了「定位 → 转向 → 位置不变 → 再定位」的原地打转循环。

8.5 批量直行优化（省时间）

长直走廊段每走一步就定位一次很浪费。当前代码在满足「朝向已对准 + 离墙够远(≥18cm) + 纯前进 + 距目标够远(>12cm)」时，一次连续走多步再定位：

BATCH_FORWARD_STEPS_BY_ANGLE = {
    3.0: 4,   # 朝向偏差 ≤ 3° → 允许 4 步（横向偏移 ≤ 0.8cm）
    7.0: 3,   # ≤ 7° → 3 步
    11.0: 2,  # ≤ 11° → 2 步；超过则回退单步
}

批量前还会用 check_segment_clear() 沿整段路径每步采样离墙距离预检，任一点贴墙就放弃批量。

9. 运动模型

9.1 平移

前进/后退/横移按机体坐标系直线运动：P' = P + d · O（d 带符号，O 为朝向单位向量）。

9.2 圆周转向模型

转向不是原地旋转，而是绕后方偏侧的圆心做圆弧运动：

旋转中心 K = P − d_cam·O + R·O⊥
  其中 d_cam = 2.0cm（圆心在机体后方），R = 5.0cm（转弯半径）
  左转：O⊥ = [-Oy, Ox]（圆心在左后方）；右转：O⊥ = [Oy, -Ox]（右后方）
位置更新 P' = K + R(α)·(P − K)
朝向更新 O' = R(α)·O

这个模型把「旋转中心偏移」和「转弯半径」做成常量（CAMERA_FORWARD_OFFSET_CM、TURN_LEFT/RIGHT_RADIUS_CM），需实机标定。

10. 主流程与路点表

10.1 统一路点模型

当前实现把「停靠点 / 转向点 / 中间走廊点」统一为 Waypoint：

Waypoint(pos, stop, orientation, bypass_position, bypass_condition)
# pos         目标位置 [x,y]
# stop        >0 = 停靠评分点（停留），0 = 经过
# orientation 目标朝向；None = 走廊内不强制朝向
# bypass_*    满足条件时跳过该点（用于「提前进入开阔走廊后无需回头」）

10.3 run_level 主流程

def run_level(state):
    assert_corridor_clear([wp.pos for wp in ROUTE])  # 上线前校验走廊净空
    state.run_action("stand")                        # 站立初始化
    state.set_head(HEAD_CENTER)                       # 头部回正
    for i, wp in enumerate(ROUTE, 1):
        navigate_to_target(state, wp.pos, wp.orientation, wp.stop, ...)
    return True   # 全程完成
路点设计思想：赛道存在「贴墙角的危险走廊」（如左墙底角、中墙上方、右墙左侧）。 中间路点的作用是提前把机器人引入开阔走廊，避开这些贴墙段，而不是等撞墙了再靠避障硬绕。 assert_corridor_clear() 会在启动时沿线每 1cm 采样校验，发现贴墙段就打印警告。

13. 优化方向与注意点

13.1 时间优化方向（按预期收益排序）

优化项思路预期收益
① 批量直行安全长直道一次走多步再定位（已实现）⭐ 最大
② 增大前进步长标定后从 4cm 提到 6~8cm步数减半
③ 降低避障阈值15cm → 12cm，减少不必要的逃离减少绕行
④ 增大转向角度30° → 45°，90° 转弯 3 次变 2 次减少转向次数
⑤ 压缩拍照质量降低分辨率/跳帧，减少定位等待降低定位耗时

13.2 需要注意的点（文档与代码差异）

  • 停留时间：赛道规则要求停靠点停留 3 秒（robot_core.py 中 STOP_TIME=3），但 levels/goodluck.py 目前 STOP_TIME=0.1，疑似用于快速测试，上线前需改回 3 秒。
  • 头部左转脉宽：代码用 HEAD_LEFT=2400，而《机器人调用说明.md》建议 1700（更保守），需按实机确认。
  • 动作参数未标定：所有步长/转角/横移量都是估算值，换地面、电量、机器人都会漂，必须实机标定。
  • 文档滞后：introduction.md 描述的是旧版单文件架构（PART A/B、monkey-patch、停靠/转向两阶段），与当前重构后的路点模型不一致，以代码为准。

13.3 工程 tradeoff（来自机器人调用说明）

新机器人转向慢、非正向步态（侧移/后退）易打滑、动作名与真实位移对应不稳定。因此工程上 主动放弃依赖侧移微调，改用「停止 → 视觉重定位 → 纯前进 / 大步距微调」的控制逻辑， 用软件流程包容硬件缺陷——稳定可重复的动作比理论上灵活但不可控的动作更有价值。
