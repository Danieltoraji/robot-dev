## 1. 背景与问题

当前稳定版通过固定手工路点 + `navigate_to_target` 逐点导航，存在以下问题：

- 路点约束过强，机器人会被拉回已经越过的点；
- 末端小步精调浪费时间；
- A* 软圈居中导致路线死板；
- 难以适应不同起点/终点，缺少通用自主规划能力。

新方案目标是：**让 A* 只负责连通性，路径由机器人真实离散动作可生成的“直线段 + 纯转向圆弧段”构成，并通过段末定位与重规划闭环运行。**

---

## 2. 核心架构

```
A*(x,y) 拓扑
  → 直线/纯转向圆弧段参数化
  → 离散动作映射（直线长度整数化、转向次数量化）
  → 碰撞校验（15cm×10cm 扫掠体）
  → 分段执行（直线段批量直行 / 圆弧段批量转向）
  → 段末定位 → 偏差分级 → 局部修正或重新规划
```

---

## 3. 路径结构

路径表示为直线段与纯转向圆弧段交替拼接：

```
LINE → ARC → LINE → ARC → ... → LINE
```

- 直线段：由 `go_forward(5cm)` 与 `go_forward_one_step(2cm)` 组合；
- 圆弧段：`turn_left × n` 或 `turn_right × n`，总转角 = `22°×n` 或 `25.7°×n`；
- **不允许左右转组合合成中间角度**，避免 LRL 振荡。

A* 仅使用 `(x, y)` 状态，负责走廊拓扑/连通性；不使用居中软罚分。

---

## 4. 直线长度整数化

机器人只有 5cm 与 2cm 直行动作，允许约 ±1cm 误差。

对目标长度 `L`：

1. `n5 = floor(L / 5)`
2. 余数 `r = L - n5×5`：
   - `r=0`：`n5` 个 5cm，误差 0；
   - `r=1`：`n5` 个 5cm，误差 +1；
   - `r=2`：`n5` 个 5cm + 1 个 2cm，误差 0；
   - `r=3`：`n5` 个 5cm + 1 个 2cm，误差 +1；
   - `r=4`：`(n5+1)` 个 5cm，误差 -1（如 19=20-1）。

最多只允许 1 个 2cm 小步，误差控制在 ±1cm。

> 注意：不能逐段独立取整；应连续解出各段长度后统一投影，并对末端残差做局部修正。

## 5. 自标定

### 5.1 标定对象

- `go_forward`（5cm）
- `go_forward_one_step`（2cm）
- `turn_left` / `turn_right` 的 `count=1,2,3`
- `left_move` / `right_move` / `back_one_step`

### 5.2 真机标定要求

当前机器人只有一个摄像头，使用 AprilTag 定位作为测量源。由于定位存在离群点、空间相关偏差和可能的航向系统偏差，标定必须：

1. 重复采样（建议 ≥20 次）；
2. 使用鲁棒统计（中位数/剔除离群点），不使用普通均值；
3. 在多个区域分别标定；
4. 保留协方差；
5. 用独立真值或交叉验证（模型预测下一次定位）验证；
6. 标定结果仅作为前馈模型，在线仍需定位闭环。

### 5.3 前向模型

每个动作保存局部系下的 `(dx, dy, dtheta)` 及协方差；执行时按当前位姿逐次叠加。

`motion_model.py` 已实现：

- `load_motion_model()`
- `apply_action(state, model, action, count)`
- `forward_model(state, sequence)`
- `quantize_straight(L)`

## 6. 碰撞扫掠

- 机器人扫掠体采用 **15cm × 10cm 矩形**；
- 直线段：矩形沿直线扫掠；
- 圆弧段：按小角度采样矩形位姿并做保守扫掠；
- MVP 阶段可先用保守 occupancy/外接矩形，再对候选做采样精确检测；
- 安全余量必须包含定位误差、动作误差与模型残差。

---

## 7. 优化求解

在“可执行直线-圆弧序列”空间中搜索：

- 枚举每个拓扑转折的 `direction` 与 `count`（在 `round(转角/22 或 25.7)` 附近 ±1~±2）；
- 固定圆弧序列后，直线方向由离散航向确定；
- 直线长度按整数化规则在可行集合中选取；
- 使用 beam search 控制组合规模；
- 目标函数：
  ```
  J = 总执行时间/动作数 + λ1×转弯簇数 + λ2×短直线反向转弯惩罚
  ```
- 不做居中软罚分。

---

## 8. LRL 与航向

- **完全禁止 LRL**：不允许通过左右交替小转角做航向微调；
- 相邻反向圆弧簇之间必须有足够长直线段（如 ≥10cm），否则候选非法；
- 本项目无 S 形绕障，该约束不损害正常路径；
- 终点航向无严格需求，容差放宽（如 ±20°~30°）；
- 末端位置修正使用 `left_move/right_move/back_one_step/go_forward_one_step`，不用于修正航向。

---

## 9. 常态化重规划

- 每执行完一个直线段或圆弧段后定位；
- 偏差在阈值内 → 继续当前计划；
- 偏差超阈值但可局部修正 → 局部修正；
- 偏差过大/被堵 → 从当前实际位姿重新 A* + 枚举；
- 危险逃离最高优先级，可中断当前段；
- 正常重规划下已提交段先执行完。

建议重规划触发基于**滤波后位姿**，不能直接用单次离群定位。

---

## 10. 定位误差评估结论

基于两份真机 trace：

- 定位调用成功率 100%，但单帧 PnP 失败 11~14 次；
- 单动作位置残差中位约 2.6~2.9cm，p95 约 6.7~9.1cm；
- 航向残差中位约 3~4°，p95 约 14~15°；
- 存在明显离群点（5cm 动作被定位成 0.7~13.5cm）；
- 存在空间相关误差（x<30、x>70 区域误差更大）；
- 存在航向系统偏差（整体 dθ 约 -1.6°~-2.0°，左右不对称）。

因此新算法运行阶段必须增加：

- 定位离群点门控；
- 运动模型预测 vs 定位的偏差校验；
- 鲁棒状态估计/滤波；
- 安全余量。

---

## 11. 可行性结论

| 维度 | 结论 |
|---|---|
| 必要性 | 固定路线非必须；通用 A* 自主导航需要 |
| 标定可行性 | 可行，但必须鲁棒统计 + 多区域 + 剔除离群点 + 独立验证 |
| 运行时可行性 | 可行，但必须增加“模型预测 vs 定位”的门控/滤波 |
| 主要风险 | 定位离群点、空间 bias、航向系统偏差 |
