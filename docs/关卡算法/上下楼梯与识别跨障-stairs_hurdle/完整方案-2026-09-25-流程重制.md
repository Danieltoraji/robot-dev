## 1. 关卡事实

### 1.1 场地（场景系：原点 = 第一级台阶基线中点，y 向前、x 向右、z 向上，单位 cm）

```
y < 0        平地（入口侧）
y = 0        第一级台阶立面；场地自带的红色标记（下称"红胶条"）下半段贴在立面上（z 0~1.5）
y ∈ [0,15]   第一级踏面 z=2.5；红胶条上半段贴在踏面前 4cm
y = 15       第二级立面
y ∈ [15,30]  顶部平台 z=5
y = 30 / 45  下行两级立面
y ∈ [30,45]  下行踏面 z=2.5 → 0
y > 45       平地；红色横杆（下称"木条"）在 y = 45 + 25~40
```

- 红胶条：**场地自带，位置不可控**，就在楼梯根部。
- 木条：截面 2×2 cm，长 80 cm（等于赛道全宽，无法绕行），**与楼梯平行**，沿运动轴的位置赛前随机（25~40 cm），提交代码后固定。
- 起点：机器人摆在入口黑胶带线以外，**位置与朝向完全自选**；挡住入口红外光束开始计时。
  代码里按"机体中心离胶条 60 cm"当摆位先验（`PLACEMENT_DIST_CM`），**只用于降级路径**：
  胶条完全看不见时按它往前走。正常流程不依赖这个数。
- 场地是固定的，不需要考虑"目标不存在"。

### 1.2 计分

| 项 | 判定 |
|---|---|
| 碰撞 | 木条上的振动传感器；每次 −2 分，2 秒冷却，单局最多记 3 次（**封顶 −6**） |
| 超时 | 分档扣分，**封顶 −3** |

**这组权重决定整套设计的优先级：撞两次木条的代价就超过全程超时。宁可慢，不能撞。**

### 1.3 机器人能力

- 只有头部一个摄像头，只能拍静态照片（`fswebcam`，单张约 0.9 秒）。
- 没有任何其他外感受器：不知道自己在哪、转了多少度、有没有摔倒、有没有碰到木条。
- 动作组（爬楼、下楼、跨栏）是黑箱，执行期间无法干预，内部步态不做任何改动。

**由此得出最硬的一条约束：爬楼、下楼、跨栏一旦开始就停不下来，而且做完之后机器人不知道自己成没成。所以每个这类动作开始之前，必须先把能确认的事情确认完。**

## 2. 相机模型（先定这一节，后面全部依赖它）

### 2.1 取值

| 量 | 取值 | 依据 |
|---|---|---|
| 观测俯仰档 | **1100** | 换舵机后重新确认 |
| 站立时相机光心离地高度 | **33.9 cm** | 卷尺标定：h_eff 32.73 + 卷尺厚 1.20 |
| 相机安装俯仰偏移 | **19.1°** | 卷尺标定：拟合俯角 55.11° − 名义 (1500−1100)×0.09=36.0° |
| 该档地面可见范围 | **3.5 ～ 71 cm** | 由上面三个量算出，与现场实测 2～70cm 一致 |

**标定来源**（`tools/calib_ruler_profile.py`，2026-09-25）：14 个卷尺刻度
（读数 3～60 cm），含畸变物理模型 **RMS = 2.72 px**、距离误差 worst 0.42 cm、
零坏点；同一组数据去掉畸变后 RMS = 12.60 px（**畸变把残差砍到 1/4.6**，
且无畸变时正好等于自由射影针孔族的上限——自洽性交叉验证）。

这个 19.1° 与 `core/camera_config.py` 的 18.5°、九宫格自标定的 19.0°
**三者吻合**。

内参（`core/camera_config.py`，对应 2592×1944）：

```
fx = 1944.90   fy = 1950.10   cx = 1283.07   cy = 983.20
畸变 k1 = −0.384402   k2 = 0.284682
```

### 2.2 半视场必须含畸变（重要纠正）

旧实现用针孔公式 `atan((H/2)/fy)` 算半视场，得 **26.49°**。这是错的。

本镜头桶形畸变很强（k1 = −0.384），用 `cv2.undistortPoints` 对画幅边缘实算，真实半视场是：

```
半视场（垂直）  针孔公式 26.49°   ← 错，低估 2.5°
                含畸变   29.02°   ← 正确
半视场（水平）  含畸变   37.07°
```

**凡是"用针孔公式推能看见多远/多近"的地方，结论都不可信。可见范围一律以实算或实测为准。**

### 2.3 可见地面带

```
可见带 = [ h / tan(θ + 29.02°) ,  h / tan(θ − 29.02°) ]
α(档位) = (1500 − pitch) × 0.09 + 安装偏移
地面俯角 θ = α(档位)
```

1100 档：θ = (1500−1100)×0.09 + 19.1 = 36.0 + 19.1 = **55.1°**，代入 h = 33.9cm：

| 量 | 值 |
|---|---|
| 近界 | **3.5 cm** |
| 远界 | **71.0 cm** |
| 现场实测 | 2 ～ 70 cm ✅ |

**仿真验证**：重制后的仿真器（`sim/stairs_hurdle_sim.py`，`CAM_HEIGHT=33.9`、
`CAM_PITCH_OFFSET_DEG=19.1`，含真实畸变）渲染出的可见带是 **[3.5, 71.0] cm**，
与解析值和现场实测三者一致。回归门：`tests/test_visible_band.py`。
（重制前仿真用 h=39cm、无安装偏移，渲染出的是 [13.9, 177.7] cm，远近两头都反着。）

### 2.4 纠正记录：九宫格自标定的 57.4 cm 不成立

九宫格 `layout_scan` 曾自标定出「安装偏移 +19.0°、离地 57.4 cm，重投影残差中位 1.4 px」，该结果**不可作为物理真值**：

1. **低残差不证明参数正确。** 九宫格自己的文档已记录：`(偏移, 高度)` 是退化方向——"参数网格退化谷较平，(偏移,高度) 在谷内可移动"。1.4 px 残差只证明"这组参数能解释格阵"。
2. **可见带反证。** 57.4 cm 会给出 96 cm 的远界（表 2.3），与实测 2～70 cm 明显不符。

**影响**：九宫格分支中凡依赖相机高度的几何（`layout_scan` 自标定、GN 定位、像素域五参数精修）都可能整体偏差约 65%，需要在该分支独立复核。**本次重制不修改任何 nine_grid 文件。**

## 3. 三条设计原则

### 原则一：摆位为主，视觉为辅

位置和朝向由人摆定。机器人要修正的只是"人摆不准"的那部分，主要是航向相对于赛道的偏差。因此不需要多轮搜索式的对正，一帧确认加边走边修即可。

### 原则二：动作组执行期间只能开环，其余尽量闭环

爬楼、下楼、跨栏是黑箱动作组，执行期间插不进任何判断，只能开环。除此之外
**能闭环的都闭环**。

⚠️ 但"能不闭环"和"该不该闭环"是两件事。第 2 步（上下台阶）**有意识地放弃了
闭环**：四个动作组之间不插任何测量，只按现场标定的固定量做右小转（理由见 §4.1）。
这是全流程唯一一处"本来可以测、但决定不测"的地方，代价写在 §9 第 2 项。

### 原则三：按步骤指定目标，不用"最近的红东西"

红胶条和木条同色、同检测方法、都横跨赛道，唯一区别是在运动轴上的位置。旧实现用"取最近的红色簇"，会在最要命的时刻出错（详见 §6）。正确做法是每一步显式指定目标及其距离窗口。

## 4. 流程：4 步

| 步 | 做什么 | 看什么 | 距离窗口 | 命令 |
|---|---|---|---|---|
| 1 | 对准并走到起爬点（离胶条 7 cm） | 红胶条 | 0～55 cm | 闭环 + 末段推算 |
| 2 | 上下台阶（上楼 2 级 + 下楼 2 级） | — | — | **整段写死**：`climb`-右小转-`climb`-右小转-`down`-右小转-`down`-右小转 |
| 3 | 对准并走到起跨点（**脚尖**离木条 0.2~1.2 cm） | 木条的**方向 + 距离** | 0～50 cm | 闭环（末段步子阶梯 + 后退调节） |
| 4 | 跨栏 | — | — | `hurdles`（开环）→ 直接交棒 |

窗口的作用要说清楚：**真正的判别手段是步骤顺序**（第 1 步时木条还远在可见带
之外；下完台阶后胶条已在身后），窗口只是第二道保险——挡住明显不属于本步的读数，
避免机器人一旦冲过头、木条进入视野时被当成胶条继续往里走。

动作组之外只有两处"没有目标可看"的开环，都是有意的：

- 第 2 步整段（楼梯段的航向补偿现场证明固定"右小转"比顶上测一次更稳，见 §5.4）
- 第 3 步末尾的推算段（详见 §5.3）

### 4.1 为什么从 6 步并成 4 步

原来的第 3 步"顶上对正"是**独立一步、只测木条方向，为的是防止上楼把机器人
带歪、下楼时摔倒**。现场结论是：这件事用固定补偿做得更好——

- 上楼/下楼动作本身会把机体转歪，方向基本一致（连续左偏），所以**每做完一个
  动作就右小转一次**，一路把它压住，比攒到平台顶上再测一次方位更省事；
- 顶上测方位要额外一帧 + 判据，收益不明显，还多一个失败点；
- 楼梯段总共只有四个动作，写死之后整段没有分支，也没有"看不见木条怎么办"
  的降级问题。

代价是这一段完全靠"现场标定的固定补偿"吃饭：补多了会右偏、补少了会左偏。
所以 §9 把"上下楼各自的航向偏置"列为必须复量的项。

## 5. 每一步的做法与判据

### 5.1 通用的测量与修正

一次拍照同时给出三个数：**前向距离、横向偏移、方向偏角**。所以"对准"和"走近"不必分成两件事，边走边修即可。

- 前向距离的定义不是"目标中点离多远"，而是"继续直行会穿过目标的那一点离多远"。斜着看时这两个数差很多，必须用后者。
- 实测时按当前步骤的目标窗口筛选红色连通域：窗口内的保留，窗口外的丢弃并记日志。

### 5.2 通用参数

| 参数 | 值 | 说明 |
|---|---|---|
| 前进步长 | **1.8 cm** | 现场口径（重装后）。同日早些时候量到 2.652 cm，差 1.47 倍，必须复量 |
| 横移步长 | 2.497 cm | 实测 |
| 左转步长 | 8.625 °/步 | 实测（组间极差 25°/20步，较散） |
| 右转步长 | 5.200 °/步 | 实测（组间极差 2°/20步，很稳） |
| 起爬点 | 离胶条 **7 cm** | 照参考实现；动作组当黑箱 |
| 起跨点 | **脚尖**离木条 **0.2 ~ 1.2 cm**（折成工具读数 **4.44 ~ 5.44 cm**，见 §5.2.1） | 现场给的验收线 |
| 摆位先验 | 开机时离胶条 **60 cm** | 未实测；只影响降级路径 |

**长距离前进一律用 `go_forward_one_step`**（现场结论：small_step 走长距离
步长太短、准直性极差）。**但末段收最后一点余量时必须用小步**——那正是它
唯一称职的场合，详见 §5.3.1。

### 5.2.1 停点必须先换算口径（最容易搞错、后果最重的一处）

测距工具读的是「**光心地面投影** → 目标」，而"机器人在栏杆前几厘米"说的是
「**脚尖** → 目标」。相机装在头部，其地面投影大致落在脚踝上方，**脚尖在它
前方 4.24 cm**（2026-09-25 卷尺标定；现场复核 +4.55~+4.66 恒定）。所以：

```
工具读数 = 脚尖到目标的距离 + 4.24 cm
```

**如果照字面把停点取成 1.2（工具读数），脚尖就已经越过木条 3.04 cm——
等于站在杆上，一碰 −2 分（封顶 −6）。** 正确取值：

```
窗口上界 HURDLE_STOP_CM = HURDLE_TOE_GAP_CM + TOE_AHEAD_CM = 1.2 + 4.24 = 5.44 cm
窗口下界 = HURDLE_TOE_GAP_MIN_CM + TOE_AHEAD_CM = 0.2 + 4.24 = 4.44 cm
```

**瞄准窗口上界**（5.44）而不是中间：落点只会比瞄准点更近（步子是往前迈的），
所以瞄准上界，最坏情况也只是贴到窗口下界，不会越过去。

这个换算还带来一个额外好处：**5.44 cm 落在可见带（3.5~71 cm）里面**，
最后一段不需要航位推算，起跨点的精度回到测量精度（约 0.4 cm），
比"读数降到 1 cm"那种写法好得多。

回归门：`tests/test_stairs_hurdle_sim.py::test_toe_frame_arithmetic`
（断言口径换算成立）与 `::test_e2e_seeds`
（20 个种子逐个断言"起跨瞬间脚尖仍在杆前"）。

**三条实施规则**（重制时踩出来的，都不是可选项）：

**① 转向死区取"该方向步长的一半 + 1.5° 噪声余量"，不是整步长。**

左转 4.3+1.5=5.8°、右转 2.6+1.5=4.1°。取半步长的理由是收敛性：一步之后
残余 |误差| ≤ 步长 − 死区 ≤ 死区，必然落进死区，不会极限环。而取整步长
（左转就是 10°）会把 10° 以内的偏差**全部放过**，机器人带着它走完整段路，
在十几厘米外横向漂移——实测就是这样跑偏到木条旁边的。

（仓库记过的那次事故是"死区 3.5° < 半步长 5°"，确实会打转；但它不能
反推成"死区要 ≥ 整步长"。）

**② 远距可以"保守批量"，近距必须一步一测。**

含义是"每一批都有复测兜底"，不是"每一步都拍照"。批量步数 =
`余量 ÷ (步长均值 × 1.10)`，用**步长上界**算所以宁可欠走；余量小于 8 cm
就退回一步一测。转向永远是一步一测——左转一步 8.625° 且组间漂移 ±7%，
批量必过冲。

**③ 横偏只纠"跑偏了"的大偏差（>15 cm），且只在 20 cm 以外纠。**

胶条 40 cm、木条 80 cm，都横跨赛道，精确居中本来就没必要。而且目标近或
被画幅裁切时，"可见段中点"不再代表带的中心，读数会乱跳；横移在航向不为
零时还带一点后退分量，越纠越远。实测：不加这条限制，机器人会在木条前
2～4 cm 处反复横移、把自己推离木条。

### 5.3 末段怎么走：闭环到底，靠"步子阶梯"贴窗

**第 3 步（起跨点）不需要推算段**：停点折成工具读数 5.44 cm，落在可见带
（3.5~71 cm）**里面**，一路都能看见。所以这一段是纯闭环。

**第 1 步（起爬点）保留推算段**：停点 7 cm 也在带内，正常情况下同样全程可见；
只有目标掉进盲区（例如胶条被楼梯沿遮住）时才退回"按标定步长推算"，且
**向下取整**（宁可少走：少走只是跨得早，走过头就是踢杆）。

这样末段误差 = 步长误差 × 步数，而不是测距误差。**步长误差可以单独标定，
且不随光照、地面而变化；测距误差会。**

### 5.3.1 末段贴窗：步子阶梯 + 后退调节

验收线是**脚尖离木条 0.2 ~ 1.2 cm**，窗口宽 1.0 cm。怎么把落点收进去：

**① 步子阶梯。** 近距不再"余量不足一整步就不迈"，而是从大到小挑：
先用整步（`go_forward_one_step`）靠近，再用小步（`go_forward_one_small_step`）
一点点收。两级决策：

1. 先找"**预计落点正好落进窗口**"的步子（从大到小），有就迈；
2. 都不在窗口里，就迈"最坏情况也不会冲过窗口下界"的最大的那一步，先靠近；
3. 连最小的步子都不安全，才考虑后退调节或就地停。

> **"落点只能落在 1.8cm 的格点上"是错的前提。** 实测两次量
> `go_forward_one_step` 得到 2.652 和 1.8（差 1.47 倍），步长本身就不稳定，
> 没有固定格点。既然不是格点，能迈多小就该迈多小；用"格点"当理由不迈步，
> 等于白白丢掉最后 1~2 cm。

**② 步长上界必须局内自适应。** 局间步长会整体漂移（就是上面那个 1.47 倍），
所以写死的名义值配 1.10 的安全系数等于没有安全系数。代码在走的过程中用
**读数差反推本局的实际步长**（整步、小步各一份，只往上修），并把这个缩放
同时折算到小步和后退步上。**这是"两步量出来不一样"的正确应对方式**——
不是去猜哪个对，而是运行时量出来。

**③ 后退调节（`BACK_STEP_CM` 标定后启用）。**
还没到停点、但再往前一步就会冲过窗口时，用"**退 + 进小步**"的组合凑：

```
净前进 = k × 小步 − m × 后退      （k ≥ 1, m ≥ 1，组合内最多 4 个动作）
```

单退一步只有后退比小步短才有用；后退更长时（很可能，`back_one_step` 大约
就是整步反过来那么长）**小组合**才管用——这些净位移与整步/小步一般互质，
凑起来等于凭空多出好几档细步子。例：小步 1.5、后退 1.8 时可选净位移
{0.9, 1.2, 1.5, 2.7}，量化从 1.5 cm 降到约 0.3 cm。

安全性：**先退后进**。退完的位置离目标更远，随后每一步前进都比最终落点更远，
所以只要最终落点不越过窗口下界，中间任何一步都不会碰到杆。搜索时"瞄准"用
名义步长，但**安全检查用最坏情况**（前进偏大、后退偏小）。

> ⚠ **这个功能不是万灵药，它自己也有前提。** 安全检查按"最坏净位移"卡，
> 所以只有当后退步**又短又稳**时才拿得出可用组合；后退比小步长、散布又大
> （仿真实测：后退 15% 散布）时，所有组合都会被安全卡掉——**那种情况下它
> 本来也帮不上忙，挡掉是对的**。换句话说：**真正决定落点精度的还是小步
> 标定值**，后退调节只是锦上添花。仿真实测：
>
> | 配置 | 落窗（0.2~1.2cm） |
> |---|---|
> | 小步 1.5（名义）、后退 1.8 | 10/20（后退调节一次没用上，全被安全卡掉） |
> | 小步 0.9（标定）、后退 1.7 | **18/20**，区间 0.23~1.31cm |

**先标小步，再去纠结后退。**

**④ 到位放宽量在起跨点必须是 0。** 通用的 `CONFIRM_SLACK_CM` 是 1 cm，
而窗口总共才 1.0 cm 宽——1 cm 的放宽量会让机器人在余量还有 2.2 cm 时就宣布
"到位"，把整个窗口丢掉（实测丢掉 12/20 个种子）。哪怕放 0.3 cm 也是直接把
上界从 1.2 抬到 1.5（seed 1 就是这么以 1.26 cm 掉出窗口的）。

**⑤ 落点精度最终取决于最小的可用净位移。** 也就是取决于**小步到底多长**：

| 小步实测 | 量化 | 1.0cm 窗口内的大致命中率 |
|---|---|---|
| 1.5 cm（老 FSM 名义值，**未标定**） | 1.5 cm | 约一半（仿真实测 10/20） |
| 0.9 cm（示例标定值） | 0.9 cm | **约 9/10（仿真实测 18/20，区间 0.23~1.31 cm）** |
| ≤ 1.0 cm 且后退也标定得又短又稳 | ≤ 0.35 cm | 应接近全中（后退调节另算，见 ③ 的前提） |

回归门 `tests/test_stairs_hurdle_sim.py` 里的落窗门槛是**按标定值自动算的**
（`window_quota`）：小步填得越短、后退常量填上，门槛自动抬高，标定到量化
≤ 窗口宽就要求 100%——**不需要人去改测试**。

⚠ 还有一条现场要确认的：**跨栏动作组能不能接受 1~2 cm 的站位差**。
它在仿真里被当黑箱（净前进 18 cm），站位差 2 cm 是否影响跨越几何，仿真答不了。

### 5.3.2 现场标定怎么填（唯一填写处）

**只改 `core/motion_calib.py` 一个文件的这一节，别的地方一律不动。**

| 常量 | 填什么 | 影响 |
|---|---|---|
| `FWD_SMALL_STEP_CM` | `go_forward_one_small_step` 走一步多少 cm | 末段贴窗的最小量化 |
| `BACK_STEP_CM` | `back_one_step` 后退一步多少 cm | 后退调节的细档；不填=关闭 |
| `FWD_STEP_CM` | `go_forward_one_step` 一步多少 cm（现填现场口径 1.8） | 所有"走几步"的推算 |

量法：机器人站直，脚尖前贴一条胶带当地面基准，走 N=10 步（N 取大一点，
单步误差被摊薄），量脚尖位移 ÷ N。三个动作各量一遍。
**顺便核对整步**：如果和现在的 1.8 对不上，就把它一起改掉——那个数决定
远距批量与出场步数。

填完之后 **开场日志会自检**，一眼能看出有没有生效：

```
常数自检：整步 1.80cm | 小步 1.50cm（⚠ 未标定 · 名义值：填 ...） | 后退 —（未标定 · 后退调节关闭：填 ...） | 脚尖偏移 4.24cm
常数自检：整步 1.80cm | 小步 0.80cm | 后退 1.10cm | 脚尖偏移 4.24cm
```

回归门：`tests/test_stairs_hurdle_sim.py::test_calibration_plumbing`
（钉死"填了就生效"，包括防止在 import 时把旧值缓存住）。

### 5.4 各步判据

**第 1 步（对准并走到起爬点）**
- 目标：红胶条，窗口 0～55 cm
- 闭环走到起爬点（离胶条 7 cm）→ 目标掉进盲区时按标定步长推算
- **降级**：胶条始终不见时，按摆位先验（60 cm）往前走，**但边走边接着找**——
  每走一小批就再拍一帧，一旦胶条重新出现立刻交回闭环。摆位先验估错得越多，
  越早看见目标，所以这个兜底的风险是有界的。

**第 2 步（上下台阶，整段写死）**
- 顺序固定：`climb_stairs` → `turn_right_small_step` → `climb_stairs` →
  `turn_right_small_step` → `down_floor` → `turn_right_small_step` →
  `down_floor` → `turn_right_small_step` → `stand`
- 中间不插任何判断（动作组执行期间只能开环，而且现场证明固定补偿比顶上测方位更稳）
- 出口：动作全部完成并站定

**第 3 步（对准并走到起跨点）**
- 目标：木条，窗口 0～50 cm，**方向与距离都用**
- 此时机器人和木条站在同一平面上，距离读数有效
- 这一步是全场罚分（碰撞，封顶 −6）的唯一来源，测量冗余度最高
- 闭环走到**工具读数 5.44 cm**（= 脚尖离杆 1.2 cm，见 §5.2.1）
- 末段用**步子阶梯**（整步→小步）贴窗；走不动时用**后退调节**凑细档。
  落点目标窗口 **脚尖离杆 0.2 ~ 1.2 cm**，保证碰不到杆（见 §5.3.1）
- **降级**：木条始终不见时，按 25～40 cm 的中值 32 cm 当先验，同样边走边找

**第 4 步（跨栏）**
- `hurdles` → 站定 → 结束
- **不需要识别终点线**：跨栏动作组实测净前进 18 cm，跨完直接交棒给下一关
- 需要"多走一点到终点线"时，把 `SKIP_EXIT` 改成 `False`，出场步数由跨障区
  几何与实测杆距推算（不用固定常数）

### 5.5 降级链

拍照失败重试 → 变俯仰档重试 → 按上一步的有效读数推算 → 按摆位先验边走边找。

**任何情况下都不做长距离盲搜。** 旧实现允许最多 100 cm 的盲搜，但起点距楼梯不到
30 cm，盲搜会直接把机器人送进楼梯。本方案的"先验盲走"是**分批 + 每批复测**，
不是一口气走到底。

### 5.6 为什么第 3 步可以在平地上量距离（旧"顶上只用方向"的替代）

原来担心的是：站在台阶上时木条比脚下平面低（相差 2.5～5 cm），投影是绕光心的
**均匀径向缩放**：

```
地面交点 = 目标点 × h / (h + Δ)      Δ = 高度差
```

这是纯粹的等比缩放，**方向严格不变**，距离偏小一到两成。所以旧流程在台阶上
只敢用方向（旧 §5.6），把距离判断留到下完楼之后。

新流程把量距离这一步**整个挪到了台阶之下**：第 2 步一口气走完上下台阶，第 3 步
是在平地上测木条，机器人和木条同处一个平面，Δ = 0，距离读数直接有效。
"顶上只用方向"这条约束因此不再需要——它是旧流程"上楼下楼分成两步、中间夹一次
对正"的产物。

同理，"径向缩放保方向"这个性质现在只在**降级**时有意义：`tests/test_ground_line_meter.py`
里保留了"台阶上读数偏小 ×0.76～0.89"的记录，用于解释万一在台阶上看读数会怎样。

## 6. 目标不会混淆（论证）

之前担心的"红胶条和木条都是红的、怎么分"在本流程下**不存在**，因为木条只在爬楼之后才进入视野：

| 机器人位置 | 木条距离 | 可见性（远界 71 cm） |
|---|---|---|
| 起点（摆位，约 y=−60） | 130～145 cm | 不可见 |
| 第 1 步途中（y=−45…−7） | 115～77 cm | 不可见 |
| 起爬点（离胶条 7 cm） | 77～92 cm | 不可见 |
| 顶部平台（y 24 附近） | 46～61 cm | 可见 |
| 台阶上（y 0～45） | 70～85 cm 以下 | 视位置而定 |
| 下完楼（y≈48） | 22～37 cm | 可见，且同平面，距离最准 |

- **第 1 步全程**：木条距离 ≥ 77 cm，超出远界 ⇒ 画面上唯一的红色就是胶条。
- **第 3 步**：胶条已在身后 ⇒ 画面上唯一的红色就是木条。

所以不需要新的检测方法，只需要每步显式指定目标窗口。

回归门：`tests/test_stairs_hurdle_sim.py::test_goal_uniqueness` 在五个探针位置
验证"第 1 步胶条 5/5 可见、木条 0/5 可见"，并在下完楼后验证"脚下无红色目标、
木条 25 cm 处可见"。

⚠️ 第 2 步的楼梯段是开环，机器人在平台与台阶上的确切位置由黑箱动作组的净位移
决定（§9 第 3 项）。不过新流程**不再依赖"平台上能不能看见木条"**——量距离挪到
了台阶之下，所以这一项从"必须确认"降级为"只影响仿真一致性"。

## 7. 标定路线与验收线

### 7.1 采用什么（已换过一次，这里是结论）

**采用：卷尺刻度点击标定（`tools/calib_ruler_profile.py`）。**

拍一张卷尺纵贯可见带的照片，点出每个刻度的像素位置与卷尺读数，拟合出
「刻度平面高度 `h−λ`、地面俯角 θ、零点偏移」三个量。2026-09-25 实测：
14 个刻度（读数 3～60 cm），含畸变物理模型 **RMS = 2.72 px**，零坏点；
同一组数据去掉畸变后 RMS = 12.60 px（**畸变把残差砍到 1/4.6**）。

**已放弃：点击式二维全 H 标定（`tools/calib_stairs_hurdle.py`）。**
放弃的理由不是精度，而是**它要的那个原点现场找不到**：全 H 标定需要一个
"机体坐标原点"来定义距离，而"相机光心的地面投影"这个点没法在地面上标出来。
继续做下去只会得到一个建立在猜测原点上的 H。工具留在仓库里当留档，并已在
文件头标注为**已放弃**。

### 7.2 距离真值的量法约定（现场口径）

两条都会让标定整体偏掉，必须记住：

**① 卷尺零点压在机器人脚尖上**，读数就是"离脚尖的距离"。（不是光心地面投影——那个点现场根本找不到；也不是双脚中心。）
现场实测：工具读数（以光心地面投影为原点）比卷尺读数（以脚尖为原点）
系统性大 **+4.24 cm**，这就是脚尖到光心地面投影的纵向距离。

**② 刻度印在卷尺上表面，比地面高约 1cm。** 这是已知的测量缺陷，列在这里是因为它有个漂亮的性质：**卷尺厚度 λ 与相机高度 h 在模型里只以 `h−λ` 的形式出现，两者永远分不开**。所以标定时**不必也不能**分别给这两个数，拟合出来的就是「光心离**刻度平面**的高度」。要量**地面**目标时再把 λ 加回去，影响是约 `λ/h ≈ 3%` 的比例误差——40cm 处约 1cm，**2cm 处只有 0.06cm**，所以对起跨点几乎无所谓。

标定结果：`h_eff = 32.73 cm`、`θ = 55.11°`、零点偏移 `+4.24 cm`；
加回卷尺厚 1.20 cm 得**光心离地 33.93 cm ≈ 33.9 cm**，反推安装下俯偏移
`55.11 − 36.0 = 19.11°`。

⚠️ `core/ground_homography.py` 的 `CAMERA_TO_BODY_FORWARD_CM = 4.0`
**是仿真参数，不是实测值**，不能拿来当"光心→机体偏移"的真值对照。
（实测值是 4.24 cm，两者只是碰巧接近。）

### 7.2.1 标定参数一律从数据里解，不要传猜测值

刻度平面高度、俯角、零点偏移**三个量全部由拟合解出**。实测（合成数据 + 2px
点击噪声）：三者都解得出来，零点偏移只飘 ±0.16cm。所以工具**不提供**"高度大概
多少、卷尺大概多厚"这类默认值——那只会给出一个看着确定、其实建立在猜测上的数。

⚠️ 零点偏移在自由射影模型下**不可辨识**（`y=(a+bd)/(c+d)` 对 `d → d+t` 不变，
实测偏移 ±10cm 残差一字不变），只有物理模型解得出来。

工具：`tools/calib_ruler_profile.py`（零已知参数即可跑）。输出里的"零点偏移"
就是脚尖到光心地面投影的纵向距离；"刻度平面高度"即 `h−λ`。

### 7.2.2 验证工具不是标定工具

`tools/verify_red_distance.py` 是**检查**工具：拿已经定好的相机参数，在同样的
几何下算一遍"给定像素行 → 应该是多少厘米"，用来核对现场摆放和读数。

⚠️ 它曾经漏掉安装偏移，把 30 cm 报成 49.2 cm（1.7 倍）。修好之后自检：
10 / 20 / 30 / 45 / 60 cm → **10.00 / 20.00 / 30.00 / 45.02 / 60.01**。
现场用真杆复核：同一读数减卷尺读数 = **+4.55 ～ +4.66 cm**，在 3～47.5 cm
全程恒定（正是 §7.2① 的脚尖偏移），**距离误差约 +0.4 cm**。

### 7.3 禁止

- **禁止**建立一维"像素 y → 距离"曲线作为唯一真值。九宫格当初的理由（残差 142.53 px、
  逐线反推得"相机在地板下"）**已被推翻**——那份数据把线↔距离配反了（正确配对下
  残差 58.7 px vs 反配 349.6 px；**交比法查不出配反**）。
  但结论仍然成立，只是理由要换：**凭眼睛在图上画整条横线，精度不够**，残差是系统性的。
  要标就用点击刻度（`tools/calib_ruler_profile.py`），并做走向自检。
- **禁止**用针孔公式推导可见范围（见 §2.2）。
- **禁止**把运行 OpenCV 窗口的标定工具放到机器人上跑——机器人上是 headless
  OpenCV，`cv2.namedWindow` 直接失败。标定一律在 PC 上用 `--image` 跑。

### 7.3 验收线

| 距离段 | 指标 | 现状 |
|---|---|---|
| d ≤ 50 cm | 误差 ≤ 2 cm，重复 σ ≤ 1 cm | ✅ 现场 worst 0.42 cm |
| **2 ～ 10 cm（新增）** | **误差 ≤ 1 cm** | ✅ 已满足 |

补第二条的理由：停点是"读数降到小值就停"，对**比例误差**天然免疫，真正致命的是**零点偏移**。如果读数系统偏大 2 cm，那么"读数 5.44 cm"时机器人已经压到木条上了。原有的 d≤50 cm 验收线守不住这一点。
（"近段"按 §5.2.1 折算：脚尖离杆 1.2 cm ⇒ 工具读数 5.44 cm。）

## 8. 与旧实现的差异

| 项 | 旧实现 | 本方案 |
|---|---|---|
| 流程步数 | 6 步（上楼与下楼之间夹一次"顶上对正"） | **4 步**（上下台阶合并成一步、整段写死） |
| 对正 | 8 轮循环 + 最多 100 cm 盲搜 | 一帧确认 + 边走边修，禁止长距离盲搜 |
| 接近楼梯 | 固定步数开环 | 闭环看红胶条 + 末段推算 |
| 楼梯段 | 上楼、顶上测方位、下楼分成三段 | **整段 4 个动作组 + 4 次右小转，零分支** |
| 接近木条 | 与接近楼梯共用一套逻辑 | 独立闭环，高测量冗余；停点**换算到脚尖口径** |
| 近距末段 | 无条件迈步，可能越过停点 | **步子阶梯**：预计落点在窗口里就迈，否则迈最坏情况也安全的最大一步 |
| 目标识别 | 取最近的红色簇 | 按步骤指定目标 + 距离窗口 |
| 收尾 | 固定 6 步离场 | 跨栏后**直接交棒**（`SKIP_EXIT`），需要时再按实测杆距推算 |
| 前进动作 | `go_forward_one_small_step` | **一律 `go_forward_one_step`**（现场：small_step 太短且准直性极差） |
| 相机高度 | 39 cm | **33.9 cm** |
| 安装偏移 | 完全漏掉 | **19.1°** |

   出来的；如果复量发现上楼与下楼的偏置方向相反，写死的序列必须改回"逐步测方位"。
