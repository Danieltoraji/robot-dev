## 1. 关卡概述

赛事入门级关卡：机器人自主完成**两级台阶上下楼梯**，随后在 50cm 平地区域**识别红色横杆障碍、精准停位并跨越**，整体越过终点线结束。全程无人工干预。考察人形机器人基础运动调参、视觉图像处理与简单闭环控制的综合应用。

场地布局（沿运动方向）：入口红外对射光束 → 楼梯区域 → 平地跨障区 → 出口红外光束。机器人摆在入口黑胶带线以外，位置自选。

```
入口红外(开始计时) ──► 楼梯区: 2级台阶上行30cm/爬升5cm ──► 下行
      ──► 平地50cm: 红色木条(距楼梯下沿25~40cm, 2×2cm截面, 横贯80cm全宽) ──► 跨越
      ──► 终点线/出口红外(结束计时) ──► 结算
```

## 2. 关卡要求

### 2.1 场地规格

| 区域 | 规格 |
|---|---|
| 楼梯 | 2 级直角阶梯，木质原色无标识、踏面平整无防滑条；踏面深 15cm、踢面高 2.5cm（总爬升 5cm）；楼梯水平长 30cm，赛道宽 80cm |
| 平地跨障区 | 长 50cm（楼梯下沿出口→终点线）；地面考虑绘制白色中线辅助直行，**不强制巡线**，偏移不直接扣分 |
| 障碍物 | 红色松木条，截面 2×2cm、长 80cm（= 赛道全宽，**无法绕行，必须正跨**）；距楼梯下沿 25~40cm 区间随机放置，选手提交代码后位置固定 |
| 终点 | 平地末端终点标识线，机器人整体越过（遮断出口光束）即完成 |

### 2.2 计分规则（ESP32-S3 主控，初始 10 分）

| 项目 | 判定方式 |
|---|---|
| 碰撞 | 801S 振动传感器装在木条上；ONGOING 期间每次有效碰撞 −2 分，2s 冷却，单局最多记 3 次（−6 封顶）；STANDBY/FINISH 状态碰撞不扣分 |
| 超时 | 分档 −1 分，最多 −3；仅 ONGOING 期间执行 |

**⚠️ 重大不一致**：说明书写超时阈值为 **150/160/170s**，但 `level.c:37` 固件代码是 `{80, 90, 100}`（且该文件自己的注释写"超过 2 分半"，与数组也对不上）。**现场必须确认实际烧录固件**——本方案按 80s 保守设计，确认 150s 档后可放宽。

其他裁判侧事实：摔倒罚项 `PENALTY_FALLING` 在固件中定义但**无触发逻辑**，判罚方式待确认；FINISH 后需人工按复位按钮才会回到 STANDBY；状态变化时 HTTP POST JSON 上传计分服务器（`server.py` 只是回显桩）。

### 2.3 硬件约束

仅 TonyPi 人形机器人本体 + 头部单目摄像头（fswebcam 静态拍照），**不允许改装机器人**。仓库已确认无 IMU/接触/姿态传感读取（摄像头是唯一外感受器）。

## 3. 当前逻辑（参考实现剖析）

`Final_Edition.py` 是纯顺序脚本：`main() = stairs_main() + hurdle_main() + 5 大步离场`，无状态机、无失败恢复。

### 3.1 楼梯段（全开环）

```
stand → 头 pitch=1300
→ 大步前进 ×5 接近楼梯（PRE_BIG_FORWARD_STEPS）
→ 【climb_stairs 动作组 + 1 小步】×2（间隔 1.0s）
→ 顶部调整：退 1 小步 + 右转 2 小步（纯漂移经验补偿）
→ 【down_floor】×2（间隔 1.2s）
→ stand → 头 pitch 复位 1500
```

**全程一帧照片不拍，不做任何确认。** 接近步数、顶部补偿全部写死；横向对齐参数（ALIGN_LEFT/RIGHT）预留了接口但为 0。

### 3.2 跨障段（视觉测距 + 三段式闭环）

1. **初始化**：后退 3 小步拉开与楼梯下沿的距离；头 yaw=1400（注释"只针对 12/141 号机"）、pitch=1000（注释"我调出来的，别动"）固定观测位。
2. **检测**：HSV 红色双区间（H<12 或 H>160，S/V>50）→ 高斯模糊 7×7 → 形态学开闭 5×5 → 最大轮廓（≥500px）→ 取轮廓最低点像素 y。（`BARRIER_ASPECT_RATIO_MIN=0`，形状过滤实际关闭。）
3. **测距**：5 帧取均值（≥3 帧有效，否则判失败）→ 两层 MLP（1→8→1，ReLU），y 像素 → 距离 cm。权重 `mlp_weights.npz`。
4. **三段式闭环停车**（目标停点距木条 0.5cm）：
   - 远段（>10cm）：每轮 ≤5 大步（步数乘 0.5 安全系数防冲过）+ 重新测距；
   - 中段（8~10cm）：单小步 + 重测（作者自注"常常不会经过，设置的太短了"）；
   - 近段（<8cm）：**盲走**——障碍物出视野，靠 1.5cm/小步航位推算，作者自注"最后来来回回误差目前在 2cm 左右"。
5. 距离达标 → 执行自制 `my_hurdles.d6a` 动作组跨障 → stand。
6. **检测失败直接 return 弃赛**（"前方未检测到红色障碍物"）。

### 3.3 训练链路

`Training_code.py` 交互式采集（y 像素，真实距离）20~40 组（建议 5~30cm）→ `Train_model.py` 训 MLP（3 种子取最优，Adam，输出层合并反标准化直接出 cm）→ 导出 `mlp_weights.npz`。附验收指标：val MAE > 1cm 或 8cm 内 MAE > 0.8cm 会告警。

## 4. 不足之处

### 4.1 楼梯段

1. **纯开环、零感知**：接近步数（5）、顶部补偿（右转 2）写死；起点摆放误差与动作组位移散布直接传导为上楼误差，踩空/卡梯风险全靠 80cm 赛道宽度兜底。机器人明明有摄像头却一帧不拍、不做任何确认。
2. **无失败检测与恢复**：硬件无 IMU，代码无重试/中止逻辑，踩空后仍会继续执行下楼，大概率演变为摔倒（摔倒即闯关失败，即便罚项未接线）。

### 4.2 跨障段

3. **MLP 测距是黑盒标定**：y 像素→距离本质是固定 pitch 下的 pinhole 几何关系，MLP 只是拟合曲线。代价：换机器人/俯仰角/分辨率/场地全部作废，现场需重采 20~40 组数据再训练；无外参可解释性。
4. **8cm 盲区 + 盲走误差 2cm**：固定 pitch 下视野下界决定 8cm 内看不见障碍物，只能航位推算；而停车目标是 0.5cm——±2cm 的起跨点误差正是踢到木条（−2 分/次）的主要来源。
5. **视觉鲁棒性弱**：无 ROI、形状过滤实际关闭、5 帧取均值对野值无抵抗力（九宫格关卡已吃过观测野值的亏，应取中位数）、无置信度概念；检测失败直接弃赛，无重试、无变俯仰搜索。
6. **效率隐患**：每轮测距拍 5 张 2592×1944 静态照片（fswebcam 单张秒级）；远段每轮 5 步 + 一轮测距。若现场固件确为 80s 档，视觉耗时可能吃掉大半时间预算（九宫格经验：拍照耗时是现场最大风险）。

### 4.3 工程与移植

7. **参数强绑定个体与场地**（yaw=1400、步长 1.5/2.2cm 均标注"换机/换场地要重测"），但调校全靠改代码，无参数外置。
8. **与主仓库体系零对接**：独立脚本自带 capture/ctl，享受不到 trace 轨迹记录、debug_server 离线分析、FSM 模式；且 `tools/sync_to_robot.py` 的 `SKIP_EXTS` 会跳过 `.npz`——参考权重根本同步不上机器人（若沿用 MLP 方案需加入 `EXTRA_FILES` 白名单）。
9. **无仿真与回归手段**；裁判文档与固件不一致（80 vs 150s）从未被交叉核对。

## 5. 我的方案

总纲：**「保底可通、测距升级、工具化调参」**。楼梯动作受硬件限制（无 IMU）保留开环，升级火力集中在跨障测距与工程化上。

### 5.1 架构接入（直接复用仓库模式）

新建 `levels/stairs_hurdle.py`，按 `main.py:LEVELS` 三步注册；继承 `core/robot_core.py:RobotState`（`run_action`/`set_pitch`/`capture_image`/`act` 位移预算守卫）；仿 `levels/nine_grid.py` 的 FSM 风格组织状态；全程开 `core/trace.py` 轨迹记录。注意：`MOTION_BUDGET_CM` 表需补 `climb_stairs`/`down_floor`/跨障动作条目（实测水平位移后登记，否则落到默认 6.0cm 上界）。

### 5.2 跨障测距升级（核心改进）：单应投影替代 MLP

用 `core/ground_homography.py:GroundHomography`（`pixels_to_ground` 按 pitch 档像素↔地面投影）替代 MLP：在跨障观测位 pitch=1000 档标定一次单应，障碍物底边 y 直接投到地面得距离。收益：

- **一次标定覆盖全距离段，免掉现场 20~40 组数据采集与训练**（标定流程复用 `tools/calib_ninegrid.py` 点击式工具）；
- 物理可解释，换分辨率/微调参数只需重标不重训；
- **单应天然给出"可见下界 d_min"**——盲走段从精确的 d_min 起步，而不是模糊的 8cm。

配套：检测换 `vision/color_detector.py:ColorBlobDetector` + 增加形状/宽高比过滤 + 多帧取**中位数**；标定产物走 `sync_to_robot.py:EXTRA_FILES` 白名单。

### 5.3 闭环控制重设计

保留三段式骨架（方向是对的），改进：

- 远段单应可靠后加大每轮步数上限（有 `act()` 预算守卫兜底防冲过）；
- 近段盲走步长用 MOTION_BUDGET 式多步累计实测，不测一次就用；
- 检测失败走重试 FSM：重试 N 次 → 变 pitch 档再找 → 仍失败则按标定步数保守直行。**任何情况不弃赛。**

### 5.4 时间预算（按 80s 保守设计）

测距帧 5→3、拍照分辨率降档（重标单应即可）、远段一轮多步；目标视觉环节 ≤25s、全程 ≤75s。现场确认固件为 150s 档后放宽。

### 5.5 楼梯段加固

- 参数全部外置成"现场标定表" + 标准化调参流程（起点贴线摆放仪式 + 单变量调参，参考代码尾部调参说明已成体系，直接继承）；
- 增加一个**低成本视觉确认点**：上楼前低头拍一张，用台阶立面-踏面交线（亮度跳变）确认楼梯在预期区域才执行 climb；检测不稳定则退化为纯开环保底；
- 上/下楼动作间隔（1.0/1.2s）只增不减。

### 5.6 跨障动作组

先试机器人现成的 `hurdles` 标准动作组（`docs/比赛相关材料/机器人调用说明.md` 动作组清单已确认存在）；余量不足再自制（抬脚 > 2cm 截面 + 安全余量；落脚点离木条留距离，防 801S 振动误判）。说明书明言跨障动作组"需自行调整舵机参数编辑，否则难以完成关卡目标"——**这是现场工作量最大的一项，需预留整段调试时间**。

### 5.7 调试工具链

- `tools/debug_server.py` + `debug.sh`：零侵入复用关卡照片链路，离线调 HSV/单应；
- 仿 `sim/nine_grid_sim.py` 做合成障碍帧的识别+决策回归测试（不含步态）；
- `tools/exec_on_robot.py` 跑静态测距验证脚本。
