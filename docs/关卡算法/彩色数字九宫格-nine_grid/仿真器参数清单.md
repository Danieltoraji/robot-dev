# nine_grid 仿真器参数清单（2026-09-25 逐行核对）

> 本文把 nine_grid 关卡**仿真侧的全部参数**分门别类列全：哪些是写死的场景真值、
> 哪些能从命令行改、哪些由驱动器在内存里改、哪些只是测试护栏。
> 每一条都标注了**权威源**（文件:行附近的符号名），改代码时以那里为准。
>
> 用法（怎么跑、怎么看、怎么批量）见 `docs/仿真器使用说明.md`；
> 建模/未建模的动机见 `sim/nine_grid_sim.py` 模块 docstring。

九个宫格的"仿真器"实际有 **4 个入口**共用同一份仿真核心：

| 入口 | 角色 | 参数承载 |
|---|---|---|
| `sim/nine_grid_sim.py` | **仿真核心**（世界+相机+动作）+ 无头 CLI | 场景真值常量、`run_simulation()` 形参、5 个 CLI 参数 |
| `sim/nine_grid_view.py` | 图形界面包装（`NineGridView`） | 6 个 CLI 参数 + 6 个显示常量 |
| `tools/record_run.py` | 录像驱动器（`Recorder(NineGridView)`） | 11 个 CLI 参数 + 改写 6 个关卡常量 |
| `tools/ab_ninegrid.py` | 多种子 A/B 驱动器 | 8 个 CLI 参数 + 10 个"臂" + 实测原语注入 |

## 1. 场景真值常量（写死在 `sim/nine_grid_sim.py`，**CLI 改不了**）

| 常量 | 值 | 含义 / 依据 |
|---|---|---|
| `FRAME_W × FRAME_H` | 2592 × 1944 | 合成画幅（= fswebcam 拍照分辨率） |
| 背景 | 纯灰 `90` | **无杂物、无同色地垫、无机体遮挡** |
| `PANEL_HALF_CM` | 14.0 | 面板半边 ⇒ 色块 28×28cm（33.3cm 格减缝） |
| `DIGIT_HALF_CM` | (4.0, 6.0) | 数字块 8×12cm |
| `COLOR_HSV` | red(3,200,200) orange(12,200,200) yellow(27,180,200) green(65,200,100) blue(107,230,130) purple(124,150,150) pink(165,120,150) | 渲染用的"必然满足检测阈值"的 HSV |
| `SIM_LAYOUT` | `{0:5, 1:2, 2:7, 3:1, 4:4, 5:6, 6:None, 7:3, 8:None}` | 默认固定布局（**6 与 8 都空**） |
| `random_layout(seed)` | 位置 6 恒空，其余 8 格中取 7 格 | 随机布局；`RandomState(seed)` ⇒ 可复现 |
| `GLYPH_ASSET_PATH` | `models/nine_grid/digit_glyphs.npz` | **真字形**资产（与现场照片同源，2026-09-25 P0） |
| `GLYPH_ROTATE_SEED` | 20260925 | 字形朝向 = 按格位 `RandomState(seed + cell*7919)` 取 90°×k |
| `GLYPH_DIGIT_SIZE_CM` | = `DIGIT_HALF_CM` | 字形贴图尺寸 |
| 缺资产行为 | 打印告警 + 退回黑块 | **不静默降级**（数字链路会失去输入信号） |

| 常量 | 值 | 含义 |
|---|---|---|
| `GRID_CELL_CM` | `100/3 ≈ 33.33` | 场地 1m 底板、3×3 格 |
| `ROW0_IS_FAR` | True | 位置 0/1/2 = 最远排 |
| `COL0_IS_LEFT` | True | 位置 0/3/6 = 入口视角左手边；**6 = 左下恒空** |

## 2. 相机 / 机体真值（从 `core/camera_config.py` 导入，与生产**同源**）

仿真渲染与关卡投影必须用同一套数字，否则端到端必挂（历史坑：pitch1200 名义 27° vs 实际 45.5°）。

| 常量 | 值 | 备注 |
|---|---|---|
| `CAMERA_INTRINSIC` | fx 1944.904, fy 1950.095, cx 1283.069, cy 983.198 | 对应 2592×1944 |
| `CAMERA_DISTORTION` | k1 −0.384402, k2 0.284682, p1 = p2 = 0 | 渲染帧带真实径向畸变 |
| `CAM_HEIGHT_STANDING_CM` | 56.0 cm | 仿真 `SimNineGridRobot.CAM_HEIGHT` |
| `CAM_PITCH_MOUNT_OFFSET_DEG` | 18.5° | 有效俯角 = (1500−pitch)×0.09 + 18.5° |
| `SERVO_DEG_PER_US` | 0.09 | 舵机脉宽→度 |
| `HEAD_CENTER` | 1500 | 头部中位脉宽 |
| `CAM_BODY_OFFSET` | **0.0** | 仿真中"相机=机体中心"；关卡另有 4cm 后退，端到端容差内 |
| 初始位姿 | `pos=[50, −20]`、`heading=0°`、`pitch=1500`、`head=1500` | 入口外居中朝场 |
| `capture_cost_s` | **0.001 s/张** | 真机 0.62~0.70 s/张 ⇒ 仿真**不会**先撞拍照预算熔断，真机才会 |

## 3. 运动原语：三套口径（**最容易踩的一处**）

同一动作有 3 组数字，混用就会得出错误结论：

| 动作 | ① 仿真真值 `_apply_action` | ② 关卡名义 `ACTION_MODEL` | ③ 现场实测 `ab_ninegrid.REAL` |
|---|---|---|---|
| `go_forward` | 5.0 cm ×(1+N(0,**0.08**)) | —（`DISABLED_ACTIONS` 禁用） | — |
| `go_forward_one_step` | 2.0 cm ×(1+N(0,**0.15**)) | 2.0 | **2.652** |
| `back_one_step` | 3.2 cm ×(1+N(0,**0.15**)) | −3.2 | 3.2 |
| `left_move` | 1.9 cm ×(1+N(0,**0.20**)) | −1.9 | **2.497** |
| `right_move` | 2.2 cm ×(1+N(0,**0.20**)) | +2.2 | **2.200** |
| `turn_left` | 22.0° ×(1+N(0,**0.10**)) | −22.0 | −22.0 |
| `turn_right` | 25.7° ×(1+N(0,**0.10**)) | +25.7 | +25.7 |
| `turn_left_small_step` | **max(0, N(2.0, 1.5))** | −2.0 | **−8.625** |
| `turn_right_small_step` | **max(0, N(2.0, 1.5))** | +2.0 | **+5.200** |
| `stand` | 无位移 | 0 | 0 |

要点：

1. **① = ②** 只对 6 个"整步"原语成立；小转的仿真模型是 `max(0, N(2.0,1.5))`——
   对称、均值 ≈2°、有约 9% 概率被"地面吞掉"（截断在 0）。
2. **现场小转是左 8.625° / 右 5.200°（严重不对称）** ⇒ 在仿真的 2° 步长下，
   "死区 12° 一步跨不出去"这个真机矛盾**根本测不出来**。
   这就是 `tools/_tmp_zone_eval.py` docstring 说的"不换原语就测不出真实差异"。
3. 换原语必须**成对换**（仿真侧 `_apply_action` + 关卡侧 `ACTION_MODEL` 族常量），
   单独换一半会把基线打挂（`ab_ninegrid.set_level_real` docstring）：

   - 正式做法：`python tools/ab_ninegrid.py --primitives real`（成对，仅内存内）；
   - 旧探针 `tools/_tmp_zone_eval.py` 只换仿真侧、**不成对**——只适合旧口径对照，
     不要拿它的结论当真机结论。
4. 仿真侧打滑噪声的随机流来自 `RandomState(seed)`（每实例独立）；
   字形朝向用的是**另一条**独立流（`GLYPH_ROTATE_SEED`），刻意不扰动动作序列。

## 4. 地板形变注入（`deform` dict，唯一的"世界侧扰动"）

只改**世界侧**的相机姿态/高度，关卡内常数保持不动 ⇒ 精确复现"常数失配"。
形变只在**动作**时演化（站定扫头部期间不变，与现场一致）。

| 键 | 默认 | 含义 |
|---|---|---|
| `sigma_tilt_deg` | 0（=无形变） | 每动作俯仰随机游走步长（度） |
| `sigma_h_cm` | 0 | 每动作高度随机游走步长（cm） |
| `max_tilt_deg` | **15.0** | 俯仰限幅（代码内缺省） |
| `max_h_cm` | **3.0** | 高度限幅（代码内缺省） |
| `step_after_actions` | 无 | 第 N 个动作后施加一次性阶跃（**与动作流强耦合，仅用于复现历史日志**） |
| `step_at_digit` | 无 | 第 K 格开始时施加一次性阶跃（**新回归一律用这个**：与被测代码的动作数解耦） |
| `step_tilt_deg` / `step_h_cm` | 0 | 阶跃幅度 |

- 形变 RNG = `RandomState(seed + 977)`，与动作噪声**分流**，可复现。
- **CLI 只暴露一个数**：`--deform SIGMA_TILT_DEG` ⇒ 实际注入
  `{sigma_tilt_deg: SIGMA, sigma_h_cm: 0.5, max_tilt_deg: 15.0, **max_h_cm: 2.0**}`。
  ⚠️ 注意 CLI 传的 `max_h_cm=2.0` 与代码内缺省 `3.0` **不一致**（写自定义
  deform 时按自己的 dict 走）。
- 已固化的计分场景（`tests/test_nine_grid_deform.py`）：

| 用例 | deform |
|---|---|
| 基线 | 无 |
| 随机游走 | σ 3.0°/动作 + 0.5cm/动作，限幅 ±15° / ±2cm |
| 阶跃（第 3 格） | `step_at_digit=3, step_tilt_deg=+15.0, step_h_cm=−2.0` |
| 阶跃（第 5 格） | 同上换 `step_at_digit=5` |
| 旧耦合场景 | `step_after_actions=60`（**只诊断、不计分**） |

## 5. `run_simulation()` 形参（唯一的"跑一局"入口）

```python
run_simulation(layout=SIM_LAYOUT, seed=3, quiet=False, viewer=None, deform=None)
# -> SimRun(robot, level, stats)
```

| 形参 | 默认 | 说明 |
|---|---|---|
| `layout` | `SIM_LAYOUT` | `{cell: digit}`；`random_layout(seed)` 生成随机布局 |
| `seed` | 3 | 动作噪声种子（`RandomState(seed)`，逐字节可复现） |
| `quiet` | False | 吞掉关卡逐行日志（重定向 stdout） |
| `viewer` | None | `None`=纯无头；否则需 `attach(robot, level)` + `on_action` + `on_frame` |
| `deform` | None | §4 的 dict；None=无形变 |

`stats` 的键（批量统计就靠这些）：
`ok_all`、`results`、`layout_ok`、`digit_cell`、`truth`、`captures`、`actions`、
`action_counts`、`small_turn_deg`、`small_turn_usable`、`banned_used`、`cell_trips`、
`panel_landing`（逐格**真值**落点 cm）、`deform_tilt_deg`、`deform_height_cm`。

另外挂在 `robot` 上的真值（评测工具用，关卡**不消费**）：
`_last_frame_truth`（每帧面板级真值：cx/cy/bbox/visible_frac/occluded_by/clipped）、
`action_log`、`n_captures`、`current_digit`、`set_deform_digit()`。

## 6. CLI 参数逐条

### 6.1 `python -m sim.nine_grid_sim`（无头）

| 参数 | 默认 | 作用 |
|---|---|---|
| `--seed N` | 3 | 动作噪声/随机布局种子 |
| `--random-layout` | off | 用 seed 生成随机布局；**不加则布局恒定，只有噪声随 seed 变** |
| `--quiet` | off | 只打摘要 |
| `--deform σ` | 0.0 | 见 §4（σ=每动作俯仰随机游走步长） |
| `--unified` | off | 本进程内把 `UNIFIED_NAV_ENABLED / VIS_ZONE_ENABLED / VIS_REANCHOR_BY_ANCHOR` 置 True，**跑完还原** |

退出码：`0` = `ok_all` 且 `layout_ok`；否则 `1`。

### 6.2 `python -m sim.nine_grid_view`（图形界面）

| 参数 | 默认 | 作用 |
|---|---|---|
| `--seed N` | 3 | 同上 |
| `--random-layout` | off | 同上 |
| `--delay MS` | 30 | 每帧等待 ms（0→`waitKey(1)`）；键 `+/-` 在 1~500 间倍增/减半 |
| `--detect` | off | 运行中也跑检测器叠加（单帧 ~120ms，整轮约 +25s） |
| `--headless` | off | 不开窗，等价 `nine_grid_sim` |
| `--quiet` | off | 吞掉关卡逐行日志 |

`NineGridView(delay_ms=30, show_detect=False)`；显示常量：`CAM_SCALE=0.25`、
`MAP_SIZE=400`、`MAP_MARGIN=16`、`STATUS_H=52`、`GAP=12`、俯视视野 `VIEW −25~110cm`
⇒ 窗口 1060×538。

### 6.3 `python tools/record_run.py`（录像）

| 参数 | 默认 | 作用 |
|---|---|---|
| `--seed` | 3 | 种子 |
| `--layout` | fixed | `fixed`=SIM_LAYOUT / `random`=`random_layout(seed)` |
| `--out` | `archive/result/rec` | 输出目录（**同一目录会反复覆盖**） |
| `--live` | off | 同时开窗（暂停/单步/退出键生效） |
| `--every N` | 10 | 每 N 帧存一张 PNG |
| `--fps` | 12 | mp4 帧率 |
| `--delay` | 30 | `--live` 时每帧等待 ms |
| `--baseline` | off | 三段式（默认就是它） |
| `--unified` | off | 置 `UNIFIED_NAV_ENABLED=True` + `VIS_ZONE_ENABLED=True` |
| `--no-region` | off | 置 `VIS_ARRIVE_REGION_ENABLED=False`（退回旧的"占比回落"判据） |
| `--tune` | off | 置 `VIS_ZONE_GREEN_TOP=0.0329`、`VIS_ZONE_GREEN_BOT=0.0719`、`VIS_ZONE_BLUE_HEIGHT=0.60`（代码默认 0.0548 / 0.1199 / 0.2445） |
| `--primitives` | **real** | 见 §3：`real`=成对换现场实测原语（**与 `nine_grid_sim` 的默认相反**） |

`Recorder(..., show_detect=True, ...)`：**录像默认叠检出框**（GUI 默认不叠）。

### 6.4 `python tools/ab_ninegrid.py`（多种子 A/B）

| 参数 | 默认 | 作用 |
|---|---|---|
| `--arms A B ...` | `zone_off zone_on` | 见下方臂表 |
| `--seeds S...` | `3 7 11 21 42 100 202 303` | 逐种子跑 `run_simulation` |
| `--layout` | **random** | `random` 时布局随 seed 变 |
| `--primitives` | **nominal** | `real` = 成对注入 §3③（并注入关卡常量） |
| `--deform σ` | 0.0 | 同 CLI：`{σ, sigma_h_cm 0.5, max_tilt 15, max_h 2}` |
| `--json PATH` | 无 | 落盘 `{args, arms, liveness_ok}`（含逐格真值落点） |
| `--set NAME=VALUE[,NAME=VALUE]` | 无 | 内存内改 `levels.nine_grid` 任意模块常量，**自动生成一个新臂**；`true/false` 会被正确解析（防 `bool("False")` 陷阱） |
| `--list` | — | 列出臂（⚠️ 含 `⇒`，GBK 控制台需 `PYTHONUTF8=1`） |

内置臂（`ARMS`）：

| 臂 | 改什么 |
|---|---|
| `zone_off` / `zone_on` | `VIS_ZONE_ENABLED` False / True（后者用代码现值阈值） |
| `zone_near_lo` / `zone_near_hi` | `VIS_ZONE_ROT_NEAR` = 0.0 / 9.0（**活性自检臂**，不是调参） |
| `zone_nohyst` | `VIS_ZONE_HYST_DEG = 0.0` |
| `zone_tail` / `zone_nohyst_tail` | `VIS_ZONE_NO_ROT_TAIL = True`（± 无迟滞） |
| `tail_only` | 二值基线 + 收尾禁转（与分区律解耦的独立变量） |
| `anchor_report` / `anchor_use` | `MAP_ANCHOR_ENABLED=True` + `MAP_ANCHOR_REPORT_ONLY` True / False |

退出码：`0` 正常；**`2` = 有臂被标 `INVALID`**（活性断言失败：两臂逐项相同）。

## 7. 驱动器会临时改写的**关卡侧**常量（都在内存内，跑完还原）

| 常量 | 代码默认 | 被谁改成什么 |
|---|---|---|
| `UNIFIED_NAV_ENABLED` | False | `nine_grid_sim --unified` / `record_run --unified` → True |
| `VIS_ZONE_ENABLED` | **False** | 同上 → True（另有 `ab_ninegrid` 的 zone 臂） |
| `VIS_REANCHOR_BY_ANCHOR` | True | `nine_grid_sim --unified` → True（本已是 True） |
| `VIS_ARRIVE_REGION_ENABLED` | True | `record_run --no-region` → False |
| `VIS_ZONE_GREEN_TOP / _BOT / BLUE_HEIGHT` | 0.0548 / 0.1199 / 0.2445 | `record_run --tune` → 0.0329 / 0.0719 / 0.60 |
| `VIS_ZONE_MOVE_DEG / ROT_DEG / ROT_NEAR` | 6.0 / 12.0 / 0.35 | `ab_ninegrid` zone 臂 |
| `MAP_ANCHOR_ENABLED / REPORT_ONLY` | False / True | `ab_ninegrid` anchor 臂 |
| `ACTION_MODEL` 族 + `FIELD_SMALL_TURN_STEP_DEG*` | 名义值（§3②） | `ab_ninegrid --primitives real` → §3③ |

另有 `--set` 可改**任意** `levels.nine_grid` 模块常量（如 `VIS_ALIGN_TOL_DEG=8.0`、

## 9. 仿真**没有**建模的东西（别把仿真通过当成真机会过）

真机拍照耗时（仿真帧瞬时，`capture_cost_s=0.001`）、舵机到位时间与抖动、
光照/白平衡对 HSV 的影响、相机-机体真实偏移（`CAM_BODY_OFFSET=0`）、
真实打滑分布（仿真只用乘性/截断正态近似）、面板物理尺寸误差、
**机体遮挡与同色杂物**（背景纯灰、颜色=数字唯一 ⇒ 物理上不可能出现两个同色候选）。

最后一条意味着：**"拒绝同色假货 / 身份核验"这类判据在现仿真里无法验证**，
必须靠现场帧回放（`tools/truth_eval.py`、`tools/replay_ninegrid.py`）。
