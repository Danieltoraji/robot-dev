## 1. 前置审计（A/B/C）要点

### 1.1 仿真器（A）
- 投影/裁切/头部/俯仰/形变/打滑**都真实**（`cv2.projectPoints` + 真内参与畸变；
  头部与俯仰真的改变可见集；形变只改世界侧相机位姿，精确复现"常数失配"）。
- **没有同色杂物**（背景恒 91 灰；只画 `layout` 里的面板）；**没有遮挡**
  （面板共面 z=0，无机体几何）。
- **每种颜色每帧至多一个观测**，且颜色=数字=唯一 ⇒ 仿真里"两个同号区块"
  **在物理上不可能**，而"拒绝假货"要判的恰恰是这个。
- 运动原语是**名义常量**（2.0/1.9/2.2/±2.0），与关卡一致，但**不是现场实测值**。
- 结论：仿真能验证**形变免疫**与**几何核验**，**不能**验证假货拒绝。

### 1.2 分区律 A/B 装置（B）
- `tools/_tmp_recalib.py` 的 `zone` 参数是**死参数** ⇒ "49/56 vs 54/56"确系 A/A 对照，作废正确。
- `tools/_tmp_recalib2.py` 与 `_tmp_zone_eval.py` 的 monkeypatch 机制**有效**。
- "四个阈值臂逐位相同"是**真观测**，因为 `'lat'` 只被"算"出来、从未被**执行**：
  全部 'lat' 来自 `_approach_visual:2351`，而它随后调用的 `_align_visual` 在首判据处
  因 `|yaw| ≤ 12°` 立刻返回。
- ⇒ **`e43a803` 只打通了咨询，没打通执行。**

### 1.3 真值集（C）
- `ground_truth.json` 只有 5 条假货，无真面板行、无逐帧分组、**无布局/位姿/相机档位**
  （`grep cell|layout|pose|homograph` 0 命中）。
- 12 帧参与；未裁切观测逐帧为 `[1,1,1,1,1,1,1,2,2,2,2,3]` ⇒ **最多 3 个**。
- 5 个假货**全部 `clip==1`**，且其中 2 条是**同一物理物体的两个颜色窗口**
  ⇒ 实际只有 4 个独立假货、分布在 3/12 帧。
- 结论：**当前真值集不能评测格子核验**；§3.3 给出最小补数据清单。

## 5. 对抗性评审（D）结论（已收到，含**两处对主 agent 的纠正**）
对抗性评审在本文定稿后返回，其结论**部分推翻了主 agent 的两条判断，必须记录**：

### 5.1 ✅ 它证实了主 agent 的到达段诊断，并给出**更根本的变量**

逐帧复现：机器人确实压到格上（seed21-p1 / seed7-p2 / seed11-p5 的真值离格心
0.77 / 3.93 / 0.84cm），而占比谷值/峰值 = **0.571 / 0.608 / 0.551**，判据要 **<0.55**
—— 差 3.7% 与 0.4%，**只差一线**。并补充：
- 峰值总是出现在离格心 **14~19cm** 处 ⇒ **真正的约束是"峰值之后还剩多少前进行程"**，
  也就是 `VIS_ARRIVE_PRESS_MAX_CM`；
- 证据门（0.08）只解释了 14 次拒绝里的 3 次（被拒帧的峰值帧覆盖 0.151，被接受的 0.152）
  ⇒ **不要把失败过度归因到证据门**。
- 直接扫 `VIS_ARRIVE_PRESS_MAX_CM`（冻结 a4408d5）：45→50→**60cm**，
  12 种子×7 格口径 固定布局 **69/84 → 84/84**、随机布局 **61/84 → 81/84**，
  且**拍照反而下降**（3181→2684）⇒ **比 `TAIL_ACCEPT_FRAC=0.80` 更大、更省的杠杆**，
  且没有"5.5~8.8cm 落点从 5 个变 7 个"的代价。

**⇒ 主 agent 已据此重跑对照（16 种子），结论并入 §6.7。**

### 5.0 ★★★ 最终裁决：两条改动**都采纳**，实测原语 16 种子 **112/112**

### 5.2 ❌ 纠正主 agent 关于锚可用率归因的错误

主 agent 曾推断"更近的面板会被检测器 `MAX_AREA_FRAME_FRAC=0.35` 当 `too_big` 整块丢弃"。
对抗性评审逐帧普查后**否证**：`last_rejected` 在 671 帧里**全空**，
未裁切面板被漏检 **0/832（0.00%）**，28cm 面板在 20cm 站位时峰值只占画幅 **0.286**（<0.35）。
**真正的唯一主因是画幅裁切**（面板-帧普查：裁切 68.1%、出画幅 17.7%、相机后方 14.2%）。
另纠正两个数字：20cm 处像宽是 **1074px**（不是 >1600px）；未裁切上限是 **6** 不是 7
（格 6 恒空）。

**⇒ 这条已按实证更正到方案 §1.5。**

### 5.3 ⭕ 主 agent 对 (A) 的复核：评审的结论**部分不成立**

评审称"把 2280 接到 `_zone_of` 不可能得到 `lat`，唯一让它可达的是迟滞"。
**实测否证**：`tools/ab_ninegrid.py --arms zone_off zone_nohyst`（迟滞=0）
在 16 种子里 `_zone_of` 返回 `'lat'` **143 次**，动作流显著改变。
原因是修好之后 `|yaw| ∈ (6°,12°]` 会**落到横移档**（旧代码在首判据就 return 了）——
这正是修复的要点。评审自己的合成测试也复现了这一点（首帧 yaw 8°/11° → `_align_actual` 走横移）。
**但评审有一条成立且重要**：`VIS_ZONE_ROT_DEG == VIS_ALIGN_TOL_DEG == 12.0`
⇒ 蓝档窗口 (6,12] 是旧死区的**子集**，三档律的"旋转档"边界与旧死区重合，
设计上是可疑的；建议把 `VIS_ZONE_ROT_DEG` 移到 18~20° 再测。

### 6.3 `VIS_ZONE_NO_ROT_TAIL` 实证是**恒等操作**（§6.7 的遗留担忧可以结案）

`zone_nohyst_tail` 与 `zone_nohyst` **逐项完全相同**（工具正确报 `INVALID`）。
原因是结构性的，不是噪声：`_approach_visual` 只在 `_zone_of != "move"` 时才可能转向，
而它前面就是 ALIGN 段，|yaw| 已被压进死区（≤12°）；此时
`near ≥ 0.35` ⇒ 分区判据返回 `'lat'`（本就禁转）；`near < 0.35` ⇒ `tail=False`。
⇒ **"收尾禁转"的语义已经被"蓝档 + near 门"覆盖**。另外 `_arrive_visual` 在
`VIS_ARRIVE_LAT_VIA_SIDESTEP=True`（默认）下**根本不转向**。
⇒ 交接文档 §6.7 的遗留要求**在当前架构下已满足**。

### 6.5 ⚠️ 新发现：测试套件对 **CPU 争用**敏感（会假阳性）
评审期间并行跑多种子 A/B 时，`python -m pytest tests/ -q` 用了 **6315s**（正常 291s，
21× 慢），并报出 `tests/test_nine_grid_deform.py::test_baseline_no_deform`
**失败**（`未确认到达的面板: [1]`）；单独重跑该测试 **9s 通过**。

根因：关卡的护栏是**墙钟**判据（`_cell_expired` 用 `time.time()` +
`VIS_CELL_HARD_TIMEOUT_S=70`，每个子循环入口也判 `time.time() > t_end`）。
CPU 被占满时一次搜索的墙钟被拉长 ⇒ 误触单格熔断 ⇒ 本格记未确认。

⇒ **纪律**：`pytest` 与多种子 A/B **绝不能并行跑**；CI 里也应串行。
这条以前没人记过，而它已经足以制造一次"改动把基线打挂了"的假警报。
