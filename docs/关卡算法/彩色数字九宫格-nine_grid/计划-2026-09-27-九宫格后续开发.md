# 计划-2026-09-27：九宫格后续开发（无开关反馈 · 单目相机 · 放弃仿真）

> 用户 2026-09-27 指出的硬约束（本计划的出发点）：
> **"机器人无法判断微动开关是否被压过（仅有一个单目相机）。现有的两个方案都跑不通。"**
>
> 配套约束：放弃仿真器（停用但保留代码与测试）；一切以真机测定为准；
> 助手不得通过 `exec_on_robot` 一类远程执行去驱动动作组（会动机体的实验由用户执行或另行授权）；
> 不同关卡之间的动作可以复用。
>
> 本计划**不是**"选哪条路线"的延续，而是把问题**重新形式化**后的执行方案。

---

## 0. 问题的真正形状

把任务写成一句可验收的话：

> **在 15 分钟内，让机器人的承压部件依次通过格 1..7 的开关位置，横向与纵向偏差都在开关可触发范围内；
> 而"是否通过"这个事实，机器人自己观测不到。**

三个必须分开处理的子问题：

| 子问题 | 现状 | 本计划的攻击点 |
| :--- | :--- | :--- |
| **A 反馈缺失**：压没压到，机器人不知道 | 计分由场地 ESP32 独立完成，Pi 侧读不到 | **§1 L1**：把"不可观测"变成"可观测"或"人类在环可读" |
| **B 落点不可测**：现有判据都是"像不像到了"，不是"差几厘米" | 统一决策用画面份额门（仿真标定）；原版用颜色事件 latch | **§1 L2**：用**已知边长的面板**做单目度量，直接得到"差几厘米" |
| **C 落点不可控**：即使测出来，也压不到 ±t 以内 | 现有落点中位 8.7cm（仿真）、真机未知 | **§1 L3**：视觉度量交棒 + 末端按实测步长单步死推 |

**一句话策略**：**先把 A 打开（哪怕只是让人读计分器），再把 B 做成厘米级可测，最后用 B 闭环压 C。**

> ⚠️ 一个必须先讲清的判断：**在 A 没打开之前，任何"到达判据"的调参都是盲调。**
> 现有两条路线之所以"都跑不通"，很可能不是判据不够精巧，而是**没有一条能知道自己压中了没有**，
> 于是既不能收敛也不能证伪。本计划把 L1 放在最前面，理由在此。

## 0.5 固件已查明的事实（2026-09-27 读 `reference code/九宫格视觉导航/esp32/NineGrid_ScoreSystem/NineGrid_ScoreSystem.ino`，520 行）

> 这一节是**直接读源码**得到的，不是推断。它推翻/修正了本计划初稿里的几处假设。

**F1 触发是"瞬时闭合"就够，不需要持续按压。**
`scanSwitches()` 是主循环里的**电平扫描**（`digitalRead(...) == LOW` 立即返回该槽位），
只有一条 `DEBOUNCE_TIME = 200ms` 的**重复触发屏蔽**（同一开关 200ms 内不重复计数），
**不是"必须按住 200ms"**。主循环 `delay(10)` ⇒ 约 10ms 轮询一次。
⇒ **轮子滚过去只要闭合能被某次 10ms 轮询抓到就算分**——⚠️ **但"10ms 轮询"是理想值**：
OLED 每秒一次 I2C 突发会造出约 0.1s/秒的盲窗（§0.6 修正 3），
所以**可靠接触要 ≥0.5s**。★ 反过来说：**电平触发 ⇒ 停在格心上不动，开关就一直闭着，
与"蹭过去"对计分器完全等价** ⇒ 末端策略可以简化成"**停住**"。

**F2 顺序错了不清零、不锁死，只不计分。**
`processTrigger()`：`if (i == targetIndex && !scored[i])` 才计分；否则打印
`❌ 顺序错误！期望%d, 实际%d` 或 `⚠️ 重复面板%d`，**进度保持不变、没有惩罚、没有重置**。
⇒ **误碰别的开关不会毁掉整局**（只损失约 2 秒冷却，见 F3）。这条大幅降低了"必须一次做对"的压力。

**F3 每个开关有 2000ms 冷却**（`TRIGGER_COOLDOWN`），且**冷却在顺序判断之前就更新**
（`processTrigger` 第 182-187 行）⇒ 一次**顺序错误的触发也会让该格 2 秒内不再响应**。
⇒ 同一格想"再压一次确认"，必须间隔 >2 秒。

**F4 首次触发即开始计时（15 分钟），不论碰的是哪个开关。**
`loop()`：`if (!roundStarted && !roundComplete)` 时任何触发都 `roundStarted = true; startTime = millis()`。
⇒ **入场时蹭到任何开关，计时就开始**，且**人工按一下也算开表**（不能拿它做"不耗时的预演"）。
⇒ 实验协议必须写清：每次实验前**复位 ESP32**，或明确"以开表那一刻为 t0"来统计。

**F5 反馈通道：机器人读不到，但"人"读得到，而且是逐格精确的。**
- **OLED**（`updateDisplay()`）：`Score: N`、`Progress: 1→2→[3]→…`（**当前待打目标带方括号**）、`Time: Ns`。
- **串口 115200**：更详细——`✅ 面板N! +10.0分`、`📊 当前得分`、`🎯 下一个目标：面板N`、
  `❌ 顺序错误！期望N, 实际M`、`⏰ 比赛超时`。
- **WiFi HTTP POST**：`SERVER_URL = "http://192.168.31.254:8001/api/v1/scores"` 是
  **编译期 `const char*`（不是运行期可配置的，见 §0.6 修正 4）**，且 `uploadScoreToServer()`
  **只在 `reportFinalScore()` 里被调用**（第 285 行），即**只在整局结束/超时时上报一次**，
  载荷只有总分（无逐格、无逐开关）。
⇒ **L1 的结论要改写**（见 §1）：电子实时反馈**目前不存在**，但**逐格的人工可读反馈存在且足够精确**；
若想要电子实时反馈，唯一办法是**改固件**（源码在本仓库，可加一行"每次计分都 POST"）——
这是需要用户裁决的硬件/固件改动，不是配置。

**F6 ★ 布局是"人工通过串口输入"给计分器的。**
`readLayoutFromSerial()`（第 465 行）在开机时读入形如 `6,5,4,3,2,1,7,8` 的布局串；
`slotToPanel[slot]` 由此建立，`slotToGrid[8] = {0,1,2,3,4,5,7,8}`、`physicalToSlot[6] = −1`（格 6 恒空）。
⇒ **场地系统本来就知道"哪个数字在哪一格"，只是由人手输进去的。**
⇒ **同一份信息可以同时交给机器人**（人手输一次 / 从串口读一次），
于是 `layout_scan`（在弱光下会 `RuntimeError` 退出、让整局"一格都没走"的那一段）**从必需项变成可选项**。
更重要的用法：知道布局 ⇒ 机器人看到**任意一块面板**就能反推自己在场地的位置
（颜色↔数字固定映射 + 布局表 ⇒ 面板的格坐标已知）。

⚠️ **但"看到两块就能定位"这句话必须加限定条件（评审 C 指出，已数值核实）**：
两块面板的**后方交会**分两种情形，结论完全不同：

| 观测量 | 场地内能复现同样观测的位姿数（1cm 网格，容差 方位角 1° / 距离 1.5cm） |
| :--- | :--- |
| **只用方位角**（面板太远/太斜，L2 的度量被质量门否掉时） | 入口沿列进入（与两板共线）**50 个解、最大差 29cm**；侧向远处 17 个解/16cm；斜对角 12 个解/5cm ⇒ **欠定，不能用** |
| **方位角 + 距离**（L2 的度量估计器给出的地面距离） | 上述所有几何下都是 **2~7 个解、且全部落在 1cm 内** ⇒ **唯一** |

⇒ 规则定死：**两面板定位必须带距离**（即两块面板都要通过 §1 的四边形质量门）；
若只有方位角可用，**必须凑到 ≥3 块不共线面板**才能解位姿。评审 C 的三面板实验也得到唯一解。

⇒ **"上一格跑完时目标常在身后 1~2 格"这个仓库里反复出现的困境，可以不靠视觉搜索解决**：知道自己在哪、知道目标在哪格，直接转过去。
若解不出位姿（面板太少/质量门全否），**退回视觉搜索兜底**（②），不允许用欠定的位姿去决策。
⚠️ 需要确认：布局串的**确切格式与顺序**（例子里第 8 个数是 `8`，但目标序列只有 1..7，需与裁判/场地核对）。

**F7 15 分钟超时是硬终止**：`TIMEOUT_MS = 900000`，超时 ⇒ `timedOut = true; roundComplete = true` ⇒ 只给任务分、不给 +30，并立即上报。

**F8 计分与"是否真的压到开关"完全解耦于机器人**：机器人侧没有任何回读路径
（没有 GPIO 回线、没有串口连接）。这一条**没有因为读到固件而改变**——
变的只是"我们知道该往哪条路上找反馈"。

## 0.6 评审 A 的修正（2026-09-27，对抗性评审，**优先于上文任何冲突处**）

评审 A 读了 `NineGrid_ScoreSystem.ino`、`关卡说明书…docx`（用 stdlib zipfile 解 `word/document.xml`，
644 段 + 5 图）、`reference code/机器人智按按钮/hardware/esp32_score.ino` 与本仓库代码，逐条核对后给出：

### ★★★ 修正 1：**面板尺寸不是 28cm** —— 按 28 来算会把所有米制距离放大 1.29 倍

> ⚠️⚠️ **本条已被评审 B 部分推翻，见下面的"B 的反证"——"28cm 没有实测依据"成立，
> 但"真值就是 21.7cm"不成立，而且现有真机数据倾向支持 28cm。改常数之前必须先量。**

- 说明书**物料表**（段落 244-250）：底板 1m×1m×5mm，**可拆卸面板 = PVC 33cm×33cm×3mm ×9**。
- 评审 A 量了 docx **自带例图** `word/media/image1.jpeg`（564×564）：色块宽 127/123/128px、
  格距（色块中心距）194.0/192.5px ⇒ **色块 / 格距 = 0.652** ⇒ **色块 ≈ 33.33×0.652 = 21.7cm ±5%**；
  纵向独立复算 128/200 = 0.64；白边（≈5.8cm/侧）**属于面板本身**。
- 本仓库 `PANEL_HALF_CM = 14.0`（28cm）的来历：`33.3 − 5.3 ≈ 28` = **只减了一条边的缝**；
  仓库自述也承认是假设（`数字宫格开发实录.md:311,397`、`仿真器参数清单.md:27`）。

**★★ 评审 B 的反证（用真机帧 + 已知内参，独立于 docx 例图）：**

| 检验 | 结果 | 倾向 |
| :--- | :--- | :--- |
| 真机帧里**未裁切面板的像宽中位**（59 个观测） | **930 px**；而 **28cm @40cm 预测 930.8 px** | **支持 28cm** |
| 21.7cm 要在 40cm 处给 930px 就得把面板放到 ~30cm，那时高/宽会是 0.72（28cm 在 40cm 处是 0.70） | 锐度上 28cm 更贴 | **支持 28cm** |
| "所有四边形在地面系下全等且为正方形"的全局拟合 | **S_impl ≈ 29~31cm**（@h=50，正方形度残差最小在 τ≈47°） | **支持 28cm** |

⇒ **裁决**：
- **"28cm 有实测依据"= 已证伪**（血统确实是假设）⇒ **P0.3 必须做**；
- **"真值应为 21.7cm"= 无法证实，且现有真机数据倾向 28cm** ⇒
  🚨 **在 P0.3 量出来之前，绝对不许把常数改成 21.7**——若真值是 28 而代码用 21.7，
  会造成 **9cm 级**的偏差（40cm 处 −9.0cm），比现状更糟。
- 评审 B 的建议（更硬的做法）：**P0.3 顺带摆两块面板在同帧里、卷尺量它们的中心距**
  ⇒ 由"边长 ÷ 中心距"直接得边长，比拿 docx 例图量靠谱一个量级。

### ★★ 修正 2：**±5.5cm 既无依据、又算错** ⇒ §3 的"1.8 倍余量"结论撤回

- `5.5` 的唯一出处是一串自我复制的**代码注释**（源头 `levels/nine_grid_three_stage.py:70`
  「微动开关区≈中心 2/3≈±5.5cm」）；文档侧 `交接报告-2026-09-14.md:56` 自述血统＝「用户+代码注释」。
- 但"中心 2/3"按线性是 **±11.1cm**、按面积是 **±13.6cm**；`33.33/6 = 5.56` 才是 ±5.5（=中心 1/3）。
  **三种读法都不是"2/3"**；而说明书 docx 三处（段落 122/126/149）都写「触发区＝面板中心约 **2/3 面积**」。
- ⇒ 它是**保守但无根据的占位数**，**不能拿它当误差预算的分母**。
- 物理解释的一手线索（评审 A 的推断，说明书未明说）：物料表段落 275-278 有
  **尼龙垫片 3×9×2mm，用途"避免误触微动开关"**，且面板是**磁吸**（段落 271-274）
  ⇒ 很可能是"面板浮搁在开关上方、由垫片留间隙的**大压板**"。
- ⇒ **若触发区真是 ±11~13.6cm，那么现有方案 8.7cm 的中位落点本来就在窗口内**，
  "压不中开关"可能根本不是现有方案跑不通的原因。**这条必须在做任何算法工作之前用实验判死**（见 P0.4'）。

### ★★ 修正 3：**触发不需要按住，但可靠接触要 ≥0.5s；且"停住不动"与"蹭过去"对计分器等价**

- 评审 A 核对：`:154-175` 是**纯电平轮询**，`:50 DEBOUNCE_TIME=200` 实现为 `:162-163` 检出后刷新
  ⇒ 是**重复屏蔽**，不是"必须按住 200ms"（原判读正确）；无 release 判定。
- **但"10ms 轮询"是理想值**：`updateDisplay()`（`:79-115`）是 ~1KB I2C 突发，运行态每秒一次
  （`:506-509`）+ 每次触发后也调（`:244/:252`）⇒ 约 **0.1s/秒的盲窗**（推断，未实测）。
  10ms 接触≈抛硬币；50ms 通常能抓到，但可能整段落进盲窗。
- ⇒ "滚过去就算分"**降级为"接触须 ≥0.5s 才可靠"**。
- ★ **但对 L3 是好消息**：电平触发 ⇒ **停在格心上不动，开关就一直闭着**，
  与"蹭过去"对计分器**完全等价**。⇒ 末端策略可以简单化为**"停住"**，不必依赖滚压时长。

### ★ 修正 4：`SERVER_URL` **不是运行期可配置的**（F5 的"（可配置）"删除）

- `:75` 是**编译期 `const char*`**，全文件无 NVS / Preferences / 串口命令 / mDNS 任何改写路径
  （`:71` 注释原话"请修改为你的实际信息"）。
- 而且**即使改了地址也没用**：唯一调用点 `:285` 在 `reportFinalScore()` 内，
  只在本局完成（`:224/:236`）或超时（`:497`）触发，载荷 `:277-282` 只有
  `module_id/robot_id/device_ip/event="FINISH"/timestamp/penalty/score`
  —— **无逐开关、无逐格、无时间序列**；且 `:315 http.POST` 是阻塞调用，会停摆轮询、吃掉下一格。
- ⇒ **L1-a 的正确形态**：照 `reference code/机器人智按按钮/hardware/esp32_score.ino:12` 的先例
  （`WebServer server(80)`、`:88-92 /score` JSON、`:95-99 /reset`、`:166 loop 里非阻塞 handleClient()`）
  加 WebServer 由 Pi 轮询。**这不是"3 行"，是一次真正的固件改造**（需用户裁决）。

### ★ 修正 5：串口是**更强的**逐格真值通道（L1-b 升级）

- 串口无周期状态流，但**任何一次被接受的闭合都打印一行**：
  `:196 📌卡槽N(位置M)→面板K`、`:207/:209/:211 ✅+10.0分`、`:248 ⚠️重复面板`、
  `:250 ❌顺序错误`、`:256 ⏳非计分面板`。
- ⇒ **"没有这一行"＝"开关没闭合"**。这是**零固件改动的逐格真值通道**，
  而且它回答的不是"计到了没有"，而是**"开关到底闭没闭"**。
- ⇒ 同时救活 P5.1/P5.2 的验收判据（见修正 8）。

### ★★ 修正 6：两条**静默毁批**机制，计划完全没提

1. **布局串手误**：`:361-364` 开机 60s 无输入即用 `DEFAULT_LAYOUT`（`:25 = {6,5,4,7,2,3,1,8}`），
   它与文档例子 `{6,5,4,3,2,1,7,8}` **在槽 3/5/6 三处都不同**（默认把**面板 1 放在槽 6 = 格位 7**）。
   docx 段落 505 自述布局"只能依靠手动输入串口"。
   ⇒ 一次手误 ⇒ **一整批实验的分数意义不明，而 OLED 照常走分、看起来完全正常**。
   ⇒ **实验前必须核对 `printLayout()` 回显**（新增为 P0.5 的硬条文）。
2. **回合结束即永久锁死**：`:189` + `:479`/`:490` 使 7/7 完成或 15 分钟超时后
   **所有开关被忽略，只能复位**；复位后又有 **60s 布局窗口，此期间开关完全不扫描**。
   ⇒ P5 实验必须按"**一次复位 = 一批实验**"排。

### ★ 修正 7：**"顺序断一格后面全丢"是错的** —— 固件允许回头补

- `:247-250` 对重复/乱序**只打印、不计分、无锁**；游标不前进，但**以后补上仍然计分**。
- ⇒ 仓库里"绝不跳格（跳了就全丢）"的说法**过度悲观**：正确表述是
  **"漏了要回头补，不是作废"**；穿别的格心**无害**（只吃该格 2s 冷却）；
  穿"下一格"也不会预先计分（游标未到）。
- ⇒ 策略上多出一个自由度：**卡住时可以先离开去换个视角/换个站位的路径**，再回头补这一格。

### ★ 修正 8：P5.2 的验收判据按原写法不成立，改成"串口有没有那一行"

- 第 2、3 次到达同格 ⇒ 打印 `⚠️ 重复面板`（`:247-248`），**分数不变 ≠ 没压到**；
  2s 冷却内的闭合更是**静默**。
- ⇒ 正确判据：**间隔 >2s，以"串口是否出现该槽位那一行"为"压到了"的正证据**
  （✅得分 / ⚠️重复 / ❌乱序**都证明开关闭合了**；**没有行 = 没压到**）。

### L2 把"到没到"做成厘米级可测（不依赖仿真、不依赖相机高度）

**核心想法**：面板上那块**视觉可分割的色块**是**已知边长的正方形**，相机内参与畸变已知
（`core/camera_config`：fx 1944.9 / fy 1950.1 / cx 1283.1 / cy 983.2，k1 −0.384 / k2 0.285）。
**已知边长的平面目标 = 自带尺度的位姿基准** ⇒ 从一帧里可以解出"面板中心相对相机地面点的
前向 / 横向偏移（cm）"，**而且不需要知道相机离地高度**。

> 🚨 **但边长这个数现在还不准，而且它是支配性误差项**（§0.6 修正 1）：
> 说明书物料表写**面板 = PVC 33cm×33cm**，量它自带例图得 **色块/格距 = 0.652** ⇒ 色块 ≈ **21.7cm**；
> 仓库沿用的 `PANEL_HALF_CM=14.0`（28cm）来自"33.3 减一条缝"，**很可能是错的**。
> 用 28 当尺度会把所有米制距离**放大 1.29 倍**（50cm 处偏 +14.4cm）。
> ⇒ **P0.3（把边长量准到 ±0.5cm）是 L2 的前置条件，不是"顺手核对"。**

#### 🚨🚨 硬规则（评审 B 期中结论，**实现时不许破**）：地面系基向量只能来自**被观测面板的法线**

评审 B 的受控数值实验（合成真值 + IPPE 反解）：

| 地面系的定义方式 | 前向/横向/法向误差 | 对相机高 h、真实俯角 τ 的敏感性 |
| :--- | :--- | :--- |
| 用**观测到的面板平面法线** `n = R@[0,0,1]` | **0.000cm（机器精度）** | **完全无关**（h 取 40/45/51/56/60 结果一模一样） |
| 用**名义俯角常数**（`CAM_PITCH_MOUNT_OFFSET_DEG` → 有效俯角 59.9°） | **−11 ~ −14cm** | **≈0.9cm / 度** |

⇒ 计划里"**不需要知道相机离地高度**"这句**成立，但理由要改写**：
真正被面板消掉的不是 `h`，而是**地面的朝向 τ**。
而本仓库现行代码的默认路径恰恰是**用名义俯角**（`pitch_offset_deg = CAM_PITCH_MOUNT_OFFSET_DEG`）。

⚠️ **若 P1.2 直接用 `core/camera_config` 的常数做机体系换算，L2 会带一个十几厘米的系统偏置，
整个"≤3cm"目标当场作废。**

**⇒ 写死三条**：
1. 地面系基向量（以及"前向/横向"的定义）**只能**由被观测面板的法线导出；
2. **绝不**用脉宽/名义俯角常数做这个换算；
3. 这条要有回归测试钉住（例如：把 `CAM_PITCH_MOUNT_OFFSET_DEG` 改成任意值，输出必须不变）。

另两条同期更正（评审 B，已复算）：

- **四角齐全的窗口是 15.0~70.5cm**（不是我在 §1 写的 12~95cm；>70.5cm 时**远角出画幅上沿**）
  ⇒ 交棒点与"度量段"的可用范围都按这个改。
  ⚠️ 口径必须统一：**"面板中心距"15cm**（四角开始被裁）与 **"可见地面带下沿 3.8cm"**
  （近边出下沿）是**两个不同基准，差 14cm** —— L3 引 3.8cm 是错位的，一律改用面板中心距口径。

#### ★ 数值验证（2026-09-27，本文件作者做的投影实验，**不是真机照片**）

用仓库里的真机内参（fx=fy=1945、cx=1296、cy=972、k1=−0.3844、k2=0.2847）、
假设相机高 51cm、俯角 59.9°、面板 28cm 铺在地面，投影 4 角点 → 加像素噪声 →
`undistortPoints` + `cv2.solvePnP(IPPE)` → 反解。400 次蒙特卡洛。

| 角点噪声 | 地面距离 RMS（15~130cm） | 地面距离 P95 | 相机高度 RMS |
| :--- | :--- | :--- | :--- |
| ±2px | **0.21 ~ 0.53cm** | ≤1.03cm | 0.23 ~ 0.71cm（⚠️ **不可当独立证据，见 B6**） |
| ±5px | **0.52 ~ 1.32cm** | ≤2.57cm | 0.56 ~ 1.78cm（⚠️ 同上） |

> ⚠️ **B6 更正**：上表"相机高度也解到亚厘米"**不能**当作"自标定能力"的独立证据——
> 评审 B 测得高度与距离的误差**相关系数 −0.84~−0.97**，两者是**同一个尺度自由度的两种读法**。

其它结论（都很关键）：

| 场景 | 影响 |
| :--- | :--- |
| 面板**平面内旋转** 0/15/30/45° | **几乎无影响**（RMS 0.284→0.297cm）⇒ 不要求面板正对机器人 |
| **横向偏移** ±14cm | 无影响（RMS 0.26~0.28cm） |
| 面板**翘边/不共面** 0.5° / 2° | 系统偏差 −0.45 / −1.80cm（2° ≈ 一边抬起 1cm，现实里只有几毫米） |
| **面板边长假设差 ±1cm** | 系统偏差与距离成正比：fwd=30cm 时 −1.03cm、fwd=60cm 时 −2.07cm ⇒ **P0.3 必须把边长量到 ±0.5cm 以内**（±0.5cm 时 fwd=30cm 偏差 −0.53cm） |
| **角点是否在画幅内** | fwd≈**12cm 以外**才四角齐全（10cm 时近角出下沿）；**fwd≈95cm 以外出上沿** ⇒ 度量窗口约 **12~95cm**，足够覆盖交棒点 |

⇒ 计划的核心主张**成立**：地面距离的噪声项是**亚厘米到厘米级**，主要误差是**边长假设的系统项**；
而且"不需要先知道相机高度"这一条**更强**——高度本身也被解到亚厘米，
意味着这套估计器可以**自标定**（本仓库长期争论的"+25°/51cm vs +18.5°/56cm"可以就地量出来）。

⚠️ **效力声明**：这是用真机内参做的**投影数值实验**，不是真机照片，也不是本仓库的仿真器。
它验证的是**估计器的条件数/可辨识性**，**不能**替代 P1.3——真实四角提取精度（贴纸边缘发白、畸变、
数字把色块切碎）仍然是未验证项，且很可能是真正的瓶颈。

#### ★★ 真机照片上的四角可提取性（2026-09-27 实测，**这一步就是 P1.3 的第一半**）

在 `tests/fixtures/field_photos/` + `tests/fixtures/nine_grid_truth/` 的 **25 张真机帧**上，
用仓库自己的链路（`normalize_illumination` → `build_color_mask` → 最大外轮廓 →
`approxPolyDP(0.02·peri)`）跑了 237 个候选色块（面积 ≥ `MIN_AREA_WORK`），量"轮廓点到四边形边界的最大偏离"：

| 指标 | 结果（工作分辨率 1296 宽） |
| :--- | :--- |
| 能给出 **4 个顶点** 的候选 | **114 / 237 = 48%**（其余 2/3/5/6/7/8… 顶点，共 123 个） |
| 四顶点候选的**边界偏离** | 中位 **5.2px**、P90 **15.6px**、max 71.2px |
| 归一化（偏离 ÷ 面板边长） | 中位 **2.0%**、P90 5.0%、最差 21% |
| 面积比 轮廓/四边形 | 中位 1.022，但最差 **3.5**（=四点切掉了一大块，典型是**同色物体粘连**） |
| 凸实性 轮廓/凸包 | 中位 0.980，最差 0.520（明显非凸 ⇒ 粘连） |
| 最干净的样本 | 紫/粉面板：偏离 1.7~2.5px、面积比 1.00~1.02 ⇒ **这种质量足够支撑亚厘米度量** |
| 最脏的样本 | 黄 3 例、橙 1 例、粉 2 例：偏离 28~71px、面积比 1.8~3.5（**与仓库文档记录的"木框橙/黄"同色干扰吻合**） |

**⇒ 三条结论，必须写进实现：**

1. **度量估计器本身没问题，瓶颈在四角提取**：干净样本的 2px 偏离 → 亚厘米（对上 §1 的表）；
   中位 5.2px（原生 ~10px）→ 地面距离误差约 **2.6cm**（由 ±5px→1.32cm 外推），**已吃掉大半预算**。
2. **必须加"四边形质量门"**：只有当"4 顶点 ∧ 边界偏离 ≤ 3~4px ∧ 面积比 ∈ [0.97, 1.05] ∧ 凸实性 ≥ 0.95"
   时才采信这次度量；否则**降级**（走近一点重拍 / 换俯仰档 / 用另一条边）。
   —— 宁可"这次不测"，也不能把一个粘连色块的错位当厘米数用。
3. **同色干扰（木框橙/黄）是已知的老问题**，在度量路线里会直接变成**几厘米的系统错位**，
   比在份额判据里更致命。P1 必须把它当作一等公民处理（仓库已有 `DIGIT_EVIDENCE`、
   `MERGE_GAP_FRAC`、形状仲裁等积累，可复用）。

> 复现方式：探针脚本已随本计划落到 `tools/_tmp_panel_quad_probe.py`（离线，不连机器人）。

### L3 把落点压到容差以内（视觉度量 → 末端单步死推）

**两段式**：

1. **度量段**（面板完整可见时）：用 L2 把面板中心解到机体系 cm，边走边复测，直到面板
   开始被画幅裁切（近距可见地面带下沿约 3.8cm@1040，可用两档俯仰延后裁切时刻）。
2. **末端段**（交接后）：用**实测步长**走有限步数。
   实测依据：`go_forward_one_step` 20 步 ×3 组 = 53.5 / 53.0 / 52.6 cm ⇒ **2.652cm/步**，
   组内 ±3σ 仅 0.055cm、组间极差 0.9cm（≈0.045cm/步系统项）⇒ 8 步的累积误差 ~0.4cm 量级。
   ⇒ **末端落点精度主要由"交接时刻的度量精度"决定，而不是由死推决定。**

到达后补一次**越障式蹭步**（`back_one_step` + `go_forward_one_step`，三段式已在真机用过）作为冗余。
（固件 F1 说瞬时闭合即可计分，F3 说同格 2 秒冷却 ⇒ 蹭步要**间隔 >2 秒**做两次才有意义。）

### L4 用"已知布局"替掉最脆弱的一环（来自固件事实 F6）

场地计分器**本来就要求人工把布局串口输进去**（`readLayoutFromSerial`）。同一份信息给机器人：
- **不再需要 `layout_scan`**（它在本仓库的历史是"弱光下参数网格投票不足 ⇒ RuntimeError ⇒ 一格都没走"）；
- 看到**任意一块面板**（颜色↔数字固定映射）就能反推它在场地的格坐标；
- 看到**两块**即可解出机器人自身的位置与航向（2 点刚体拟合 + 地面手性约束消二义）；
- ⇒ **"目标在身后 1~2 格"不再需要靠视觉搜索硬扫**：知道自己在哪、知道目标在哪格，直接转过去。

这条把 L2 的适用域从"目标在视野内"扩展到"目标在场地任何位置"，是**本计划里第二高杠杆的一项**，
而且**完全不需要动作组**（只要一张布局表和几张照片就能离线验证）。

**待确认**：布局串的确切格式与顺序（例 `6,5,4,3,2,1,7,8` 的第 8 个数与"目标序列只有 1..7"的关系），
需要与场地/裁判侧核对（见 P0.1）。

## 1.5 运行期控制架构（每格走一遍，供照着写代码）

```
进入本格 d（顺序计分：d 没计到就绝不进 d+1）
│
├─① 定位（可选，L4）：若视野里有 ≥1 块面板且已知布局
│     → 解出自身位姿；据此算出"该往哪边转多少"（目标在身后也能直接算）
│     若解不出 → 走 ② 的视觉搜索兜底
│
├─② 捕获目标：把头/身体转到目标进入视野（复用现有"头部四档扫 + 侧向记忆逐步转"，
│     它有"每步复测、过冲由下一步吸收"的性质；只是方向可以先用 L4 算出来）
│
├─③ 度量伺服（L2，本计划的核心）：
│     每帧 → 4 角点 → (d_fwd, d_lat, ψ, 协方差)
│     一次决策只下发**一个**原语：
│        |ψ| > ψ_tol            → 转（小转一步，方向由 ψ 定，不用步数规划）
│        |d_lat| > lat_tol      → 横移一步（方向由 d_lat 定）
│        d_fwd > 交棒阈值        → 前进若干步（步数 = f(d_fwd)，但**下一条决策仍要复测**）
│     ⚠️ 这里刻意**不用"算好 N 步一起转"**：本仓库已有教训——步长估计一错就转过头。
│
├─④ 交棒 → 末端（L3）：当四角开始被裁切（约 d_fwd ≤ 15~20cm，见 L2 的可见性窗口）
│     n = round((d_fwd − offset_mech) / 2.652)，走 n 步
│     （n 很小，通常 0~6 步；误差 ~0.4cm 量级）
│
├─⑤ 压过确认（蹭步）：先等 >2 秒（避开固件 F3 的同格 2000ms 冷却），
│     back_one_step → go_forward_one_step，让承压部件再走一遍格心
│
└─⑥ 留档：把"度量估计的落点偏差(cm) + OLED/串口读数 + 本格拍照数/动作数"打进日志
      （注意：**日志里不许出现无条件的"到达 ✓"**——那是自我安慰，本仓库已经吃过这个亏）
```

三条纪律（写代码时别破）：

1. **一次决策一个原语**，每步复测（过冲由下一步吸收）；
2. **判据必须是厘米数或明确的物理量**，不许再出现"像不像到了"的合成门；
3. **每一步都留"我离格心多远"的估计**，即使没压中也能复盘差在哪。

## 3. 误差预算（先写下来，再逐项用实验替换）

| 环节 | 数值 | 来源/状态 |
| :--- | :--- | :--- |
| **色块边长真值** | **21.7cm 或 28cm（相差 29%！）** | 🚨 **未实测**；docx 物料表(33cm 面板) + 自带例图(色块/格距=0.652) 支持 21.7cm；仓库沿用 28cm ⇒ **P0.3 必须先做**，否则整张表都是错的比例尺 |
| 度量估计（噪声项）@15~95cm | ±2px→RMS 0.53cm｜±5px→RMS 1.32cm | 数值实验（§1 L2；**只证明条件数，尺度是外部输入**） |
| 度量估计（**边长系统项，支配项**） | 边长差 1cm → 30cm 处 1.03cm、60cm 处 2.07cm（线性） | 数值实验；**若真值差 −6.3cm ⇒ 30cm 处 −6.8cm、60cm 处 −13.5cm** |
| 度量估计（翘边系统项） | 0.5° → 0.45cm | 数值实验 |
| 真实四角提取精度 | 中位偏离 **5.2px**、P90 15.6px（工作分辨率）；48% 候选能给 4 点 | ✅ **真机照片实测**（§1 L2 第二张表）⇒ 原生 ~10px ⇒ 约 2.6cm |
| 每次前进步长 | 2.652cm | 真机实测（20 步×3 组）；**但标定表面是否有缝/高差未记录**（§0.6 修正 11） |
| 末端 n=8 步累积 | ~0.36cm（系统）+ ~0.05cm（随机） | 由上一行推算 |
| 机械偏置 `offset_mech` | 目标 ≤1.0cm | ⏳ 待 P0.4'-C 组实测 |
| 打滑/形变的额外项 | ±? | ⏳ 待实测 |
| **开关触发容差 `t`** | **±5.5 / ±11.1 / ±13.6cm 三个候选，全部无依据** | 🚨 **撤回原"合计 ≤3cm、留 1.8 倍余量"的结论**（那是拿一个无根据的数当分母的循环论证）⇒ **P0.4' 实测** |

**★ 预算必须按方向拆开（评审 C 指出）**：开关是 **6×6×5mm** 的器件，
真正卡人的是**横向**精度（轮子/承压面要盖住它），而**纵向只要"走够远、跨过那条线"**即可
（多走 3cm 不影响计分）。所以：

- **横向预算** = 度量横向误差 + 横移步长误差 + 机械偏置的横向分量 ⇒ **这是主战场**；
- **纵向预算** = 只要保证"能跨过并有 ≥0.5s 接触"即可，可以刻意多走一点；
- 而"停在格心上不动"因电平触发（§0.6 修正 3）成为**纵向最稳的做法**。

⚠️ 这张表里**只有"步长"和"四角提取质量"两行是真机实测过的**。
其余都要在 P0.3 / P0.4' / P1.3 / P2.3 里换成实测值；**在此之前不许拿它当结论**。

⚠️ 这张表里**只有"步长"一行是真机实测过的**。其余都要在 P0~P3 里换成实测值；
在此之前不许拿它当结论。

## 6. 明确不做的事

- 不再用仿真结论做任何验收（仿真代码保留，仅作历史资产）。
- 不再争论"哪条既有路线更好"——两条都缺 A（反馈）与 B（厘米级落点），
  本计划直接补这两块，既有代码只在**观测层**（统一决策的比例不变量、面板检测器）与
  **动作原语实测值**上被复用。
- 不做"全程只用颜色事件 latch"的到达判据（无检验的序贯判决，虚警率随帧数累积）。
