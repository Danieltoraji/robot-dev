## 2.5 纯算法层面的正面对比（用户口径：不看标定、不看证据来源）

> 本节把标定、证据血统、真机记录**全部放到一边**，只比较算法本身。这是用户 2026-09-27 指定的判据。

### 2.5.1 两者在控制论上的定位根本不同

| | `nine_grid_original` | `nine_grid`（统一决策） |
| :--- | :--- | :--- |
| **问题形式化** | **事件检测**：目标是否已从视野近端消失（= 已经从身下通过） | **位置伺服**：我是否已抵达目标附近 |
| **控制律** | **分段比例**：`n = int(\|yaw\| / 步长在线估计)` 批量转；框宽驱动前进 | **分段常值（bang-bang）**：判档 → 固定原语，一次一个 |
| **终止条件** | 状态机的**事件**（颜色进入 → 离开） | 单帧六条画面量**合取（AND）** |
| **观测量** | 几何量：`yaw`（角）、目标框宽（尺度） | **比例不变量**：目标色占全帧的份额、目标在画幅中的相对位置 |
| **记忆** | 有（`seen_color` latch） | 无（纯状态反馈，可单帧断言） |
| **在线自适应** | 有（小转角 EMA α=0.3 在线辨识） | 无（也不需要——它不规划步数） |
| **动作空间** | 转 / 前进 / 后退（**无横移**） | 转 / 前进 / 后退 / **横移** |
| **失效结构** | latch 是"或"运算 ⇒ 虚警率随帧数**单调升向 1**；框宽在近距裁切后**不再单调**；模式切换硬阈值无迟滞 ⇒ 抖动 | 六门 AND ⇒ **精度高、召回低**（"永不成立"的概率随门数上升）；无记忆 ⇒ 用不上"刚看到过它"这条最强证据；单档取景 ⇒ 存在**观测不可达状态**而策略无定义 |

### 2.5.2 三条实质判断

**① 问题形式化：事件 > 位置（原版这一半更对）。**

任务的成功条件是**事件**（微动开关被压过），不是位置。判据写成"离格心 ≤ d\*"，
就把任务误差与**距离标定误差**绑死；写成"目标已从身下通过"，误差主要来自
**机器人自身几何**（相机离地、近端可见地面界、相机-轮距），那是机械常数而非位姿相关量。

更关键的是**作用域宽度**（判据翻转发生在多宽的位移区间内）：

- **事件判据**：翻转发生在"面板从画面近端离开"的整个过程里，这段过程跨越**整个面板长度 28cm**；
- **阈值判据**：翻转宽度只由噪声与标定误差决定（`紫份额 = 0.35` 那条线的穿越宽度）。

相对 ±5.5cm 的开关容差，前者天然宽 2~5 倍。真机 trace 可以印证事件判据的翻转宽度：
三段式面板 6 的序列 `0.1556 → 0.1349 → 0.1222 → 0.1050 → 0.0935 → 0.0788`，
相对门（峰值×0.55 = 0.0856）在最后一步被穿过 ⇒ **翻转宽度 ≈ 1 个步长（2.65cm）**，
而峰值到翻转跨了 5 步 ≈ 13cm。也就是说：事件判据既不"尖锐到怕噪声"，也不"钝到错过窗口"。

**② 观测量：比例不变量 > 几何量（统一决策这一半更对）。**

统一决策的全部判据都是"占总量的份额 / 占画幅的比例"。相机内外参、安装俯仰、机体倾斜、
镜头畸变、甚至面板尺寸误差，**只改变像素的分布，不改变份额** ⇒ 判据对这些量**结构上免疫**。
这是一个很强的算法性质，原版完全没有：它的 `yaw` 依赖线性增益（真实 FOV 67.4° vs 按 60° 折算），
它的框宽作为距离代理在近距因画幅裁切而**反向塌陷**（实测同一格 1164→676px）。
**两个观测量的适用域都没有任何保护**。

**③ 记忆：问题不是"要不要记忆"，而是"记忆必须带假设检验"。**

- 原版的 latch = **无检验的序贯判决**：任一帧误判"看到颜色"即永久锁死（"或"运算把虚警概率推向 1）。
- 统一决策的**完全无记忆**是另一个极端：它主动放弃了"我刚看到过它、现在它不见了"这条**最强证据**。
- 正确形态在两者之间：**带前提的序贯判决**——先要求"确实看到过足够大的目标"（峰值门），
  再要求"相对峰值显著回落"（相对门），并要求"回落成因是它从画面近端离开"（方向校验）。
  这既保留事件语义，又消掉虚警累积。**三段式的"峰值→回落"正是它的第一近似。**

### 2.5.3 结论：最优形态是"各取一半"，而且移植成本**不对称**

**取原版的问题形式化（事件终止）+ 统一决策的观测层（比例不变量）+ 统一决策的无模式分区控制律（稳、无需步长估计）。**

具体判据（可直接实现，参数只有两个）：

1. 维持**峰值跟踪器** `peak = max(peak, whole_t)`，且**只在"目标居中且在走廊内"时更新**
   （避免斜切片的残缺投影污染峰值——这正是统一决策历史上被骗门的机制之一）；
2. **事件成立** ⇔
   `seen_big`（曾经 `whole ≥ θ_peak`）
   ∧ `whole_t ≤ ρ · peak`（相对回落，ρ≈0.5）
   ∧ **方向校验**（目标观测底部已贴近画幅下沿 / 质心持续下移）
   ∧ 自峰值以来**至少前进过一次**（排除"原地转身导致颜色消失"）；
3. 到达后仍可补一次蹭步（`back_one_step` + `go_forward_one_step`）作双保险。
   （真机 trace 里三段式就是这么收尾的，代价 2 个动作。）

**为什么方向是"往统一决策里加"而不是"往原版里加"**：`nine_grid` 每帧算出来的 `whole`
（目标色像素 ÷ 全帧像素）与原版 `vision.identify_color()` 返回的 `ratio`
**是完全同一个量**，而且每帧已经现成算好了；加上峰值跟踪器大约 20 行。
反过来，把"比例不变量观测"移植进原版，要重写它整条视觉与判据链（两套 HSV + 框宽门 + 判据重标）。

> 这也顺带解释了一个现象：**三段式是唯一真机跑通的**，因为它的到达判决（相对峰值-回落）
> 本来就是**事件语义**；它只是没享受统一决策那套比例不变量观测。
> 而统一决策这一轮把控制律与观测层做对了，却在**终止条件**上退回了"位置伺服"。
> 两条路线的优点从来没在同一份代码里出现过。

## 3. 三个决定性差异（带证据）

### 3.1 到达判据 vs 计分事件：只有原版"押在计分点上"

计分由场地 ESP32 读 **8 个 6×6×5mm 微动开关**，机器人必须**按 1→7 顺序压过格心**；顺序断一格，后面 70 分全不算。

- 微动开关有效区：**±5.5cm**（`levels/nine_grid_three_stage.py:1022-1024` 的注释与警告门）。
- 统一决策的到达点（代码注释 `levels/nine_grid.py:168-173` 自述）：
  `ZONE_PURPLE_HEIGHT=0.31` ⇒ 紫区只覆盖画幅底边上方约 **8cm** 地面 ⇒ 紫门 0.35
  "大约要走到**离格心 ~8cm** 才成立"。
- 仿真口径的落点分布（8 种子）：中位 **8.7cm**、最大 10.1cm、**≤5.5cm 只有 3/46~4/48**
  （`需求规格-2026-09-25-统一决策重写.md` §9.3/§9.4）。
- 而且统一决策**到达前不做蹭步**（`back_one_step`+`go_forward_one_step`），
  文档原话："**所以微动开关不一定触发**……**上现场先用 `python main.py nine_grid_three_stage`**"
  （`levels/nine_grid.py:35-38`、`代码结构与入口.md` §8）。

⇒ 统一决策存在一个**静默归零**的失败模式：视觉上 7/7 走完，开关一个没压到，**70 分全丢**。
原版的 `arrived()` 判据（颜色出现→消失）**按定义**意味着"面板已从画幅近端退出"，即机器人已经开过它。

### 3.3 证据血统：按"放弃仿真器"的新规则，两边的账不一样

> 真机实测代价极低）。**算法层面的判断以 §2.5 为准**，本节只用于回答"要动手标定的话，
> 哪些数字还能用、哪些必须重测"。也就是说：这一节不再作为"选哪条算法"的依据。

| | 到达判据的标定来源 | 新规则下的效力 |
| :--- | :--- | :--- |

## 4. 各自的结构性弱点（不粉饰）

### 4.1 `nine_grid_original`

1. **A 组常量全部未按本机器人/本场地重标**（`参考原版通关代码-nine_grid_original.md` §4 列了 10+ 项）：
   俯仰档（`LOOK_FORWARD_PULSE=1200` 原版自己就写 TODO）、`LOOK_DOWN_PULSE=1000`（vs 本机 1040，差 3.6°）、
   框宽门 450px@1280×980、7 组色占比门、**两套独立的 HSV 表**、`MIN/MAX_AREA=15000/500000`、`CAMERA_FOV=60`。
2. **历史 latch 的假到达风险**：`seen_color` 一旦置位，**任何一次**颜色丢失（遮挡、反光、邻格同色）
   就判"已压过该格"→ 提前转下一格 → 顺序计分下**直接断链**。
   本仓库有活生生的同源先例：三段式的"峰值→回落"曾在形变场景里**在离格心 89.5cm 处**判 ✓（峰值仅 0.042）。
   ⚠️ 反过来也是风险：颜色**不消失**就一直往前开。
3. **搜索是单向左大转**：20 步 ×44° ≈ 880°（覆盖够，但慢：每步 2 帧 + 1 动作 + `sleep(0.5)`），
   且没有"上次在哪一侧"的记忆、没有头部扫。
4. **卡滞脱困会调用 `climb_stairs`**：⚠️ **本节理由已按用户澄清修正**——
   用户 2026-09-27 明确"**不同关卡之间的动作可以复用**"，因此"它是楼梯关卡的动作"**不构成反对理由**，
   本条不再作为算法或复用性上的缺陷。剩下的只有一条**独立的安全理由**（与算法无关）：
   本仓库九宫格的动作白名单把小步幅以外的动作挡在门外，理由是"5cm 步幅在 33cm 小面板 + 打滑地板上容易摔倒"
   （`levels/nine_grid_shared.py:120-123`），`tests/test_nine_grid_sim.py:39` 把 `climb_stairs`
   与 `go_forward`/`go_forward_fast` 并列钉住这条。它是**可以按需重新裁决的工程策略**：
   若现场确认安全，把它加回白名单即可（届时 `over_hurdle()` 不再有任何障碍）。
5. **零复用、零测试网**：自带视觉/动作/分类，不享受 shared 底座的护栏、遥测、调试镜像；
   目录里只有一个 19 项的回归测试文件。
6. **一次"真机"痕迹是空跑**：`archive/result/real_trace_20260926_111950.txt` 只有 5 行、
   `动作次数: 0, 定位次数: 0`。"真机日志将写入 `F:\coding\...`"说明它其实是在 **PC 上**跑的，
   在 `action.init_servo()` 处因无硬件而终止（本机核实：`core.robot_core.AGC/ctl/board 全为 None`）。
   **这不是真机记录，别当成"跑过了"。**

### 4.2 `nine_grid`（统一决策）

1. **到达判据不压格心**（§3.1）——这是最致命的一条，且**不是调参能解决**，缺的是"最后一环"。

## 6. 裁决建议

### 6.1 算法层面：选原版；代码层面：别用原版当底座

- **"到达 = 压过格心"和"导航档/检测档两档取景"这两件事，是原版对统一决策的实质优势**，
  而且它们正好各自对应统一决策的两个已量化缺口（§3.1、§3.2）。
- 但把原版那 2480 行当底座，等于放弃本仓库的动作白名单、遥测、调试镜像、
  真机实测位移常量，还要重标两套 HSV —— 收益与代价不成比例。
- ⇒ **推荐落法：把原版的"到达语义 + 两档取景"落到本仓库底座上。**
  本仓库里最接近这个组合、且**唯一有真机 7/7** 的是 `nine_grid_three_stage`（峰值→回落 + 蹭步 + 两档）。
  若限定必须在 `nine_grid` 与 `nine_grid_original` 二者中选**代码**底座，则选 **`nine_grid`**，
  但要移植原版的到达语义（等于把三段式的到达段搬进统一循环）。

### 6.2 但在动代码之前，先做一次零风险的真机照片复盘（不需要动作组）

**语料（都已入库 Git，不依赖 archive/）**：

| 目录 | 数量 | 内容 | 真值 |
| :--- | :--- | :--- | :--- |
| `tests/fixtures/field_photos/` | 26 jpg（25×2592×1944） | `photo_1789022*` 10 张（09-10，布局扫整轮）、`probe_a/b/c` 3 张（09-11/12，暖偏色等恶劣光照）、`field_1789281*_<pitch>_<head>` 12 张（09-13，**文件名自带真值云台档位**）、1 张调试拼图 | 布局归属真值硬编码在 `tools/replay_ninegrid.py:48` 的 `PHOTO_TRUTH` |
| `tests/fixtures/nine_grid_truth/` | 21 jpg（20×2592×1944） | 09-21~23 的现场帧 | **有独立真值**：`truth.json` 73 条**观测级**标注 = 68 真 / 5 假；`ground_truth.json` 记 5 条假货 |

**现状：`tools/replay_ninegrid.py` 只能验"布局扫"这一段，且有两个已知折扣**
（实测 `--expect` 退出码 0、2.7s；`pytest tests/test_nine_grid_replay.py -q` → 2 passed in 4.08s）：

1. `find_photos()` 的 glob 只吃 `photo_1789022*.jpg`（`:64`）⇒ **文件名自带真值档位的 12 张 `field_*.jpg` 永远不会被用到**，
   而照片→(俯仰,头部) 的映射目前是"**用户 2026-09-11 表示未确认**"的假设值（`:19-21`）。
   ⇒ 改成用 `field_*` 的文件名读真值档位，是**成本最低、收益最直接**的一处加固。
2. `layout_scan` 有提前退出判据（未裁切覆盖 ≥6 个数字且两档俯仰都有观测）⇒ **10 张里实际只用掉 6 帧**。
   宣传"10 张语料"时要打折。
3. 语料是**单一静止机位、多档云台**，**没有距离/位移维度** ⇒ 框宽↔距离、色占比↔距离这两条**必须新拍**（见 M3/M4）。

**⚠️ 边界（重要，别高估）：离线照片只能验"感知与单帧决策"，不能验"整局闭环"。**
两条路线的循环都靠"做动作 → 产生新视角 → 再判"推进，静止照片下"前进一步"没有新视角，
以框宽/占比为条件的循环体会原地空转（`tools/replay_ninegrid.py:95-96` 自己就写明了这一点）。
所以：

| 能离线验（有真机照片就够） | 只能真机验（需要动作组授权） |
| :--- | :--- |
| 颜色窗口能不能找到面板、候选框/数字认对没有 | 走位、转位、搜索策略是否收敛 |
| 单帧判据（分档、到达六量、`identify` 的 yaw/框宽）取值分布 | 微动开关到底压没压到 |
| 布局归属、自标定、位姿自举（这三项**现在就能跑**） | 打滑/形变的真实幅度 |

**待做的第一步（纯 PC、不连机器人、不需要任何授权）——"真机帧上的视觉链 A/B"**

不要试图去驱动 `nine_grid_original.run_level`（它第 2 句就是 `action.init_servo()`，
在 PC 上必抛 `RuntimeError`；而且它靠"框宽达 450px"驱动循环，静止照片会死循环——
**这是物理性障碍，不是接线问题**）。正确做法是**只调它的纯视觉函数**：

```python
# 伪代码：零改动、零硬件、纯函数调用
import cv2
from levels.nine_grid_original import vision, classifier
img = cv2.resize(cv2.imread(照片), vision.CAPTURE_RESIZE, interpolation=cv2.INTER_AREA)  # 必须先缩放
cands = classifier.classify_candidates(img, topk=5)      # → color/model/hole/final_digit/final_score
ok, yaw, box_w = vision.identify(digit, img)             # 原版所有判据的入口
ratio = vision.identify_color(vision.id_to_color(digit), img)
```

三个要回答的问题：

1. 参考队那两套 **HSV 窗口在本场地的贴纸/灯光下还成不成立**？
   （`tests/fixtures/nine_grid_truth/truth.json` 的 73 条观测级真值可以直接算**候选提取的查准/查全**，
   与统一决策的 `detect_panels` 在同一批帧上做 A/B。）
2. `final_digit` 与人工读图真值一致几次？（这一步不过，原版后面所有判据全免谈。）
3. `identify_color()` 在真机帧上的量级是多少？—— 它是 `COLOR_THRESHOLD` / `COLOR_LOST_THRESHOLD`
   的**唯一入口量**，据此可以开始标候选值（不用仿真、不用动作组）。

这一步的产出直接决定 §7 的第 1 项怎么选：**若原版的视觉链在本场地站得住，
"算法取原版"就从纸面判断变成有真机帧支撑的判断；若站不住，那它也必须换视觉链，
选择就退化为"在 nine_grid 底座上补到达语义"。**
