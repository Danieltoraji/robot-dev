## 1. 一句话现状

数字宫格现在有**两套并存的实现**，各占一个模块，共用一套感知与预算机制：

| 模块 | 是什么 | 行数 | 谁在用 |
|---|---|---|---|
| `levels/nine_grid_shared.py` | 两套共用的机制：拍照与量测、布局扫描、投影、位置核对、单格预算与熔断、运动原语 | ~1815 | 下面两个模块都继承 `NineGridShared` |
| `levels/nine_grid.py` | **统一决策**（三档分区 ＋ 一个循环）：默认算法 | ~845 | `python main.py nine_grid`、仿真不加参数时 |
| `levels/nine_grid_three_stage.py` | **三段式**（搜索 → 对准 → 接近 → 到达）：现场发货、跑通过的稳定版 | ~1075 | `python main.py nine_grid_three_stage`、仿真加 `--three-stage` |

两套办法的差别只有一句：**决策那一步怎么算**。感知、预算、护栏、投影、

## 2. 统一决策（`levels/nine_grid.py`）

一格的主流程（`NineGridLevel.go_to_panel` → `_drive_to_panel`）：

```
每格开始：时间预算 + 拍照/动作上限；取景档固定低头档
循环（上限 UNIFIED_MAX_STEPS）：
    1. 拍一帧，整帧按颜色分成三档区域 → 紫/橙/左右不对称三个份额
       （同时拿一次完整面板检测：既取目标色，也给"位姿反推"用）
    2. 目标在画面哪一档？→ forward（绿·直行）/ side（蓝·横移）/ turn（橙·旋转）
       —— 判档纯像素，yaw 只当伺服增益，不参与规划
    3. 到达判据（**只看当前这一帧，且全部是画面量**，全过才算到）：
         目标居中 ≤ ARRIVE_CENTER_MAX
         目标够大 ≥ ARRIVE_MIN_TARGET_COVER
         形状不扁（宽/高 ≤ ARRIVE_MAX_WIDTH_HEIGHT_RATIO）
         紫区 ≥ ARRIVE_PURPLE_MIN、橙区 ≤ ARRIVE_ORANGE_MAX、
         左右不对称 ≤ ARRIVE_ASYMMETRY_MAX
         （代码形态：`_arrive_pixels_ok()` —— **不许读 `self.pose`**）
    4. 到了 → `_reanchor_pose`：用视觉+地图反推实测位姿（解不出退回格心+原航向）
    5. 没到 → 按档下发**一个**原语（恒为 1 个，从不批量转）
目标丢了 → `_find_target_again`：按上次看到它的一侧逐步转、每步复测（纯视觉）
这一次尝试没磨下来 → 回 run_level，**换搜索方向重试同一格**（见 §5）
```

关键纪律（改代码时别破）：

- **一次决策一个原语**：不做"算好 6 步一起转"。
- **不用推算位姿做决策**：`self.pose` 既不参与"往哪边找"（2026-09-25 起改纯视觉），
  也不参与"到了没有"（2026-09-26 短路，见下）。还在读它的只有两处：
  `_arena_guard`（离场围栏，**待决策**）与 `_reanchor_pose`（到达后**重写**位姿）。
- **到达判据不含历史**：全是当前帧的状态量，所以原地转身、偏头、遮挡都不会误判。
- **到达判决不含位姿**（2026-09-26）：曾经还有一道"格的同一性核验"（锚解实测位姿
  距目标格心 ≤16.7cm 才放行）。实测它会拿**不可信**的位姿否决**正确**到达
  （面板 5 连试三次才认；形变场景位姿漂 105cm 而真值离格心只有 13cm），已摘掉
  否决权。锚测量保留为 `ARRIVE_ON_CELL_PROBE` 的**纯诊断探针**：只在"画面说到了、
  地图说不在"时打一行 `[核验] …仅记录，**不否决**`，不改变控制流。
  ⚠️ 恢复否决 = 回滚该次提交，不是加个 `if`；`tests/test_nine_grid_arrive_shorts.py`
  用 AST 钉住"废弃开关在代码里零引用"。
- **过冲由下一帧闭环吸收**：不追求一次转到位。
- **绝不跳格**（见 §5）：一格没确认就一直磨这一格。

判据的代码形态（2026-09-25）：分区几何是 `levels/nine_grid.py` 的**模块级纯函数**
—— `zone_at_pixel`（逐点判档）、`zone_masks`（四块掩膜；类方法只是带缓存的包装）、
`zone_lines`（分割线，归一化画幅坐标）。三者共用同一组"半边宽度"公式，所以
**画出来的线就是判据的边界**（tests/test_nine_grid_zone_px.py 逐段钉住）；调试镜像
的「分区判据」图层（网页勾选框，默认勾上）直接复用它们，不另抄几何。⚠️ 这些函数在
**调用时读模块全局常量**，`tools/record_run.py --tune` 与若干测试靠运行时改
`ZONE_*` 改参，别改成 import 期捕获/默认参数（那会让改参静默失效）。

## 3. 三段式（`levels/nine_grid_three_stage.py`）

一格的主流程（`NineGridThreeStageLevel.go_to_panel` → `_drive_to_panel`）：

```
搜索 `_search_target`：导航档 + 头部五档扫 + 盲走
对准 `_turn_to_face_target`：可见目标时按 yaw 转向（批量小转，带在线步长估计）
接近 `_walk_closer`：按框宽/色占比分档前压，顺带厘米级横移纠偏
到达 `_walk_until_underfoot`：整帧色占比"出现→回落"判到位，前压兜底
确认 `_press_switch`：蹭步（后退 3.2cm + 前进 2.0cm）压过格心，确认微动开关
```

它的到达判据用的是**整帧色占比的峰值与回落**，与统一决策的"四量同帧"完全不同；
两条死推算判据（`ARRIVE_STOP_FORWARD_CM` / `ARRIVE_FALLBACK_CM`）保留为
"视觉全盲时的最后手段"，命中情况进遥测（`_note_dead_reckoning_hit`）。

## 5. 顺序计分 ⇒ 绝不跳格、绝不因耗时放弃（2026-09-25 的策略）

本关按 1→7 **依次到位**计分：顺序断一格，后面的分全都不算。所以：

| 规矩 | 现在的做法 | 旧做法（已取消） |
|---|---|---|
| 一格没确认 | **一直磨这一格**：`run_level` 反复调 `go_to_panel(digit, attempt)`，attempt 递增 | 记未确认 → 接着做下一格（顺序断了 ⇒ 后面全丢） |
| 单格时间 | 只提醒（`CELL_TIME_REFERENCE_S = 70s`） | 70s 硬熔断（还按剩余时间自适应收缩） |
| 整局时间 | 只提醒（`TOTAL_TIME_REFERENCE_S = 780s`） | 13 分钟看门狗，超了整局停 |
| 拍照数 / 动作数 | 只遥测 + 每 30 张报一次进度 | 140 张 / 300 次的硬上限 |
| 单格转向预算 | 转满 360° 就**换办法重试本格**（`_give_up_attempt`） | 拒绝转向 + 熔断本格 |
| 打转判据 | 同上（第 3 次触发 → 换办法） | 熔断本格 |
| 能自己停下来的 | **只有离场护栏**（位姿越出场地外框 ±1 格 ⇒ 整局收手，保已得分） | 上述任意一条 |

重试时子类换什么：统一决策**换搜索方向**（奇偶次反向，`_drive_to_panel` 里读
`attempt`）；三段式沿用原有的 `RETRY_LIMIT` 轮次 + 后退一步。

仿真侧另有一条**保险丝**（`SIM_FUSE_CAPTURES/ACTIONS`，默认 3000）：关卡既然
不再自己放弃，仿真就必须自己刹车，否则一次"磨不下来"的实验会跑到天荒地老。
它是**仿真器的保护，不是关卡策略**——真机上这个角色由人来扮演（Ctrl-C）。

## 5b. 到达判决与位姿解耦：短路"格的同一性核验"（2026-09-26）

**决定**：到达判决**只吃画面量**（居中/够大/形状/紫/橙/不对称，代码形态
`_arrive_pixels_ok()`）；地图锚解出的位姿**不参与"到没到"**。

**为什么**：那道核验（`_verify_target_cell`：锚解实测位姿距目标格心 ≤16.7cm 才放行）
实测会用**不可信**的位姿否决**正确**到达：

- 面板 5 连试三次才认到达；
- 形变场景里位姿漂 **105cm** 而真值离格心只有 **13cm**（仓库早就写明
  "不要用位姿去否决到达"，见 `tools/diag_arrive.py` 与 09-13 交接文档）。

**代价（如实记）**：这道核验原本替"尺度门 + 形状门"兜住"站在别处、画面里却是一整块
又大又居中的目标色"这一类假到达。历史实测：只留尺度/形状门时出现过 27/28 但
**2 次超半格、最大 75.5cm 落点**。所以本次改动**必须**看
`tests/test_nine_grid_deform.py` 的真值落点门（≤16.667cm）与
`tools/diag_arrive.py` 的"跨格级假到达必须 0"。

**保留了什么**：锚测量降级为**纯诊断探针** `ARRIVE_ON_CELL_PROBE`（默认开）——
只在"画面判到达、地图说不在"时打一行
`[核验] 面板N 画面判到达，但地图锚认为不在目标格（…）——仅记录，**不否决**`，
用于事后统计"这道核验本来会否决几次"。到达后的 `_reanchor_pose` 不受影响，
照旧跑一次锚并把位置与航向都换成实测值。

**实测（2026-09-26，固定布局 seed 3）**：`7/7、拍照 484、动作 422`，
逐格真值落点 6.7~10.3cm（全在半格内），**探针一次都没报分歧**（7 次到达全部
"unknown（锚不可用）"或 "yes"）。⇒ 这条路径上"核验"本来就没起作用，
短路没有改变这次的结果；真正的收益是**去掉了"锚一旦解出来就可能误杀正确到达"
这个隐患**。同一局里面板 5 仍然磨了 3 次，原因**不是**到达判据，而是
`TURN_BUDGET_DEG=360`：第一次尝试 359°、第二次 354° 各转满一圈仍没扫到目标
（`[尝试] 单格累计命令转角 … 超参考上限 360°`），第三次换方向才找到。
**要不要动那个预算，是另一个决策**（不在本次范围内）。

**已知空档（本次未修，必须知道）**：随机布局 + 多种子跑
`tools/ab_ninegrid.py --variants unified --seeds 3 7 11 21 --layout random --primitives real`
时出现 **1/22 次跨格级假到达（落点 132.1cm，seed 7 的面板 1）**。已用对照实验定性：
把到达门换成"恒 True"⇒ 22 格全部假到达（说明画面量门确实在干活）；把旧否决权
**在内存里还原**（画面量 ∧ 锚不否决）⇒ 结果与现状**逐格完全相同**（同为
`{1: 11}` 次尝试、同为 132.1cm）——因为那一刻锚是"unknown"，旧代码也拦不住。
⇒ 这是**既有空档**（`实现档案` 记的"锚可用率 ~16% 导致核验形同虚设"），
不是本次短路引入的。现有 `tests/` 只跑固定布局，所以随机布局这条没人守。

**怎么恢复**：回滚该次短路提交。**不是**加个 `if`——`ARRIVE_ON_CELL_REQUIRED`
已废弃且代码里零引用，`tests/test_nine_grid_arrive_shorts.py` 用 AST 钉住这条。

### 6b. 同步到机器人 —— ⚠️ 只传这条路线要的文件（2026-09-27）

```bash
python tools/sync_nine_grid_to_robot.py --check   # 干跑：只列将传什么
python tools/sync_nine_grid_to_robot.py           # 真传 + 自动逐字节核对
```

**别用 `python tools/sync_to_robot.py`（默认集合）**：它的 `DEFAULT_PATHS` 是
`main.py + debug.sh + core/ vision/ levels/ tools/ models/`，会把**全部关卡**
（含 `stairs_hurdle` / `press_button` / `football_shooter` 现场手调过的那些）、
`tools/` 上百个文件、40MB 模型一起推上去，覆盖掉机器人上别处的现场值。

专用命令把范围钉死在 **10 个文件**上（路线本体 3 + core/vision 依赖 5 + 入口与
trace 2），每条为什么在清单里都写在脚本文件头里，最小集是**留一法实测**出来的，
不是读代码猜的。常用开关：`--verify`（只核对不写）、`--no-verify`、`--pull`
（传完把 `archive/result/real_trace_*.txt` 拉回来复盘）。

同步前后各有一条容易踩的坑（都实测过）：

- **`--full` 是默认行为**：本地清单 `archive/sync_manifest.json` 记的是"我这个
  工作树推过什么"，机器人上的同名文件可能被**别的工作树**后推覆盖过（实测：
  清单说 `core/camera_config.py` 已同步，机器人上却是老版本）⇒ 清单会静默跳过，
  所以本脚本不给它机会。
- **`core/trace.py` 必须跟着传**：九宫格没有 `WALLS`/`ROUTE`，老版 `save_trajectory_png`
  会抛 `module 'levels.nine_grid' has no attribute 'WALLS'` —— 机器人上那些
  35407 字节、长得一模一样的 `real_trajectory_*.png` 就是这么来的。

## 7. 怎么确认"没改行为"

```powershell
$env:PYTHONUTF8="1"
python -m pytest tests -q -p no:cacheprovider                            # 179 passed
python -m sim.nine_grid_sim --three-stage --no-ui --seed 3 --quiet        # 7/7、拍照 170、动作 139
python -m sim.nine_grid_sim --no-ui --seed 3 --quiet                      # 7/7、拍照 484、动作 422
python tools/diag_arrive.py --quiet                                       # 逐格真值落点；跨格级假到达必须 0
python tools/ab_ninegrid.py --variants unified three_stage --seeds 3 7 11 21
```

固定布局、种子 3 这两组数字是**行为冻结基线**：任何重构都必须让它们一模一样
（除了明确记录过的行为改动）。演进史：统一决策那一组在 2026-09-25 由 `6/7、526、480`
变成 `7/7、652、591`（"取消放弃该格"那次策略改动）；随后小转原语换成现场实测值
（左 8.625°/右 5.200°，仿真不再用一个不存在的机器人）后降到 `523、446`；
2026-09-26 短路格的同一性核验后为 **`484、422`**。
⚠️ 三段式的 `189、167` 也已过期：现在是 **`170、139`**（同一批小转/标定改动所致），
别照着旧数字判断"行为有没有变"。

## 8. 已知差距（改之前先看这一条）

- 统一决策**到达前不做蹭步**（`back_one_step` + `go_forward_one_step`），
  所以真机上微动开关不一定触发。**上现场先用 `nine_grid_three_stage`。**
- 仿真里没建模的：真机拍照耗时、舵机到位时间、光照/白平衡、机体遮挡与同色杂物、
  面板物理尺寸误差（详见 `sim/nine_grid_sim.py` 模块 docstring）。
  **仿真通过不等于真机会过。**
- "绝不跳格"意味着**一格卡死就整局卡死**（真机上表现为一直磨到人工叫停）。
  这是顺序计分下的正确取舍（磨着至少还有机会拿到这一格和后
  面的分；跳过则一定 0 分），但要知情：现场需要有人盯着日志的
  `[重试] 面板N … 继续磨这一格` 行，判断是不是该人工介入。
- **随机布局下的跨格级假到达仍会出现**（实测 4 个种子 1/22 次、最差落点 132cm；
  见 §5b）。固定布局跑不到它，`tests/` 也只跑固定布局 ⇒ **上现场前若要更强的
  保证，得自己跑一遍 `tools/ab_ninegrid.py --layout random --primitives real`**
  并接受或处理这个数字。
