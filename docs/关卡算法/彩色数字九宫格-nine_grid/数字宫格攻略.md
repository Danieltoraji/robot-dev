# 数字宫格关卡攻略（九宫格视觉导航）

> 关卡：1m×1m 九宫格，7 块数字面板（1 红 … 7 粉）随机布局，左下位置 6 恒空。
> 机器人按 1→2→…→7 顺序依次到达各面板中心（压中微动开关），限时 15 分钟。
> 计分：顺序正确每格 10 分（70）+ 限时完成 30 分 = 100 分。
> 代码入口：`python main.py nine_grid`；核心实现 `levels/nine_grid.py`。
> 开发过程、踩坑与可复用经验见《数字宫格开发实录.md》。

---

## 0. TL;DR

- **视觉主判 = 颜色**（HSV 七色，色↔数字一一映射），**HOG+SVM 数字只做仲裁否决**。
- **定位 = GN 地图定位**：布局扫出"数字→格"映射后，9 个格心即地图；每步用
  动作模型预测位姿，再用可见面板的「投影像素 ↔ 检出像素」残差修正。
- **观测必须裁切感知**：面板被画幅裁切后，轮廓对角线交点失去几何意义
  （实测偏差 150~826px）；裁切面板改用「颜色掩膜凸包质心」，预测端用
  「四角投影与画幅求交的面积质心」配对。这是 2026-09-08 仿真 7/7 全败的根因。
- **到达确认 = 位姿"脚下覆盖中心"主判**（+ 接近段检出过目标面板 + 蹭步压开关）。
  低头色占比不可作主判：pitch 1040 站在面板中心时面板整个在视野外（占比 0.003）。
- **绝不跳格**：ESP32 计分链按顺序，错序/重复只日志不断链（已读 .ino 确认）。

## 1. 关卡与计分规则（来自赛道方 .ino / README）

| 项 | 说明 |
|---|---|
| 场地 | 1m×1m 底板，3×3 格，格距 33.33cm；位置 6（左下）恒空 |
| 面板 | 七色数字牌，色块约 28cm 见方；黑字 1~7 |
| 触发 | 每格中心微动开关（3×3 矩阵，共 8 个），压中即计分 |
| 计分 | 顺序正确每格 +10；15min 内全部完成再 +30 |
| 计分容错 | 顺序错误/重复触发只打印日志，**不断链**；借道压到其它面板安全 |
| 触发冷却 | 每格 2000ms（同一格 2s 内重复触发忽略） |
| 上报 | ESP32 串口 + WiFi HTTP POST（`SERVER_URL` 需现场配置） |

机器人需要自己**从视觉发现布局**（哪块数字在哪个格），再按 1..7 顺序走。

## 2. 参考方案（清华队已验收）分析

参考实现见 `reference code/九宫格视觉导航/`（README + robot/*.py + .ino）。

### 2.1 直接继承的优点

1. **三信息融合**：颜色主判 + HOG/SVM 数字 + 洞分析；符合"颜色为主、数字为辅"。
2. **视觉闭环**：每步动作→重拍→重识别→修正，不依赖里程计，天然抗打滑累积误差。
3. **自适应小转**：EMA 在线估计每次小转实际角度，低于阈值判"被地面吞掉"→升级大转。
4. **卡滞恢复**：proximity 无改善 → 后退+越障脱困。
5. **到达判定三段式**：低头看颜色"出现→压过→消失"（过渡判据，不要求站上可见）。
6. 双姿态（前视/低头）搜索、per-id 阈值现场可调。

### 2.2 不足（本仓库的改造点）

| 参考方案不足 | 本仓库做法 |
|---|---|
| 两套 HSV 阈值并存 | 收敛为单一阈值源 `vision/nine_grid_detector.COLOR_THRESHOLDS` |
| `yaw=-(dx/W)*FOV` + bbox 宽近似距离 | GN 地图定位（真实内参+畸变模型） |
| 紫色(6)阈值极敏感靠特判 | 统一色块几何校验 + 凸包观测 |
| `while True` 无超时 | 单格 110s + 全局 780s 看门狗 |
| 无布局先验，每个目标原地转 | 开局双俯角宽扫建"数字→格"映射 |
| "压过颜色消失"可能走出小面板 | 位姿覆盖中心判据 + 蹭步 |
| 小转在本机实测不可靠（goodluck 已弃用） | EMA 在线裁决 + 连续 2 批失效升级 + 大转防振荡 |

## 3. 本仓库方案

### 3.1 视觉（`vision/nine_grid_detector.py`）

- **主判颜色**：HSV 七色。绿 `H∈[100,160]° 且 S/V≥1.15`、蓝 `H∈[207,220]°`
  且 V∈[35%,75%]、S 随 H 动态（不用简单长方体，继承参考实测结论）。
- **数字仲裁**：黑色数字 mask（主色 HSV 距离 + Otsu）→ HOG（64×64/9 orientation/
  8×8 cell/L2-Hys）→ 参考 pkl SVM。**只否决不改主判**：颜色判 k 而 SVM 高置信
  判 j≠k → 该格标记"待近距复核"。
- **同色碎块合并**：数字孔洞/画幅裁切会把同一面板的颜色掩膜切成多块（bbox 互不
  重叠，跨色 IoU 去重抓不到）。本关卡每色只有一块面板，故把"间距小于较大块尺寸"
  的同色碎块并成一个观测，取凸包为可见区域。
- **两种中心定义**（关键）：
  - 未裁切：`center_px` = 轮廓对角线交点（透视不变量，面板中心的精确投影）；
  - 已裁切：`hull_centroid_px` = 颜色掩膜凸包面积质心（裁切不变）。
  `clipped` 用"合并后 bbox 是否贴画幅边（工作分辨率 8px）"判定。

### 3.2 定位（`levels/nine_grid.py`，GN 地图定位）

**布局扫**（`layout_scan`）：
- 双俯角（导航 1200 / 低头 1040）× 头部 5 位（中/左/右/宽左/宽右）扫全场；
- 每帧色块经地面单应（点击标定或 `from_pose` 解析自举）落到场地坐标 → 最近格 →
  多数投票 → `数字→格` 映射；扫齐 7 个数字提前收束；
- 最后补一帧中位头+导航档做 GN 精化，消掉起始位姿假设误差。

**每步 GN**（`_gn_run`）：
- 残差 = 预测像素 − 检出像素，逐点：
  - 未裁切：`project(cell_center, pose)` − `center_px`；
  - 已裁切：`clipped_quad_centroid(cell_center, pose)` − `hull_centroid_px`，
    其中 `clipped_quad_centroid` = 面板四角投影 → 与画幅矩形求交 → 交多边形
    面积质心（与检测端同定义，裁切不变）。
- **鲁棒核**：IRLS + Cauchy(c=4px)。裁切野值/误检残差可达数百 px，平方损失会被
  拖走；Cauchy 让大残差权重趋零。
- **弱先验正则**：附加 `(p−p0)/σ` 行（σ_xy=8cm、σ_θ=8°），保证只有 1~2 个
  面板可见时解不会沿不可观测方向乱跑。
- **门控**：单帧 RMS ≤12px / 合并帧 ≤15px；相对预测跳变 ≤12cm/30°；残差 >25px
  且点数 ≥5 时剔除一轮后重解（剔除后须 ≥2 点）。
- **惰性多起点**：先解先验起点，RMS ≤3px 即返回；否则补 ±8cm/±10° 起点取最优。

**为什么不用逐帧单应**：接近目标时一帧常只有 2~3 块面板共视（近处面板超出视野/
贴边裁切），单应需要 ≥4 块。GN 用动作先验 + 2 块就能解。

**为什么开局扫全场，而不是"只找下一个"**（参考方案是后者）：

1. **下一个目标可能不在视野里**：布局随机，到达面板 k 后 k+1 常在身后/侧后，
   "只找下一个"必须转机身搜索——本场地小面板+打滑，原地转向是摔倒/蹭偏的
   高风险动作（且本机小转实测不可靠）。有全局地图后可以直接朝已知格心走，
   只在接近段用视觉确认。
2. **预扫是零身体风险的一次性动作**：机器人站在入口外侧静止，只动头部
   （2 俯仰档 × 5 头部位 ≈ 10 帧）；"只找下一个"把同样的搜索摊到每个目标，
   机身转向次数成倍增加。
3. **GN 定位本身需要这张地图**：残差是"检出面板像素 ↔ 已知格心投影"，不知道
   "红色在 cell3"就无法配对——`数字→格` 映射是定位的前置输入。
4. **一次多视角投票更稳，且早失败**：每数字最多 10 帧多数投票，单帧漏检/误检
   不影响结论；扫不齐 7 个直接 `RuntimeError`（提示查 HSV/光照/起始位姿），
   不会开到一半才发现布局不对。
5. （软）全局地图允许借空格/借道穿越，减少转向；ESP32 对借道压到其它面板
   只记日志不断链，是安全的。

代价：预扫依赖起始位姿假设（现场必须点击标定覆盖）、多花约 10 张照片、
HSV 阈值不准时会开局直接失败（好处是失败得早、错误明确）。

### 3.2b 导航 v3：视觉伺服（抗地板形变，2026-09-11 起为**默认生效路径**）

> **为什么改**：用户现场确认**本关地板会形变**，机器人在板上行走时机体俯仰/
> 相机高度大幅变化（按 **±15°** 考虑）。量化：h=50cm、竖直半视场 26.8° 时，
> 有效俯角 42°/57°/72° 的可见地面带分别是 **19~184 / 5~86 / 0~50 cm**
> —— 同一个俯仰档，可见带 4 倍摆动。任何"冻结相机常数 + 度量投影"的判据
> （上面 §3.2 的 GN、"位姿覆盖中心"判据）在这种形变下都不可用。
> **sim 实测：无形变 7/7（200 张）；随机游走 ±15° 时旧导航 0/7。**

v3 改用**相对量视觉伺服**（做法与参考实现一致：
`reference code/九宫格视觉导航/` 的 `yaw=-(dx/W)·FOV`、`proximity=框宽`、
低头颜色"出现→消失"），全程不需要相机高度/俯仰：

```
搜索：当前朝向头部五档（零身体位移）→ 按"死推提示"转向（最多 5 个大转步）
      → 目标不在任何俯仰档视野里时按死推纵向**盲走**（形变会把可见带推走）
对准：yaw = -(dx/W)·CAMERA_FOV_H + 头部角   （机体系偏角，左正）
      死区 8°；>30° 大转；否则 EMA 小转批量（与 do_turn 同一套常量）
接近：框宽 ≥ VIS_ARRIVE_BOX_PX(820px ≈ 目标进 50cm) 交棒；卡滞=框宽不涨
低头到达：颜色占比**峰值跟踪**——峰值过下限后跌破峰值 55% ⇒ 已压过该格
      横向纠偏 dx/框宽×28cm（投影不变量）；未过峰用 6cm 批量、过峰改 2cm
确认：蹭步压微动开关 + 仲裁冲突近距复核（沿用 v2）
锚定：每格到达后把死推位姿重置到该格格心（消除逐格漂移，保提示可用）
```

关键点与阈值依据：

| 量 | 抗形变原因 |
|---|---|
| `yaw`（像素偏移） | 只作伺服增益，把误差驱到 0；FOV 取名义值不影响收敛点 |
| 框宽（目标框宽 px） | ∝ 1/**沿轴深度**（≈ d·cosθ + h·sinθ），俯仰变动时同步变化，仅用来触发"进 50cm"（实测 150/100/80/60/50/40/30cm → 376/530/624/742/808/880/954 px，50cm 内趋于饱和） |
| 颜色占比峰值/跌落 | 描述"色块从视野里出现→消失"的**机器人与色块相对关系**，与相机参数无关（尺度无关版，参考实现的每色绝对阈值在我们的俯角下判不到，实测峰值仅 0.13） |
| `dx/框宽×28cm` | 比值是投影不变量（两者同比缩放） |
| 死推位姿 | 纯动作模型积分，不含任何相机常数；每格重置一次 ⇒ 只用于"往哪转/盲走多远"的粗提示（±30° 容差足够） |

失效与兜底：
- 目标反复丢失/不入视野，但死推已到位 ⇒ 直接交低头颜色判据裁决；
- 低头段迭代用尽 ⇒ 死推距离兜底（|纵向|≤15cm 且 |横向|≤12cm 判到位）；
- 时间不足（剩余/剩余格 <90s）⇒ 自动收缩低头段迭代上限；
- 地图 GN 仍在（`USE_MAP_CORRECTION=True` 时可每格校正一次），**失败只打一行
  日志、绝不触发恢复链**（v2 的"定位风暴"根因）；
- 现场应急回退：`VIS_NAV_ENABLED=False` 即回到 v2 地图路径
  （`_go_to_panel_map`/`_approach`/`_enter` 全部保留）。

验收（PC）：`python tests/test_nine_grid_deform.py` 三场景全过 ——
基线 7/7（200 张）、随机游走 ±15° 7/7（233 张）、阶跃 +15° 7/7（246 张）；
`tests/test_nine_grid_sim.py` 基线仍 7/7。

### 3.2c 颜色识别：现场光照鲁棒链路（2026-09-11 起为**默认生效路径**）

三段式：**归一化 → 数据拟合窗口 → 结构证据**，每段都有开关可以单独回退。

| 段 | 机制 | 关键常数（`vision/nine_grid_detector.py`） |
|----|------|------------------------------------------|
| 1 归一化 | 灰世界白平衡 + 曝光基准（白点均值拉到 155） | `NORM_ENABLED`、`NORM_TARGET_WHITE_MEAN=155`、`WHITE_S_MAX=40`、兜底 `WHITE_S_FALLBACK=120` |
| 2 调色板 | 13 张实拍帧拟合的互斥 H 窗口 + 松 S/V 下限 | `USE_PALETTE`、`PALETTE`（`models/nine_grid/palette.json` 可现场覆盖） |
| 3 结构证据 | 色块内黑字占比（数字证据）+ 现场模板形状仲裁 | `DIGIT_EVIDENCE_*`、`SHAPE_*`（`models/nine_grid/digit_templates.npz`） |
| 4 相机固定 | 一局开始锁白平衡/曝光/对焦（**场地相关常数**） | `core/robot_core.CAM_*`：`CAM_WB_TEMPERATURE_K=5800`、`CAM_EXPOSURE_ABS=100`、`CAM_LOCK_EXPOSURE=True` |

- **颜色始终是主判**：形状只在"同位置双色命中"或"中位 H 距窗口边界 <4°"时
  才允许改判，且形状匹配"间隔"必须 ≥0.30（留一实测：该门限下 24/24 正确）；
- **数字证据只做软信号**：现场实测"色块内没有黑字"可能是**数字被物件挡住**的
  真面板（photo_1789022703 的绿 4 证据 0.0000），硬过滤会误杀 ⇒ 只对
  "证据 >0.22 的大片深色块"硬丢，低证据改用于导航同色择优；
- **过曝是不可逆的**：`normalize_illumination` 会报 `clip_frac`，>5% 时应锁曝光
  （见 `core.robot_core.CAM_LOCK_CONTROLS_ENABLED`）；归一化救不回打满的像素。

一键回归：`python tests/test_nine_grid_color.py`（含通道增益扰动矩阵：
未过曝组合必须 7/7）；现场复标流程见 `数字宫格开发实录.md` §13.5。

### 3.3 运动与 FSM

动作白名单（全部小幅度，位移用本机实测值）：

| 动作 | 名义量 | 用途 |
|---|---|---|
| `go_forward_one_step` | 2.0cm | **唯一前进原语**（远距允许 ≤3 次小批量 = 6cm） |
| `back_one_step` | 3.2cm | 脱困/蹭步/过冲回蹭 |
| `left_move`/`right_move` | 1.9/2.2cm | 横向纠偏 |
| `turn_left`/`turn_right` | 22°/25.7° | 大转兜底 |
| `turn_*_small_step` | EMA 在线估计 | 小角对准（连续 2 批 <0.5°/次→升级大转） |
| `stand` | — | 停 |

**禁用**：`go_forward`、`go_forward_fast`——5cm 步幅在 33cm 小面板 + 打滑
地板上容易重心前扑摔倒（现场结论）；`_act` 里做了硬门拒绝，误用会直接
抛异常而不是悄悄执行。

FSM：`SEEK`（布局先验+视觉确认）→ `ALIGN`（小转批/大转）→ `APPROACH`（闭环小步，
远距+对准良好才批量）→ `ENTER`（低头档，横移纠偏）→ `CONFIRM`（位姿覆盖中心 +
接近段检出过目标 + 蹭步压开关）→ 下一格。

### 3.4 容错

- **卡滞**：相邻两次定位的目标纵向改善 <0.5cm 连续 2 次 → 后退 1 步脱困。
- **定位丢失**（逐级升级，`_recover`）：低头补扫 → 按运动先验朝目标转 → 后退重扫
  → 盲走一步 → 撤销上次转向 → 放弃本段重试。
- **丢失恢复为什么必须能转身**：目标在身后时，转身途中可能出现"整帧 0 个面板"
  的方位（实测格心朝南），纯头部扫（±40.5°）救不了；用运动先验位姿算目标方位
  把视角转回去。
- **大转防振荡**：22/25.7° 步长大于 8° 死区两倍时，9°→−13°→9° 会来回转；
  检测到误差符号翻转且无改善 → 停止转向，改用"带航向偏置的接近"（横偏靠横移）。
- **时间预算**：单格 110s、全局 780s（13min，留 2min 上下场）；定位次数软护栏
  40 次/格（超限只告警，用于真机时间诊断）。
- **绝不跳格**：顺序错只日志不断链，借道穿越其它面板安全。

## 4. 2026-09-08 根因诊断记录（为什么仿真曾 7/7 全败）

### 4.1 现象

`python tests/test_nine_grid_sim.py` 全 7 格未确认；日志刷屏
`[定位] 离群剔除后可用面板不足，丢弃`。

### 4.2 根因一：裁切面板的"中心"是野值

在 (50,−20)、heading −18.69°、pitch 1200、head 1050 的一帧里，7 个检出在
**真值位姿**下的残差：

| 目标 | cell7 | cell4 | cell5 | cell1 | cell2 | cell3 | cell0 |
|---|---|---|---|---|---|---|---|
| 是否裁切 | 是 | 否 | 否 | 否 | 否 | 是 | 是 |
| 残差 px | 152 | 9 | 2 | 7 | 2 | **305** | **826** |

- 全 7 点 GN（真值先验）→ 被拖到错误折中解（RMS 207px）；
- 事后离群剔除（>15px 全剔）→ 可用点 <2 → 返回 None；
- 只用 4 个未裁切点 → 收敛到真值，RMS 2.69px。

**机理**：`quad_center` 取轮廓对角线交点，只对完整四边形有意义；裁切后可见碎块
的交点与真实中心无几何关系，越近偏差越大。GN 是平方损失，单个 826px 野值压过
6 个 ~5px 内点；而离群剔除在收敛之后执行，此时所有点都被拖大，退化为清空点集。

**为什么"丢弃裁切面板"也不行**：格内时 33cm 网格宽于视场，干净面板只剩 0~3 个
（实测 (50,45) 处 p1200 干净 0 个 / p1040 干净 1 个）。只能"用"裁切面板。

### 4.3 根因二：到达确认判据几何不可行

相机高 39cm、f=1950：

| 俯仰脉宽 | 俯角 | 画面下沿对应地面 |
|---|---|---|
| 1200（导航） | 27.0° | 28.9cm |
| 1040（低头） | 41.4° | **15.8cm** |
| 1000（参考低头） | 45.0° | 13.1cm |

站在面板中心时面板远边 ≤14cm < 15.8cm → **目标面板整个在视野外**。实测目标色
占比：距中心 25cm 时 0.164（峰值），站上中心 0.003；旧判据要求 >0.10 → 永远失败。
参考方案用的是"出现→压过→消失"过渡判据。

### 4.4 根因三（测试基建）：仿真渲染 26s/帧

角点 z 略大于 0.05 时投影溢出为 ±inf，`astype(int32)` 得 INT_MIN，
`cv2.fillPoly` 扫描 ~2³¹ 行（实测 26.4s/次，整轮 820s+）。
修法：投影后**裁到画幅**（`intersectConvexConvex`）而不是整块丢弃——真实相机
只看到交集，丢弃会让"贴边仍可见的细条"在仿真里消失，比现实更难。

### 4.5 另一个 AI 的排查为什么卡住

其手工 GN 脚本用"6 个对应点 + 真值先验"收敛到 1.98px，关卡却发散，于是怀疑
GN 数学（比对两份代码、怀疑 `.ravel()`）。实际：
- 当前 HEAD 两处 `r = residuals(...).ravel()` **都已有 `.ravel()`**，该 bug 不存在；
- 差异在**输入点集**：手工脚本的点集不含裁切野值，关卡的点集含 3 个野值。
教训：先插桩**数据**（对应点、逐点残差），再怀疑算法。

### 7.1 图形化仿真（`sim/nine_grid_view.py`）

```bash
python -m sim.nine_grid_view                       # 开窗播放完整关卡
python -m sim.nine_grid_view --random-layout --seed 11
python -m sim.nine_grid_view --headless            # SSH/无显示器：退回无头运行
python -m sim.nine_grid_view --detect              # 运行中也叠加检出（慢 ~25s）
```

窗口 = 左侧**相机窗格**（合成帧 ×0.25：预测面板中心 + 目标格橙圈 + 暂停时
的检出框 `color→digit`/`C=裁切`）+ 右侧**俯视图**（3×3 格线、真值面板配色、
估计映射青圈、目标橙环、估计位姿品红/真值黑色、估计轨迹尾迹）+ 底部**状态栏**
（step/caps/target/fwd/lat/bearing/est_err/phase）。

| 键 | 作用 |
|---|---|
| `SPACE` | 暂停 / 继续 |
| `S` | 单步（暂停时每按一次放行一次拍照） |
| `R` | 重开（seed+1） |
| `Q` / `ESC` | 退出 |
| `D` | 切换检出叠加（暂停时自动开，运行中默认只画预测以省时间） |
| `+` / `-` | 调速（1~500ms/帧） |

看什么：① 布局扫后青圈是否落在对应数字面板上（错了会画红线）；② 接近段
品红与黑圈是否贴合（`est_err` 即两者差）；③ `phase` 是否按 SEEK→APPROACH→
ENTER→CONFIRM 推进；④ 卡滞/恢复时轨迹是否打转。GUI 只挂在 I/O 接缝上
（`viewer=None` 时仿真行为与无头完全一致），窗口里文字用 ASCII（cv2 不支持中文）。

仿真基线（2026-09-08 修复后，PC，默认布局+seed 3）：**7/7 确认到达，拍照 215 张，
动作 171 次，墙钟 ~33s**。拍照护栏 <350 张（真机时间预算的代理指标）。

## 8. 已知风险

- **面板色块尺寸**按 28cm 假设；裁切预测依赖它，P3 必须实测。
- **真机拍照耗时**（fswebcam）未实测：若单张 >2.5s，需评估 1296×972 采集或
  v4l2 常驻管线；定位次数软护栏与仿真拍照计数是代理指标。
- **小转可靠性**是本机历史包袱；已加三重兜底（连续失效升级 / 大转防振荡 /
  航向偏置接近），但仍需 P3 实测裁决。
- **布局预扫依赖起始位姿假设**（缺省 (50,−20)/0°）；现场必须点击标定覆盖。
- 同色外物（赛道外红色/蓝色物体）可能污染检测；当前靠面积/长宽比/凸实性过滤。
