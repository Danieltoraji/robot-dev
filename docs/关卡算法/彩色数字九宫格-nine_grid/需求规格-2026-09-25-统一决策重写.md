## 1. 用户原始方案（原文，逐字保留，勿改写）

```
目前已知：
1.想要正确判定色块，必须联合场地信息。
2.图像像素和具体位置间难以建立可以求解析式的映射。

为此我提出以下方案：

1. 开局趁着在场地外侧，预扫描场地，建立具体格子-位置对应关系 Map。
2. 赛中，拍照识别。
   - 对识别的结果对照 map 核验，如果明显违背 map（不是偏差，而是对不上）
     则尝试救援：放弃其中一个再核验，直到符合。
   - 如果出现两个同样号码的区块，根据 map 判断正确的是哪一个。
     （要降低连通化的距离阈值，让不同区域联合变得困难）
   - 如果没有找到结果，根据图像中有的内容反推位置，启发下一次的搜索。
   - 即将掉出场地时，给予避让。
3. 寻找到目标后，进行决策。决策方法是：看目标点的位置。将图像划分为：
   1. 以部分下沿为下底，部分上沿为上底，高等于画幅高度的等腰梯形。
   2. 以整个下沿为下底，部分上沿为的上底，高等于画幅高度的等腰梯形。但不包括 1。
   3. 画幅除了 1 和 2 的部分。
   如果在 1，则直行。如果在 2，则横向移动。如果在 3，则旋转。

上述一切涉及距离的，都通过去畸变 + 按照标定的像素点曲线，从像素反推距离。

请谨慎评估方案，召集 subagent 评审。确认无误后，予以实现。
```

**配图**：中央**上窄下宽**的绿色等腰梯形（直行）；两侧蓝色梯形（平移）；
蓝/橙之间有一条**水平分界线**；最外侧橙色（旋转）。

## 2. 用户澄清的四个概念（不许混为一谈）

| 概念 | 含义 | 用户裁决 |
|---|---|---|
| **老办法** | 二值：对准了就直行 / 没对准就转（`\|yaw\| ≤ 12°`） | **废弃** |
| **三档分区** | 看目标落在画面哪一块 → 直行 / 横移 / 旋转 | **要**（= §1 第 3 条） |
| **三阶段** | 对准 → 接近 → 到达，**三段各有各的切换判据**（12° 死区 / 框宽 920px / 色占比回落） | **不要** |
| **统一决策** | 不分三段，**用同一套逻辑一路走到目标** | **要** |

> 用户提的是 **三档分区 ＋ 统一决策**。"三档分区塞进三阶段"这个组合用户自己否了。

## 3. 用户明确放弃的三样（重写后一个都不许回来）

| 放弃 | 精确含义 | 边界（不许误读） |
|---|---|---|
| **批量转弯** | 一次决策下发**多个**转向原语（`_act(act, n)`，n>1） | 不是"取消小转"，是取消"批量" |
| **yaw** | 用 yaw 的**数值**做规划（`n = floor(\|yaw\| / 步长估计)`） | yaw 仍可作**伺服增益**（`-(dx/W)×FOV`）。官方结论原文："作为伺服增益无所谓（闭环吸收），**但不要用它去反推角度数值**" |
| **死推** | 用按动作推算的位姿做**导航判据/提示/护栏** | 允许存在，但**只进遥测，不进决策** |

**用户原话（2026-09-25）**："在统一决策方案之中我们没有采用批量转弯，也完全放弃了
yaw 和死推。为什么它们还在决策？"

## 4. 被实测否证、因此不再实现的三条（附证据，不改写用户原意）

| 用户条目 | 实测结论 | 依据 |
|---|---|---|
| ②-b 两个同号区块按 map 裁决 | **在观测层不可能出现**：`detect_panels` 每种颜色每帧只保留一个观测（`main = frags[0]`），裁决发生在**合并内部** | 真值集 12 帧实测：单帧同色多观测 **0/12** |
| ②-c 降低连通化距离阈值 | **不可行**：该阈值是被"防误并"顶上去的（旧准则太松 ⇒ 木框碎块被并入、观测中心偏 600 原生px）。安全下界约 **0.20**；降破后到达证据门失守、交棒点永不触发 | 交接文档 §5.4 / 评审 Q7 |

### 4.1 ④ 的替代（仍是"从像素反推距离"的本意）

不冻结任何曲线，改**运行期标定**：布局扫的 `_pixel_pose_calib` 联合精修出
`(x, y, θ, 安装偏移, 相机高度)`，用 `project_ground_to_pixel` 做**逐帧**像素↔地面映射。
该链路已在用，实测自标定结果：**安装偏移 +19.0°、离地 57.4cm（重投影残差 中位 1.4px／均方根 3.6px）**。

## 5. 用户对仿真器的裁定（2026-09-25，P0 的立论）

> "现场字形朝向随机，不需要考虑这一点，并将仿真器的朝向也作为随机的。"

⇒ 三档分区判据、形状仲裁、数字判据都建立在"画面里的数字"之上，而**仿真器此前
把数字画成纯黑实心矩形**，数字链路在仿真里**没有输入信号**。故 P0 必须先把仿真器
做真：画**现场照片同源的真字形**，朝向**随机**（按格位确定性随机，不动动作噪声的随机流）。

### 7.2 数据流（每帧一次拍照 → 一次检测 → 一次决策 → 一个动作）

```
运行期标定（布局扫产出，开局一次）: pose5 = (x, y, θ, 安装偏移 off_deg, 相机高度 h_cm)
        │  project_ground_to_pixel / GroundHomography
capture_frame() ─► 一次全色检测 ─┬─► 目标色观测 → (px, py) ─► 分区判档 ─► 一个动作

```

### 7.3 感知层

1. `detect_panels(frame, colors=[target], arbitrate=False, drop_border=False)` → 取
   `max(hull_area)`；**不跑 SVM**。裁切取点规则不变（`clipped` → `hull_centroid_px`）。
2. 四区份额 `(whole, purple, orange, asym)`；份额 = 区域内目标色像素 ÷ 全帧目标色像素（四区之和 = 1）。
3. **取景档全程 `PITCH_DOWN=1040`**（可见带 3.8~85.7cm）。`PITCH_NAV=1200` 只用于布局预扫 +
   "完全不在视野里的远距补帧"（每次重捕获最多 1 张），**不做控制**。
4. **机体系折算**：`col_forward = W/2 + head_deg × W / 60.0`，
   `dx = |px − col_forward| / W`（`head_deg = (head_pulse−1500)×0.09`，脉宽大=头左转）。
   现版本 `_zone_px_of` 只折头部、**这是对的**——见下面的更正。

   ### ⚠️ 更正（2026-09-25，实测）：`_pitch_offset_deg` 是**俯角**，不是"前偏"

   规划文档与日志长期把它写成"相机相对机体**前偏** +19.0°"，据此曾计划给判档补一个
   ≈19°×19.7px/° ≈ **374px** 的横向偏置。**该计划已作废**，两条实测：

   | 实测 | 结果 |
   |---|---|
   | 投影模型里该量的位置 | 只进俯角：`alpha = (1500−pulse)×SERVO_DEG_PER_US + pitch_offset_deg`（`project_ground_to_pixel` / `GroundHomography.from_pose`），**不含任何方位信息** |
   | 对**横向**像素预测的影响 | 取 0° 与 19°：面板正前方 40/60/80cm 的横向预测误差**都是 0.3px**（零影响） |
   | 仿真里"面板正前方"落在哪 | **1283px** vs 画幅中线 1296px ⇒ 偏差 **13px ≈ 0.7°**（`CAM_BODY_OFFSET=0`），而不是 374px |

   ⇒ **`_col_forward` / `_body_yaw_deg` 不得引用 `_pitch_offset_deg`**；日志文案里的
   "前偏"应改为"前倾/下俯偏移"。已加回归闸
   `tests/test_nine_grid_unified_zone.py::test_pitch_offset_is_elevation_not_yaw`。
   **若将来现场确实标定出相机-机体方位安装偏差**，正确做法是：① 给投影模型加一个
   yaw 安装参数；② 再在 `_col_forward` 里按它平移中线。**不许挪用俯角参数**。

### 7.4 决策层

**判档 `zone_of(dx, t)`**（`t = py / H`）：绿半宽 `= GREEN_TOP+(GREEN_BOT−GREEN_TOP)·t`；
蓝只在 `t ≥ 1−BLUE_HEIGHT`，蓝半宽 `= BLUE_TOP+(BLUE_BOT−BLUE_TOP)·u`。

| 参数 | 值（画幅比例） | 物理含义（低头 1040） |
|---|---|---|
| `GREEN_TOP` / `GREEN_BOT` | 0.0548 / 0.1199 | 走廊半宽 ±6.7cm(85cm处) ~ ±8.0cm(3.5cm处) ⇒ 近似**恒定 ±7cm** |
| `BLUE_TOP` / `BLUE_BOT` | 0.2746 / 0.3623 | 蓝外沿 ±20.7 ~ ±24.3cm ⇒ 近似**恒定 ±22cm** |
| `BLUE_HEIGHT` | 0.2445 | 蓝区上沿 = 地面 **15.9cm**（那条水平分界线） |
| `PURPLE_HEIGHT` | 0.2445 | 紫区上沿，**独立参数**；横向边界**就是**绿走廊 |

**动作（一次决策 = 一个原语，次数恒为 1）**：绿 → `go_forward_one_step`；
蓝 → `left_move`/`right_move`；橙 → `turn_left/right_small_step`。
**迟滞只放宽"离开"**：已在本档时边界 +`HYST_PX = 2.0°×W/60` ≈ 86px。

**决策输入门控**：① 候选核验（用户 ②-a）：目标观测落在锚共识外（残差 >6px）或不在任何
格心半格内 ⇒ 判为假面板，**不压它**，改为自转 1 步 + 前进 1 步；锚不可用（≈85% 帧）⇒
不核验、只记遥测；救援上界 1 个观测、失败 2 次弃格。② 颜色歧义：用形状模板**在候选色内**
裁决，冲突只记遥测。③ 目标丢失 ⇒ §7.6 纯视觉重捕获。

**到达证据门（只看当前帧）**：`紫 ≥ 0.35` 且 `橙 ≤ 0.10` 且 `|左右溢出不对称| ≤ 0.25`
（≈横向 3.2cm）；另加"几何锚可用时 `‖实测−格心‖ ≤ 5.5cm`"作**独立第二通道**。
到达后 `back_one_step`+`go_forward_one_step` 蹭步，打印依据与残差，**不谎报"到达 ✓"**。

### 7.6 状态机与容错（不是"三阶段"）

```
run_level
 ├─ layout_scan()                     # 允许最多 3 轮前进一步重扫
 └─ for digit in 1..7: goto(digit)
        └─ drive(digit)               # ★ 唯一决策循环，走到证据门成立
        └─ confirm(digit)             # 蹭步 + 残差 + 诚实声明
```

**丢失 ⇒ 纯视觉重捕获**：① 只扫头五档各 1 帧（零位移、不烧转向预算）；② 仍不见 ⇒
向最后已知一侧自转 **1 步**再扫；③ 连续 4 步不见 ⇒ 完整重捕获（每步复测）；④ **全程不用死推**。

**护栏不变**：单格 70s（自适应下限 45s）/140 张/300 动作；全局 780s；`trip` 即本格未确认
并返回；**绝不跳格**。

**日志契约**：每决策帧一行 `[决策]`；每格一行 `[格]`；整局一行 `[遥测]`。
**任何一格的结论都必须能只靠本局日志复算。**

- 试了"单向扫够 `VIS_REACQ_SWEEP_CAP_DEG=150°` 就反向"：到达 **24→23**、
  拍照 **2386→2512**（更差）⇒ **反向没救回那几格，反而多花帧**。
  ⇒ 已把该常量**默认设回 720（=不反向）**，注释里写明这次否证，别重复走。
- 也试过用"**脚下那块面板**"做 1D 航向搜索（此前否证用的是邻格面板，而脚下那块
  是唯一"正前方"的已知面板）⇒ **同样不可行**：站在格心上时 6 个格位**全部无观测**
  —— 相机看不到自己正踩着的那块面板（近距盲区 <3.8cm）。

**★ 仍然存在的洞（第三轮 `cap=150` 实验期间暴露，但机制与 `cap` 无关）**：
digit 3 有一次**假到达落在 100cm 外**，而那一帧**四个门全部通过**
（whole 0.082 ≥0.065、aspect 合规、紫/橙/不对称都合规）。
⇒ 说明现有门只能挡住"**边缘斜视残缺投影**"这一类假到达；
**"站在别的格子上、看到一块完整且居中的同色面板"**这一类挡不住
（整帧份额与形状在那种视角下都正常）。
要堵它需要**格的同一性核验**（即用户方案 ②-a：对照 map 核验候选是否是地图上
该格的那块），而不是再加份额/形状阈值。仓库已有件：`_map_anchor`（v2 裁切角点版）。

**当前权威成绩（8 种子，代码现状 `cover=0.065 aspect=0.46 center=0.12 cap=720`）**：
```
到达 48/56 = 85.7%   拍照均值 600/局   失败 8
【成功格】落点 中位 8.4cm  最大 10.8cm  ≤5.5cm 3/48  ≤半格 48/48  ★超半格 0
```


到达门要到 6cm 才成立（橙 ≤0.10），而从 40cm 出发要走 ~13 次前进决策（框宽是弱
代理、近距还饱和）⇒ 单格 ~40 帧是"正常接近"的下限；若再叠加一次 360° 重捕获
（~70 帧），单格必然撞 140 张上限。**任何"目标常在身后"的布局都必须靠减少重捕获
次数，而不是靠调阈值。**

### 过程中修掉的三个真 bug（都已写进代码注释）
1. **重捕获只转 4 小步 ≈ 36°**（旧 `VIS_UNIFIED_TURN_MAX`）⇒ 目标在 79cm 外、90° 侧方时
   必然丢格。改为"头部四档 → 按地图方位逐步转、上限 420°/40 帧"。
2. **框宽判"前进无效"必然误报**：面板走到脚下时框宽会因裁切**塌陷**（实测同一格
   1164→676px）⇒ 触发"后退一步"、把位姿推得更偏。改用色占比判。
3. **只看整帧占比仍会打成极限环**：压过格心时面板有部分出画幅，占比**正常下降**，
   被误判成"没走近"⇒"前进→后退→再前进"死循环（实测橙在 0.20↔0.10 来回）。
   正确签名 = 占比不增 **且** 橙不减。

## 10. 显式假设与残留风险
**假设**：① 五个分区参数（画幅比例）就是用户的设计意图，自带"恒定 ±7cm 走廊"
几何含义；若本意是按物理走廊宽度定义，需一次性反投影改写（只改 `zone_of` 一个函数）。
② 一次决策一个原语对运动抖动的免疫力来自闭环复测（前进组间极差 0.9cm/20步、
左转 25°/20步），而非常量精度。③ `right_move = 2.200` 有效（正文与表格不一致，需现场复核）。
④ 安装前偏用运行期自标定值（+19.0°），不用名义 18.5°。

**风险**：
1. **测量 2（近距剖面 50→16cm）未执行** ⇒ 紫/蓝上沿的"15.9cm"与三个到达阈值在真机
   未验证（现场同检测器占比峰值只有 **0.059~0.072**，而 sim 是 0.118~0.187）。
   **这是重写后真机一次通过的最大未知数**；建议开工前补做（~15 分钟，不改代码）。
2. **测量 5（真实形变 4 个格位）未执行**（无变形 112/112，`--deform 1.5` 只有 103/108）。
3. **数字 4 的字形只有裁切样本**（§9.1）⇒ 仿真里数字 4 的字形质量存疑，建议现场补拍一帧。
4. 仿真不建模同色杂物 ⇒ 到达证据门的"假到达"防护仿真测不出，只能靠真机 + 真值集。
5. 字形 crispness：`warpPerspective` + `INTER_LINEAR` 降到工作分辨率后略糊；现场帧本
   就略糊（模板即从现场帧提取），若形状匹配显著变差再改插值（已写进资产测试的容差）。
6. **相机-机体方位安装偏差未标定**：当前投影模型**没有**这个参数（仿真 `CAM_BODY_OFFSET=0`，
   实测面板正前方落在中线旁 13px≈0.7°）。若真机上该偏差显著（>2°），判档中线会整体偏 ⇒
   **属于必须现场补测的一项**。测法：把一块面板摆到机体正前方，读它在画面里的列与中线的差。
   ⚠️ **不许**拿 `_pitch_offset_deg` 顶替（它是俯角，见 §7.3 末尾的更正）。

## 12. 术语表（本文与代码注释统一用词）

| 词 | 含义 |
|---|---|
| 三档分区 | 绿=直行 / 蓝=横移 / 橙=旋转，按目标在画面里的位置判档 |
| 统一决策 | 一个循环、一套判据走完全程；没有"段"、没有交棒点 |
| 到达证据门 | 只看**当前帧**的四个量（紫/橙/不对称/几何锚），不含任何历史 |
| 候选核验 | 用户 ②-a 的可执行形式：目标观测能否被地图共识解释 |
| 重捕获 | 目标丢失后的纯视觉找回（头部五档 + 缓步自转），不用死推 |
| 死推 | 按动作推算的位姿（`predict_pose`），本项目**只允许进遥测** |
| 交棒点 | 三段式里"对准 → 接近"的切换点（`VIS_ARRIVE_BOX_PX`）；统一决策里**不存在** |
