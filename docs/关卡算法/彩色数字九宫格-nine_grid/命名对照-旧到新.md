# 命名对照：旧 → 新（2026-09-25 重写）

这份文档是给"看过旧代码的人"用的：旧名字 → 新名字，一行一个。
新代码里**已经不存在**旧名字（`grep` 旧名字只会在本文件和历史文档里命中）。

改名只做一件事：**把自造缩写换成看得懂的说法**。
没有改行为的意图，也没有改任何默认值。

- 旧名字里的 `VIS_` 前缀一律去掉：本关每个判据都是视觉判据，这个前缀不区分任何东西。
- `LATTICE_` → `GRID_FIT_`（格阵拟合）、`LAYOUT_` → `LAYOUT_SCAN_`（布局扫描）、
  `MAP_ANCHOR_` → `MAP_POSE_`（用地图里已知的面板反推自身位姿）、
  `POSE_BOOTSTRAP_` → `POSE_FROM_PANELS_`（由面板观测起手定位）。
- 分区名的值 `move` / `lat` / `rot` → `forward` / `side` / `turn`：
  这三个字符串会直接印进仿真日志与统计，写英文缩写没人看得懂。
- 对照工具里那套"臂"（`ARMS` / `--arms`）→ 对照组（`VARIANTS` / `--variants`）。

## 一句话说明这次改了什么名字

| 类别 | 旧 | 新 |
|---|---|---|
| 共用部分 | `levels/nine_grid_shared.py`、`NineGridShared` | 不变（"共用"就是它的意思） |
| 新办法 | `levels/nine_grid.py`、`NineGridLevel` | 不变（模块头写明是统一决策） |
| 老办法 | `levels/nine_grid_three_stage.py`、`NineGridThreeStageLevel` | 不变 |
| 例：格阵拟合 | `lattice_assign` / `_lattice_grid_fit` / `LATTICE_RMS_MAX_CM` | `assign_grid_cells` / `_fit_grid` / `GRID_FIT_RMS_MAX_CM` |
| 例：位姿反推 | `_map_anchor` / `MAP_ANCHOR_MIN_PTS` | `_map_pose` / `MAP_POSE_MIN_PTS` |
| 例：分区判档 | `_zone_of_px` / `_zone_of_px_body` | `_zone_at_pixel` / `_zone_at_body_pixel` |
| 例：重捕获 | `_unified_reacquire` / `VIS_REACQ_STRIDE` | `_find_target_again` / `FIND_STRIDE` |
| 例：到达后重置位姿 | `_reanchor_pose` | 不变 |

## 这一轮**删掉**的名字（不是改名，是不再需要）

| 删掉的名字 | 为什么 |
|---|---|
| `UNIFIED_NAV_ENABLED` | 它只用来"选哪套办法"。两套办法已经各是一个模块，这个开关在两边都是定值，所以分支直接摊平、开关删掉 |
| `VIS_ZONE_ENABLED` | 三档分区律的开关。现在分区律就是统一决策唯一的判据，没有"关掉"这个状态 |
| `VIS_ZONE_MOVE_DEG` / `VIS_ZONE_ROT_DEG` / `VIS_ZONE_ROT_NEAR` / `VIS_ZONE_NO_ROT_TAIL` | 旧的三档阈值（按角度分档）。现在的分档边界是从画面几何直接算出来的绿走廊/蓝区，不再用角度 |
| `VIS_ARRIVE_REGION_ENABLED` / `VIS_ARRIVE_ANCHOR_*` / `VIS_ARRIVE_MIN_BOX_PX` / `VIS_ARRIVE_ANCHOR_EVERY` | 统一决策的三个"候选到达判据"，两个被实测否证、一个（几何锚）随 `_verify_target_cell` 重写后没用了 |
| `VIS_REACQ_SWEEP_CAP_DEG` | "单向扫够就反向"。按角度算，它**永远不可能触发**（额度 720°，而外层预算先到），代码和常量都删了，结论写进 `levels/nine_grid.py` 的说明 |
| `BIG_TURN_THRESHOLD_DEG` / `BIG_TURN_OSC_ACCEPT_DEG` | 没有任何代码读它们（大转那段代码用的是写死的 1.0°） |
| `VIS_ZONE_PURPLE_HEIGHT = 0.2445`（同一文件里出现两次，后一次覆盖前一次） | 真正生效的是 0.62 那次赋值；旧值只留一句说明 |
| `_drive_unified` | 那是被 `_drive_to_panel` 取代的旧循环副本，里头的常量引用同时属于两套办法，留着只会让"哪个常量属于哪套办法"说不清 |
| `_gn_localize` / `_capture_corr` / `GN_*` 一族 | Gauss-Newton 地图定位。导航改成相对量视觉伺服之后它不再参与决策（只剩像素域标定 `calibrate_pixel_pose` 还在用同一条残差定义） |
| `_zone_of_h` | 旧的"带迟滞判档"包装函数，已经并进 `_zone_at_pixel` 的 `prev` 参数 |
| `_visual_heading_delta_deg` | 旧的"用视觉修航向"，已被弃用（改航向要近轴小量，误差大） |
| `_drive_to_panel_map` / `_approach` / `_enter` / `_confirm` / `do_turn` / `_recover`（v2 地图路径） | 三段式路线里的第二条导航路径，长期没人走 |
| `_small_turn_deg` 的初值 2.0 被当成真值用的那条路 | 保留在线估计（EMA），删掉"信任初值"的写法 |
