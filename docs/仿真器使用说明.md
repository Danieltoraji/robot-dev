# 仿真器使用说明（sim/）

> **本文只回答一件事：现在这套仿真器怎么用**——有哪些入口、怎么看实时画面、
> 怎么批量跑、坑在哪。
>
> 全部命令与数字 **2026-09-25 在 PC 上实跑核对**（Windows / Python 3.13.14 /
> opencv 5.0.0 / numpy 2.5.2 / matplotlib 3.11.1，**在仓库根目录执行**）。
> 关卡方案见 `关卡算法/`；**仿真建模 / 未建模清单以各 `sim/*.py` 模块 docstring
> 为权威源**（改代码时同步改那里，本文不复制细节）。

## 1. 现状速览

| 入口 | 关卡 | 仿真粒度 | 图形界面 | 批量 | 状态（实测） |
|---|---|---|---|---|---|
| `python -m sim.nine_grid_sim` | nine_grid | **图像级**：合成 2592×1944 帧 + 真实内参/畸变，跑真实视觉链路 | ✅ **默认开窗**；`--no-ui` 关窗 | §4 | ✅ 统一决策 7/7、拍照 652、动作 591；`--three-stage` 7/7、拍照 189、动作 167 |
| `python -m sim.goodluck_sim` | goodluck | **位姿桩**：直接给 PnP 真值+噪声，matplotlib 画 2D 轨迹 | ✅ matplotlib（TkAgg，跑完 `plt.show()`） | `python -m sim.run_sim_variants` | ⚠️ 能跑；无参数、**无退出码语义、不可复现**（见 §5） |
| `python -m sim.stairs_hurdle_sim` | stairs_hurdle | 图像级合成帧（红胶条 / 横杆） | ❌ 无 | 无专用工具（用测试脚本的多种子循环） | ✅ `--seed 0`：ok、拍照 31、动作 43 |
| `python tools/record_run.py` | nine_grid | 复用 nine_grid 仿真 | ✅ 加 `--live` 才开窗 | 无（一局一个输出目录） | ✅ 产出 `run.mp4` + 逐帧 PNG |

> ⚠️ **上现场先用 `--three-stage`**：统一决策那条路目前**到达前不做蹭步**
> （`back_one_step` + `go_forward_one_step`），微动开关不一定触发；三段式是
> 一路发到现场、跑通过的那套。
>
> ⚠️ **关卡不再"耗时太长就放弃一格"**（2026-09-25）：本关按 1→7 顺序计分，
> 跳一格等于后面全丢，所以一格没确认就**一直磨这一格**（每次尝试换搜索方向），
> 时间/拍照/动作只打印提醒。仿真这边由**保险丝**
> （`SIM_FUSE_CAPTURES=3000` 张 / `SIM_FUSE_ACTIONS=3000` 次，见
> `sim/nine_grid_sim.py` 模块头）刹车——它是仿真器的实验保护，不是关卡策略；
> 真机上这个角色由人来扮演（Ctrl-C）。

结构约定（别打破）：`sim/` 只提供 **世界 + 传感器 + 带噪声动作**，算法走
`levels/` `vision/` 的**真实代码**；断言在 `tests/`；入口统一
`python -m sim.<关卡>_sim`。

> nine_grid 的**参数全清单**（场景真值 / 相机 / 三套运动原语口径 / 形变注入 /
> 4 个入口的 CLI / 驱动器改写的关卡常量 / 测试护栏）另见
> [`关卡算法/彩色数字九宫格-nine_grid/仿真器参数清单.md`](关卡算法/彩色数字九宫格-nine_grid/仿真器参数清单.md)。

## 2. 无头跑（最快的一遍）

```powershell
$env:PYTHONPATH=(Get-Location).Path   # 或直接 cd 到仓库根
python -m sim.nine_grid_sim --no-ui --seed 3 --quiet
```

| 参数 | 作用 |
|---|---|
| `--seed N` | 动作噪声种子（默认 3）；**加 `--random-layout` 后同时决定随机布局** |
| `--random-layout` | 用 seed 生成合法随机布局（默认用固定 `SIM_LAYOUT`） |
| `--quiet` | 吞掉关卡逐行日志，只留摘要 |
| `--deform SIGMA` | 注入地板形变：每动作俯仰随机游走 SIGMA 度（上限 ±15° / ±2cm；0=无形变） |
| `--three-stage` | 走**三段式**（搜索→对准→接近→到达，现场发货的那套）。**不加就是统一决策**（三档分区＋一个循环） |
| `--no-ui` | 不开窗（默认开窗）。无图形环境时自动退回无窗并说明原因 |
| `--delay MS` | 开窗时每帧等待毫秒数（默认 30；0 映射为 `waitKey(1)`） |
| `--detect` | 运行中也叠检出框（慢 ~25s） |

**退出码**：`0` = 7/7 且布局识别正确；`1` = 否则（含关卡异常）——批量脚本就靠它判。

同一 `--seed`（且布局模式相同）**逐字节可复现**（已核对两次输出完全相同）：
`RandomState(seed)` 是每实例独立的，不走全局 `np.random`。

当前两组数字（seed 3，固定布局）：

| 命令 | 结果 | 说明 |
|---|---|---|
| `python -m sim.nine_grid_sim --no-ui --seed 3` | **7/7、拍照 652、动作 591、exit 0** | 统一决策（默认） |
| `python -m sim.nine_grid_sim --three-stage --no-ui --seed 3` | **7/7、拍照 189、动作 167、exit 0** | 三段式 |

> 统一决策这一组在 **2026-09-25** 由 `6/7、526、480、exit 1` 变成
> `7/7、652、591、exit 0`：那次取消了"单格拍照/耗时超限就放弃这一格"——
> 面板 4 以前在 141 张时被记未确认，现在它会继续磨到确认。
> 顺序计分下这才是对的（跳格 = 后面全丢），代价是拍照张数变多。
>
> 基线护栏在 `tests/test_nine_grid_sim.py`：三段式 `CAPTURE_GUARD = 350`，
> 统一决策 < 900（实测 652）。拍照张数仍是"真机时间预算"的代理指标
> （真机单张 0.62~0.70s），但现在它只报警不停止。

## 3. 带图形界面实时观察

### 3.1 nine_grid（唯一有专门 GUI 的关卡）

开窗就是 `nine_grid_sim` 的默认行为（以前是 `nine_grid_view`，那个入口已删）：

```powershell
$env:PYTHONPATH=(Get-Location).Path
python -m sim.nine_grid_sim                                  # 开窗播完整一局（统一决策）
python -m sim.nine_grid_sim --three-stage                    # 开窗跑三段式
python -m sim.nine_grid_sim --random-layout --seed 11        # 随机布局
python -m sim.nine_grid_sim --delay 0                        # 最快（0 映射为 waitKey(1)）
python -m sim.nine_grid_sim --detect                         # 运行中也叠检出框（慢 ~25s）
python -m sim.nine_grid_sim --no-ui --quiet                  # 无显示器/SSH：只打摘要
```

`sim/nine_grid_view.py` 现在只是**画面库**（`NineGridView` 类 + 绘图函数），
直接 `python -m sim.nine_grid_view` 会提示改用上面这条命令。

窗口内容 = 左**相机窗格**（合成帧 ×0.25：预测面板中心、目标格橙圈、暂停时的检出框
`color→digit`，`C` = 被裁切）+ 右**俯视图**（3×3 格线、真值面板配色、估计映射青圈、
目标橙环、**估计位姿品红 / 真值位姿黑**、估计轨迹尾迹）+ 底**状态栏**
（step/caps/target/phase/fwd/lat/bearing/est_err/last）。

| 键 | 作用 |
|---|---|
| `SPACE` | 暂停 / 继续（暂停时阻塞等键，D/±/H 改完会重绘） |
| `S` | 单步：放行一次拍照 |
| `R` | 重开（seed+1） |
| `Q` / `ESC` | 退出（关窗口也算，不会卡死） |
| `D` | 检出框叠加开关（**暂停/单步时自动开**，运行中默认只画预测以省时间） |
| `+` / `-` | 调速（1~500 ms/帧，默认 30） |
| `H` | 打印按键说明 |

看什么：① 布局扫后青圈是否落在对应数字面板上（错位会画红线）；② 接近段品红与黑圈
是否贴合（`est_err` 就是两者差）；③ `phase` 是否按 SEEK→APPROACH→ENTER→CONFIRM 推进；
④ 卡滞/恢复时轨迹是否打转。

无图形环境时 `_gui_available()` 为假 → **自动**退回无窗并在控制台说明；也可显式
`--no-ui`。窗口内文字一律 ASCII（`cv2.putText` 画不了中文），中文只在控制台。

### 3.2 nine_grid 的"录像版实时观察"（推荐给要回看的场景）

```powershell
python tools/record_run.py --seed 3 --out archive/result/rec_base            # 最快，不开窗
python tools/record_run.py --seed 3 --live --out archive/result/rec_live     # 边录边开窗（可暂停/单步）
python tools/record_run.py --seed 3 --three-stage                            # 换成三段式跑
```

产出 `run.mp4` + `frames/fNNNN.png`（`--every N` 控制取样，`--fps` 控制录像帧率），
**画面与 `nine_grid_view` 完全一致**，且把关卡每一帧的决策日志直接打在终端。
它的画面顶部有 banner：本局 seed / 布局 / 运动原语 / 导航算法 / 到达判据门槛。

### 3.3 goodluck / stairs_hurdle

```powershell
python -m sim.goodluck_sim                 # 开 matplotlib 窗口，跑完 plt.show() 保持
python -m sim.goodluck_sim --corner-stub   # 角点级桩（另有 --decoy 歧义诱饵）
```

## 4. 批量跑

### 4.1 简单循环（要的就是"跑 N 个 seed 看谁挂"）

```powershell
$env:PYTHONPATH=(Get-Location).Path; $env:PYTHONUTF8="1"
foreach ($s in 3,7,11,21,42) {
  python -m sim.nine_grid_sim --seed $s --random-layout --quiet
  "seed=$s exit=$LASTEXITCODE"
}
```

**可以并行**（每个进程独立、确定性互不干扰）。实测 3 局：

| 方式 | 墙钟 |
|---|---|
| 串行 3 局 | 36.8s |
| 3 个进程并行 | **11.3s**（≈3.3×） |

```powershell
# 并行：想跑几个就开几个进程（下面 3 个），日志各自落文件
foreach ($s in 3,7,11) {
  Start-Process python -ArgumentList "-m","sim.nine_grid_sim","--seed","$s","--quiet" `
    -NoNewWindow -RedirectStandardOutput "$env:TEMP\sim_$s.log"
}
```

### 4.2 正式批量：`tools/ab_ninegrid.py`（多种子对照，入版本库）

```powershell
$env:PYTHONUTF8="1"
python tools/ab_ninegrid.py --list                                  # 看有哪些对照组
python tools/ab_ninegrid.py --variants unified three_stage          # 默认 8 个 seed、随机布局
python tools/ab_ninegrid.py --variants unified --seeds 3 7 11 21    # 单组 = 纯多种子批量
python tools/ab_ninegrid.py --variants unified three_stage --primitives real
python tools/ab_ninegrid.py --variants unified \
    --set shared.COLOR_DROP_FRAC=0.75 \
    --json archive/result/ab_drop75.json                            # 不改源码扫常量
```

- 每个 seed 一行统计：自报到达、**仿真确认真值落点**（≤半格 / ≤5.5cm 两档）、
  拍照、动作、布局是否正确、档位计数、动作计数。
- 两个内建对照组就是两套决策办法：`unified`（默认）与 `three_stage`（现场发货）。
- `--set [模块.]NAME=VALUE`：在**内存里**改某个模块的常量（模块 ∈
  `shared` / `level` / `three_stage`，省略则在三个里找唯一命中），自动生成一组新的
  对照（逗号分隔 = 同一组的多个赋值），跑完还原，**不碰仓库默认值**。
- **先证明真的跑了**：任何一组若与基线"逐项相同"，直接标 `INVALID` 且退出码 `2`
  （这是 2026-09-23 两次错判的教训固化成的规则）——报数字前先证明分支真的执行了。
- `--json` 落盘完整结果（含逐格真值落点），后续可用 `tools/_tmp_landing_report.py` 读。

### 4.3 程序内批量（要自己加判据时）

```python
from sim.nine_grid_sim import run_simulation, random_layout
for sd in (3, 7, 11):
    r = run_simulation(layout=random_layout(sd), seed=sd, quiet=True, deform=None)
    s = r.stats      # ok_all / results / layout_ok / captures / actions /
                     # panel_landing（真值落点）/ action_counts / banned_used ...
```

`run_simulation(layout, seed, quiet, viewer, deform, three_stage=False)` 是唯一的
跑一局入口：`viewer=None` 纯无窗，传 viewer 就由 viewer 决定节奏；
`three_stage=True` 走三段式，否则走统一决策。`tools/ab_ninegrid.py` 与
`tools/record_run.py` 都是它的调用方，可直接照抄。

### 4.4 goodluck 的批量

```powershell
$env:MPLBACKEND="Agg"
python -m sim.run_sim_variants ideal|noisy|stress [轮数]
```

⚠️ 两个限制：① 它只贴 `ideal/noisy/stress` 三档噪声，**没有 nine_grid 那样的多种子
统计**；② 结尾的"完成 N/N 轮"**不是成功率**（计数器无条件 +1），要看结果得自己读
日志。goodluck 仿真用全局 `np.random`，**同一命令两次结果不同**，也无法按 seed 复现。

## 5. 环境与坑（Windows PC）

1. **必须从仓库根运行**：`python -m sim.xxx` 依赖 cwd=仓库根（或设 `PYTHONPATH`）。
   直接 `python sim/nine_grid_sim.py` 也能跑（模块内有 sys.path 兜底），
   `python tests/test_nine_grid_sim.py` 同理。
2. **控制台编码**：本机 Python 默认 `stdout=gbk(cp936)`。`tools/ab_ninegrid.py` 的
   `--list` 与告警行含 `⇒`(U+21D2)，**会 UnicodeEncodeError 崩掉**。跑批量前统一加：

   ```powershell
   $env:PYTHONUTF8="1"      # 或不改环境：$env:PYTHONIOENCODING="utf-8"
   ```
3. **默认 seed 与布局**：不加 `--random-layout` 时布局恒为 `SIM_LAYOUT`
   （位置 6/8 空），`--seed` 只改动作噪声——"换 seed"不等于"换布局"。
4. **输出目录**：所有产物写 `archive/result/`（gitignore）。`record_run.py` 会把
   同一 `--out` 目录反复覆盖，批量时给每局独立目录名。
5. **`goodluck_sim` 退出码恒为 0**：它把异常吞在 `run_simulation()` 里再打印
   traceback，**不能靠退出码判成败**；日志文件名的时间戳在 import 时就固定，
   单进程内跑多轮会**互相覆盖**同一个日志文件。
6. **GUI 判定在 `nine_grid_sim` 里**：`_gui_available()` 真的建一次窗口再销毁，
   opencv-headless 构建或无 DISPLAY 时返回 False → 自动退回 `--no-ui`。
7. 仿真**未建模**的东西（真机拍照耗时、舵机到位时间、光照/白平衡、机体遮挡与
   同色杂物、面板物理尺寸误差）见 `sim/nine_grid_sim.py` 模块 docstring 的
   "建模了什么 / 没建模什么"——**别把仿真通过当成真机会过**。
