2. 第一条铁律：shell 脚本一律用 bash

bash debug.sh          # ✅ 正确
./debug.sh             # ✅ 也可以（shebang 是 #!/usr/bin/env bash）
sh debug.sh            # ❌ dash 不支持 set -u → "Illegal option -"
典型报错（已实际踩到）： 
: invalid option: set: -
debug.sh: line 5: cd: $'.\r': No such file or directory
debug.sh: line 9: syntax error near unexpected token `$'in\r''
两半原因：
① invalid option: set: - → 用了 sh（dash），不支持 set -u；
② 满屏 \r → 文件是 CRLF 行尾。Windows 上 core.autocrlf=true 会把工作树 checkout 成 CRLF，而同步工具是逐字节传文件，于是把 CRLF 带上了机器人。
已修：tools/sync_to_robot.py 现在对 .sh/.bash 上传前自动 CRLF→LF 并打印 [行尾] 提示。

3. Python 环境：两个解释器，必须选对

机器人上只有一个 Python 二进制（3.13.5），但有两个不同的“包世界”：

解释器是否可用包集合
/home/pi/jupyter-env/bin/python3 ✅ 我们的代码必须用它 venv site-packages：numpy 2.5.3、cv2 4.14.0、scipy、matplotlib、scikit-learn、scikit-image、joblib、onnxruntime、apriltag、yaml、serial、hiwonder
/usr/bin/python3 ❌ 不要用 Debian dist-packages：有 numpy 2.2.4 / cv2 / serial / smbus / RPi，没有 scipy / apriltag / onnxruntime / sklearn
容易绕晕的一点：/home/pi/jupyter-env/bin/python3 是个软链，指向 /usr/bin/python3 —— 同一个二进制。真正起作用的是 pyvenv.cfg（include-system-site-packages=false），它切换了 sys.path。
所以“看 which python3”分辨不出来，必须看路径前缀。

用法（二选一）

PY=/home/pi/jupyter-env/bin/python3     # 推荐：显式、不依赖 shell 状态
$PY main.py nine_grid

# 或者先激活 venv
source /home/pi/jupyter-env/bin/activate
python main.py nine_grid

4. Python 文件的执行方式（按用途分四类）

先决条件：cd /home/pi/Robot_Competition
所有入口都以仓库根为基准，core.paths.RESULT_DIR 也是相对它计算的。

① 关卡入口 main.py

cd /home/pi/Robot_Competition
/home/pi/jupyter-env/bin/python3 main.py nine_grid
/home/pi/jupyter-env/bin/python3 main.py goodluck
/home/pi/jupyter-env/bin/python3 main.py stairs_hurdle

main.py 的 LEVELS 表只有这三个键。line_seeker_tracking 与 apriltag_sorting_task 不在其中，那两个要直接跑文件（见 ③）。

② tools/ 下的工具 —— 直接给文件路径

/home/pi/jupyter-env/bin/python3 tools/run_layout_scan.py --no-lock --budget 600 --out m5_pos1.json
/home/pi/jupyter-env/bin/python3 tools/field_probe_ninegrid.py
/home/pi/jupyter-env/bin/python3 tools/field_camera_sweep.py --what all
/home/pi/jupyter-env/bin/python3 tools/diag_arrive.py

这些脚本自己做了 sys.path.insert 把仓库根加进去，从仓库根跑即可。

③ levels/ 下未注册的关卡 —— 同样直接跑文件

/home/pi/jupyter-env/bin/python3 levels/line_seeker_tracking.py
/home/pi/jupyter-env/bin/python3 levels/apriltag_sorting_task.py

line_seeker_tracking.py 自己会 sys.path.insert 到 vision/（它 from line_detector import ...），不需要额外操心路径。

④ ❌ 不要用 python -m

/home/pi/jupyter-env/bin/python3 -m tests.test_nine_grid_sim   # ❌ 必失败
两个原因：
① tests/ 没有 __init__.py，不是包；
② 更坑的是 site-packages 里有个同名 tests 包会遮蔽本仓库的 tests/，报 No module named tests.xxx。
PC 上同理，一律用文件路径：python tests\test_nine_grid_sim.py

5. shell 脚本的执行方式

cd /home/pi/Robot_Competition
bash debug.sh              # 启动 debug 镜像 → http://192.168.31.209:8081
bash debug.sh stop         # 停止
bash debug.sh status       # 查看状态
bash debug.sh log          # 查看日志（tail /tmp/debug_server.log）
tools/train/export_onnx.sh        # 训练相关，需 bash
tools/train/train_baseline.sh
  • ⚠️ 别用 sh。
  • ⚠️ 行尾必须是 LF（同步工具已自动转换）。
  • ℹ️ debug 镜像服务不占用摄像头：全文件无 cv2.VideoCapture，唯一碰设备处是网页按钮触发的 fswebcam 子进程（拍完即退）；后台 watchdog 每 0.5 秒只扫盘分析已有 JPEG。测量期间可以开着，只需别点网页上的拍照按钮。

6. 两种操作分工（2026-09-23 定稿）

定稿分工：人全程用 SSH（PowerShell 比网页终端顺手）；AI 用 exec_on_robot.py（Jupyter REST，密码内置，无需额外配置）。 
# ============ 人：SSH（推荐，交互脚本必须走这条）============
ssh pi@192.168.31.209              # 密码 pi；登录 shell 就是 bash，source 可用
cd /home/pi/Robot_Competition
source /home/pi/jupyter-env/bin/activate
which python                       # 应显示 /home/pi/jupyter-env/bin/python

# ============ AI：exec_on_robot.py（走 Jupyter 内核，非交互）============
python tools/exec_on_robot.py --cmd "iw dev wlan0 get power_save"
python tools/exec_on_robot.py --code "print(1+1)"
python tools/sync_to_robot.py --check
python tools/pull_from_robot.py --remote "archive/result/measure_frames" --dest "tests/fixtures/field_photos"
⚠️ 内核没有 stdin：交互脚本（带 input() 的）不能走 exec_on_robot.py
exec_on_robot.py 走的是 Jupyter 内核会话，内核不支持输入请求。凡是停下等输入的脚本 （_tmp_measure_motion.py、_tmp_dist_sweep.py）走它会直接抛：
StdinNotImplementedError: raw_input was called, but this frontend does not support input requests.
所以那两个测量脚本必须由人在 SSH 里跑。AI 若需代跑，只能用管道喂 stdin （printf '值\n值\n' | python tools/xxx.py），已实测可行，但需要人先把测量值报给 AI。
机器人上 python 默认不是 venv —— 这是最容易踩的一条：
默认 python = /usr/bin/python3，它只有 Debian dist-packages （numpy / cv2 / serial / smbus / RPi），没有 scipy / apriltag / onnxruntime / sklearn， 我们的代码跑不起来。
三种解法（任选）：
① source /home/pi/jupyter-env/bin/activate（SSH/bash 下可用；Jupyter 网页终端是 dash，要用 .）；
② 直接用全路径 /home/pi/jupyter-env/bin/python3 <脚本>（最省心，不依赖 shell 状态）；
③ 把 venv 的 bin 前置到 PATH（见下）。
验证：which python 应显示 /home/pi/jupyter-env/bin/python。
可选（一劳永逸，改的是机器人 ~/.bashrc，不碰仓库代码）：让 SSH 一登录就是 venv。 
echo 'export PATH=/home/pi/jupyter-env/bin:$PATH' >> ~/.bashrc   # 追加前先确认没有重复
代价：python/pip 全局都指向 venv。只要不装系统级包就没副作用。
机器人侧默认 shell 的坑：
① SSH 登录 shell 是 bash（source 正常）；Jupyter 网页终端是 dash， source 会报 source: not found → 用 .；
② sh debug.sh ❌（set -u 不支持）→ 用 bash debug.sh。
PC 侧每个新终端都要先设一次： 
$env:PYTHONIOENCODING='utf-8'
原因：PowerShell 自报 OutputEncoding = utf-8，但 chcp 仍是 936（GBK），Python 按代码页决定 stdout 编码。机器人输出里的 ⇒ / ✓ 会让 exec_on_robot.py 在回显阶段抛 UnicodeEncodeError —— 机器人其实已经执行完，只是输出丢了，容易误判成失败。

8. 故障排查：机器人连不上

第一步永远是查 PC 的 WiFi。
必须连 eelab901b 或 eelab901b_2；不能连 Tsinghua-Secure（校园网与机器人不在同一广播域，必然连不上）。 
netsh wlan show interfaces                     # PC：看当前 SSID
ping -n 4 192.168.31.209                       # PC：通不通
Test-NetConnection 192.168.31.209 -Port 8888   # PC：Jupyter 端口
arp -a | Select-String "192.168.31"            # PC：有没有 ARP 条目
症状结论
PC 侧 SSID 不是 eelab901b*先改 WiFi，让其主人手动修正
无法访问目标主机、ARP 无条目设备不在同一广播域（连错网 / 机器人连了副路由）
ping 时好时坏、丢包机器人 WiFi 省电模式（已关并持久化，换镜像后需重做）
一直不通机器人没开机（先看灯 / uptime）
