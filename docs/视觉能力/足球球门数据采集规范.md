# 足球/球门数据采集规范（现场一页纸）

> 依据：《足球与球门识别训练部署方案》§3。给现场拍摄与标注人员的操作清单。
> 采集工具：`tools/data_collect/capture_dataset.py`（机器人端，fswebcam 静态照 2592x1944）。
>
> **实物参数（2026-09-05 确认）**：足球直径约 **6cm**（标准黑白拼块道具球），
> 球门约 **15cm**（白色铁网小门），场地纵深 **≤1m**。
> 因此采集距离全部在 0.2~1m；6cm 球在 1m 处折算到 640 输入只有约 29 像素，
> **远端（0.8~1m）样本必须拍够**，否则远距漏检。

## 1. 拍摄命令

脚本**直接驱动头部舵机**（偏航+俯仰），无需人工摆位。每个场景组合一条命令：

```bash
# 机器人上，项目根目录；一条命令扫过多个偏航档，每个偏航档各拍 count 张
python3 tools/data_collect/capture_dataset.py --scene ball_050 --count 6 --pitch 1150 --head center right left
```

- `--head` 偏航档序列：`center / right / left / wide_right / wide_left`，可一次传多个，脚本逐档转头拍摄（2026-09-05 真机验证舵机模式可用，系统 python3）；
- `--pitch` 俯仰舵机脉宽，脚本直接驱动：**1500=水平，数值越小越低头，可调约 950~2000**；
  **1040=能看到脚下最近地面点，1350=场地一端能完整看到另一端球门**；
  关卡实用档位带为 1040~1350（≥1500 是抬头找 AprilTag 的定位档，不采样）；
- 换距离/换场景时改 `--scene` 与 `--pitch`；同场景续拍用 `--start` 接序号；
- **拍摄前关闭视频流/预览工具**（相机被占用时 fswebcam 静默失败，脚本已加落盘校验会报"拍照异常"）；
- SDK 不可用或显式 `--manual` 时进入人工摆位模式：按提示手动调头，回车继续；
- 照片输出到 `/home/pi/dataset_raw/<场景>/`，拍完用 PC 端
  `python tools/pull_from_robot.py --remote dataset_raw --dest <本地目录>` 一条命令拉回。

## 2. 覆盖矩阵 checklist（逐项打勾）

**摆球方位必须跟着偏航档走**（2026-09-05 FOV 实算：半视场约 33.7°，偏航档 ±40.5°——
**球放正前时 left/right 档看不到球**，摆位错 = 白拍）：

| 偏航档 | 相机朝向 | 球/目标应摆方位（相对机身正面） |
|---|---|---|
| center | 0° | 正前 ±20° |
| right / left | ±40.5° | 该侧前 25°~55°（40~50° 最稳） |
| wide_right / wide_left | ±63° | 该侧前 35°~70° |

> ⚠️ 上表是理想针孔几何，**未含自遮挡**：真机实测（2026-09-05）近距 + 宽扫时
> 视线会被机器人自身肩臂部分遮挡。执行规则：**球部分可见（哪怕只露一半）照拍**
> ——自遮挡是部署时的真实外观，是天然难例；**球被完全挡死才跳过**（那张等于
> 普通负样本，无额外信息量）。遮挡球标注口径见 §4。

**正式采集协议 v2（2026-09-05 定稿，144 张）**：**4 俯仰 × 3 偏航 = 12 个姿态**；
每姿态 = **3 个机器人位** ×（3 个球位各 1 张 + 拿球拍 1 张负样本）= 12 张（9 正 + 3 负）。
常用档加权照旧：1040c/1150c 的 center 实拍已达 20 张/姿态。
（v1 的 35 姿态/420 张保留为可选扩展：基线不达标时按 badcase 补拍或恢复 wide/1300。）
要点：
- 机器人 3 个位置围绕该档标称距离布置（±10cm 内），变的是横向位置与机身朝向；
- 球的 3 个位置必须落在该偏航档的可见方位窗口内（见上表），
  且**纵深刻意变化 ±5~15cm、含 1 个非配对距离**——俯仰是绕光心的纯旋转，
  只改变球在画面中的位置、不改变大小与透视，"同俯仰、远近不同"是真实部署需求
  （接近段固定俯仰走过去，球由远及近），必须覆盖；
- 脚本自动续号：同一命令换球位/机器人位后直接重跑，文件名自动接续（无需 --start）；
  球位之间用 `--interval 6` 的间隔挪球，一条命令拍完 3 个球位；
- 负样本在各自机器人位上顺手拍（拿球即拍，同背景同光照）；
- **常用档位加权**：部署高频档（近中距 1040/1150、对门 1350）比其他姿态多拍
  30~50%（每机器人位多 1 球位或加 1~2 个机器人位）——训练分布向部署分布倾斜；
- **模糊取舍**："框还能画准就留，画不准就删"——轻微模糊是部署真实外观
  （刚停稳就拍），留着；重糊导致框画不准的删除，标注噪声比模糊更伤模型。
  不刻意制造模糊（现阶段停-拍-想-走范式不会边走边拍）。机器人上直接删文件即可，
  自动续号不受影响；
- **错拍处理**：YOLO 中"无标注的图"=负样本——画面里**没球**的错拍（拍空/出画）
  留着无害；画面里**有球**的错拍要么当场删、要么标注时必须标（漏标=主动教错）。
  标注阶段用"模型预标注+人工确认"流程兜底漏标风险。
- **域外保险样本 ball_whitebg（10~20 张，~5%，主体 420 拍完后做）**：白纸/白板垫地
  或靠白墙，center+right 档各 5 张。双重价值：防"绿色背景上下文过拟合"的保险
  （比赛场地/灯光可能有差异）；白底+白球片是真实难例，强化特征。基线训练后
  用未参训的白底图做域外探针：检出正常=模型没依赖绿背景；失败则加入训练重训；
- **畸变应对 = 数据覆盖 + 测量端修正，不做图像去畸变**（2026-09-05 复核维持
  《视觉识别算法详解》§5.2 决策，理由按 YOLO 重新推导）：实算 k1=-0.384/k2=+0.285 下，
  角部小球几乎不变形（各向异性 ~2%）但局部尺度比中心小 ~12%（测距会高估 ~14%）；
  上下中部小球椭圆化 ~13%（恰是固定俯仰接近时球所在位置）。确定性形变由
  画面位置覆盖吸收；测距靠"先居中瞄准 + 现场标定表"吸收，必要时仅对测量值
  加径向修正函数，不改图像。每姿态 3 球位中 1 个贴偏航窗口外缘（wide 档
  55~70°），保证边角/上下边缘样本密度；近距+宽扫组合（如 ball_020 wide）
  正好覆盖画面四角。

可见地面带参考（相机高 39cm、垂直半视场 ±26.5°实算）：1040→0.16~1.47m（近乎全场）、
1150→0.24~4.5m、1250→0.34m~地平线、1350→0.47m~地平线（近端出画）。
配对表是"构图居中 + 近端硬边界"经验，**不是物理一一对应**——非配对距离的球
只是落在画面更高/更低处，仍然可见，且这类组合正是部署所需。

| 维度 | 要覆盖的组合 |
|------|--------------|
| 俯仰 | **4 档：1040 / 1150 / 1250 / 1350**（2026-09-05 v2 定稿；1300 由相邻档+纵深变化覆盖；**不采 ≥1500**——AprilTag 定位档） |
| 偏航 | **3 档：center / right / left**（wide 档移出协议：非常用档+近距自遮挡；已拍的 wide 图保留为附加难例） |
| 距离（球位纵深） | 各俯仰带内取近/中/远 3 档：**1040→0.15/0.25/0.35m、1150→0.35/0.45/0.60m、1250→0.45/0.55/0.70m、1350→0.60/0.80/1.00m** |
| 角度 | 球门正面/左前/右前/侧面；足球各朝向、滚动姿态 |
| 光照 | 室内灯 / 自然光 / 逆光 / 阴影 / 白网反光 |
| 背景 | 浅色墙 / 深色墙 / 地面 / 其它道具 / 空地 |
| 组合 | 球在球门附近、球门内、球门正前方、球被部分遮挡 |
| 负样本 | 无目标空场景，尤其是"像白网/圆形物"的干扰物（占总数 10%~20%） |

**白色铁网球门是头号难例**，以下组合必须单独拍够：

- [ ] 白网正对 / 斜对相机
- [ ] 网孔密集（近距）/ 稀疏（远距）
- [ ] 背景为白墙 / 浅色地面
- [ ] 球门部分出画（只露门框或网的一部分）
- [ ] 室内灯直射造成的网面过曝

## 4. 标注口径（全项目统一）

| 类别 | 类名 | 框法 |
|------|------|------|
| 足球 | `football`（id=0） | 框住整个球体，外接框贴合球边缘 |
| 球门 | `goal`（id=1） | 框住门框+网体整体；**框底边中心=射门瞄准参考** |

**一律不标注（背景）**——2026-09-05 试拍确认的场地元素：

- **AprilTag 地贴**（满场都是）：球与 tag 同框是常态，正常标球即可；
- **球门底部的红色射门判定线**、**上一关的红色循迹线路**：不标注；
- **机器人自身身体入画**（低俯仰档画面底部的前景弧形带）：不标注，保留。

**负样本专项**（防误报的关键，本场地都好构造）：

- [ ] **配对负样本（推荐，零成本）**：每个距离拍完球后把球拿走，换 `_neg` 场景名续拍
      一组（如 `--scene ball_050_neg --count 1 --head center right left`）——
      同背景同光照，只差球不在，是教模型"该背景=空"的最干净样本
- [ ] tag 密集但**无球无门**的空场景（教模型"黑白方块是背景"）
- [ ] **有红色线条但无球门**的场景（上一关循迹场地，教模型"红线≠球门"）
- [ ] 白纸/白胶带等白色干扰物

- 工具：X-AnyLabeling / LabelImg / Label Studio 任选，输出 **YOLO txt**
  （每行 `class x_center y_center w h`，归一化）；负样本不给 txt。
- 提效：第二批起可用上一版 best.pt 预标注（伪标签），人工只做修正。
- 疑难判定：球在门内时球与门**各自独立成框**，不许合并、不许漏标；
  **被遮挡的球（含机器人自遮挡、道具遮挡）按"可见部分的外接框"标注**，
  不猜测被挡部分的边界——口径一致、噪声小，遮挡时测距本就降级为次目标
  （瞄准流程会先移动再重新居中）。
