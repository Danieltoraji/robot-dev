# 视觉识别算法详解

> 本文是 `vision/` 视觉识别能力的**算法原理权威文档**，详细介绍四个检测器各自的算法。
> 用法见《视觉接入说明.md》，调参见《视觉调试指南.md》，架构背景见《视觉识别能力规划.md》。

## 0. 总览与选型

| 检测器              | 文件                  | 返回              | 算法类别           | 一句话原理                              |
| ------------------- | --------------------- | ----------------- | ------------------ | --------------------------------------- |
| `LineDetector`      | `line_detector.py`    | `LineResult`      | 传统 CV + 几何拟合 | 中心线提取 + 骨架化 + 二次拟合 + 纯追踪 |
| `ColorBlobDetector` | `color_detector.py`   | `list[Detection]` | 传统 CV            | HSV 阈值 + 轮廓 + 圆形度                |
| `DigitRecognizer`   | `digit_recognizer.py` | `DigitResult`     | 传统 CV            | 连通域分割 + 模板匹配                   |
| `YoloDetector`      | `yolo_detector.py`    | `list[Detection]` | 深度学习           | 单阶段 CNN 目标检测（本地/远程双后端）  |

**选型原则**：传统 CV（颜色/形状/模板）打底——确定、可解释、RPi 可跑；YOLO 补盲——用于外观多变、难用颜色形状描述的目标；数字复杂场景外接现成 OCR。

## 1. LineDetector —— 巡线

### 1.1 要解决的问题

单质心方案在以下场景失真，本算法逐一对治：

| #   | 问题                       | 病根                     | 对策                             |
| --- | -------------------------- | ------------------------ | -------------------------------- |
| 1   | 小半径曲线跑出「割线中点」 | 质心=整段弧的重心=弦中点 | 中心线 + 拟合 + 前视点落在曲线上 |
| 2   | 密集折角描述不了           | 拐角处多段线被平均       | 直线度判 corner，走离散转向      |
| 3   | 横向线 → 震荡              | 横线硬去跟               | 分类 cross，不跟随               |
| 4   | 分割线上线段算两次         | 近/远分段双计            | 无分段，整条追踪                 |
| 5   | 一个 y 对应多个 x          | 用行(y)当参数            | 弧长参数化，与行列无关           |

### 1.2 流水线

```
二值掩膜 → 连通域分割 → 骨架化 → 弧长参数化 → 坐标变换+拟合 → 分类 → 纯追踪输出
  Step0      Step1        Step2      Step3          Step4         Step5      Step6
```

### 1.3 Step 0：二值掩膜（白=线）

- **灰度模式**（`hsv_range=None`）：`BGR→灰度` + 阈值。黑线用 `THRESH_BINARY_INV`（暗像素→白），白线用 `THRESH_BINARY`；`thresh=None` 时用 OTSU 自动求阈值。
- **颜色模式**（`hsv_range` 给定）：`BGR→HSV` + `cv2.inRange` 抠目标色像素。
  - **红色两段自动合并**：OpenCV 的 HSV 用 8 位存 hue，把 0~360° 压到 0~180，红色因此被劈成 `h∈[0,~10]` 与 `[~170,180]` 两段。当给定范围 hue 下界 ≤8 且上界 ≤20 时，自动补 `170~180` 段做第二次 `inRange` 并 OR 合并，否则只命中一半红色。

### 1.4 Step 1：连通域分割

`cv2.connectedComponentsWithStats(mask, 8)` 把互不相连的线拆成独立组件，`min_area` 过滤噪点。解决「双竖线被平均」「横竖线混一起」——每条线先被拆开，之后各自独立处理。

### 1.5 Step 2：骨架化（Zhang-Suen 细化）

把粗带退成 1px 中轴，保留连通性与长度。Zhang-Suen 是**迭代剥皮**算法：每轮删掉「删了也不会断线、不削短端点」的边缘像素，直到无可删。

对前景像素 P1，记 8 邻域（P2 在正上方，顺时针）：

```
P9 P2 P3
P8 P1 P4
P7 P6 P5
```

定义：
- `B(P1)` = P2+…+P9 = 非零邻居数；
- `A(P1)` = 序列 P2,P3,…,P9,P2 中「0→1」跳变次数（骨架像素应是 1 次，保证不产生空洞/断点）。

**子迭代 1**（删 P1，需同时满足）：`2 ≤ B ≤ 6` 且 `A = 1` 且 `P2·P4·P6 = 0` 且 `P4·P6·P8 = 0`
**子迭代 2**（删 P1，需同时满足）：`2 ≤ B ≤ 6` 且 `A = 1` 且 `P2·P4·P8 = 0` 且 `P2·P6·P8 = 0`

两子迭代交替进行，直到整轮无像素被删。实现为纯 numpy 向量化（`_zhang_suen`），无额外依赖。

### 1.6 Step 3：弧长参数化（骨架追踪）

对骨架每个像素数 8 邻域：**1 = 端点，2 = 普通点，≥3 = 分支点**。

- 从每个端点出发，沿「唯一未访问邻居」逐步行走，直到另一端点/分支点，得到**沿线有序点列**；
- 分支点处断开成多段；闭合环（无端点）从任意未访问点绕一圈。

关键：点列顺序**只取决于线本身走向，与图像行(y)无关**——「一个 y 对应多个 x」从此消失。

### 1.7 Step 4：坐标变换 + 二次拟合

- 机器人系：`rx = x − roi_w/2`（右正）、`ry = roi_h − y`（前正，0=机器人处）。
- 对 follow 线做最小二乘二次拟合 `rx = a·ry² + b·ry + c`（`np.polyfit(ry, rx, 2)`）：

| 系数 | 物理含义                   | 字段          |
| ---- | -------------------------- | ------------- |
| `c`  | 机器人处横向偏移（拟合值） | 参考          |
| `b`  | 切线斜率，切线角 = atan(b) | `heading_deg` |
| `a`  | 曲率（右弯正）             | `curvature`   |

实际输出的字段与拟合系数的对应关系（避免外推爆炸，做了一致性回退）：

| 字段             | 取值方式                                             | 说明                                                           |
| ---------------- | ---------------------------------------------------- | -------------------------------------------------------------- |
| `lateral_offset` | 最近点实测 `rx`（`argmax(ry)`）                      | 不取拟合 `c`；拐角/短线段处更可靠                              |
| `heading_deg`    | follow=`atan(b)`；corner=近臂弦向角                  | 右正左负                                                       |
| `lookahead_x`    | 拟合 `a·L²+b·L+c`，超 `LOOKAHEAD_CLAMP` 回退实测插值 | 拐角处不可靠                                                   |
| `far_ry`         | `ry.max()`（线最远端的前向像素距离）                 | 线延伸到视野尽头≈`roi_h`；线末端进入视野时显著变小，供终点判定 |

**为什么二次够用**：任何光滑曲线在机器人附近泰勒展开截到二阶即二次。ROI 短到「这段线在眼前就是直线/单向弯」时二次精确够用；S 形弯或直角靠缩短 ROI + 分类兜底，不靠升次数。

### 1.8 Step 5：分类（follow / cross / corner）

分类顺序：**先肘部弦角检测判 corner，再用方差方向判 follow/cross**。

**肘部检测**（`_find_elbow`，corner 主判据）：沿有序点列滑窗，对每个候选肘点取
两侧各 `ELBOW_WINDOW` 个点的弦向向量，求夹角；夹角 > `ELBOW_ANGLE_THRESH`（45°）
即认定为拐角。臂长用「肘点到段端点的全弧长」（骨架点间距≈1px）：
近臂阈值低（`ELBOW_MIN_NEAR_ARM_PX`，机器人可贴近拐角）、远臂阈值高
（`ELBOW_MIN_FAR_ARM_PX`，排除噪声毛刺）。取**最近端第一个**满足条件的肘部
（近拐角优先）。L 形拐角的两臂靠「分支点沿当前行进方向继续走」留在同一条点列里。

| 分类     | 判据                                  | 处理                             |
| -------- | ------------------------------------- | -------------------------------- |
| `corner` | 肘部弦角 > 45°                        | 离散转向（接近→定点转→出口确认） |
| `follow` | 无肘部 且 竖直方差 ≥ 水平方差         | 拟合 + 纯追踪跟随                |
| `cross`  | 无肘部 且 水平方差 > 竖直方差（横线） | 不跟随，交关卡（停止/跨越）      |

`corner` 转向方向（`curvature`）：远臂末端相对肘点的横向符号（右=+1，左=−1）。
`corner` 的 `elbow_px`（肘点图像坐标）纵向分量编码**拐角距离**（越大越近），
关卡据此「前进接近到拐角脚下再定点转弯」。

另设**拟合 RMS 兜底**：follow 拟合后 `rms > FIT_MAX_RMS` 改判 corner（方向用远/近端点 x 符号），
防止把折线硬拟合成二次曲线。`straightness` 保留作 `confidence` 输出。

### 1.9 Step 6：纯追踪前视点

在拟合曲线上取「机器人前方 L 处」一点：`lookahead_x = a·L² + b·L + c`，其中 `L = lookahead_ratio × roi_h`。

前视点落在**曲线上**而非弦中点 → 小半径曲线能正确「切弯」；带前馈，比直接追偏移更稳。

### 1.10 决策映射（量 → 动作，关卡层 `levels/line_seeker_tracking.py` 实现）

**循迹主循环**（`track_line`）按 `primary.orientation` 分派：

| 信号状态                                         | 动作                                                |
| ------------------------------------------------ | --------------------------------------------------- |
| `orientation == "corner"`                        | 走「拐角三阶段」：前进接近 → 定点转弯 → 出口确认    |
| `orientation == "cross"`                         | 前进跨越（连续超 `CROSS_MAX_CONSECUTIVE` 次回寻线） |
| `follow` 且 `far_ry < LINE_END_FAR_RY`           | 终点前进（线末端接近，前进到尽头停止）              |
| `follow` 且 `\|lookahead_x\| > T_BIG`            | 左/右转（修朝向）                                   |
| `follow` 且 `T_CENTER < \|lookahead_x\| ≤ T_BIG` | 左移 / 右移（横移对齐）                             |
| `follow` 且 `\|lookahead_x\| ≤ T_CENTER`         | 前进                                                |
| `exists == False`                                | 后退找线（超 `TRACK_MAX_BACKS` 回寻线）             |

**拐角三阶段**（`_handle_corner`）：
1. **前进接近**：检测到 corner 时拐角可能仍在视野远端（D_FAR≈35cm），
   先前进直到 `elbow_px.y ≥ CORNER_APPROACH_Y`（或检测到 cross），保证转弯时拐角在脚下。
2. **定点转弯**：左弯 4×22°=88°、右弯 3×25.7°=77.1°（略欠转，避免超转导致线跑到侧后方）。
3. **出口确认**：累计角足够后看到 follow 线即认为弯已转过（横向/朝向误差交给对齐阶段）。

**对齐阶段**（`_align_to_line`，过弯后/寻线后统一收敛）优先级：

| 信号状态                                 | 动作                                                                           |
| ---------------------------------------- | ------------------------------------------------------------------------------ |
| `corner`                                 | 按其方向转一次（seek 上下文则直接进入循迹）                                    |
| `cross`                                  | 前进跨越                                                                       |
| `follow` 且 `\|heading\| > 25°`          | 先转向拉正线（大幅欠转时线严重倾斜，最近点与远前视点横向方向相反，横移会振荡） |
| `follow` 且 `\|lateral\| > T_LAT(40)`    | 横移对齐（拐角处 lateral 可靠）                                                |
| `follow` 且 `\|lookahead_x\| > T_CENTER` | 横移对齐                                                                       |
| 居中                                     | 完成                                                                           |

判定顺序的关键：**大幅欠转（heading>25°）必须先转向**，否则线倾斜时横移会在
lateral 与 lookahead 之间左右反复（如 P3 弯后 lateral=+56 而 lookahead=−58，右移左移互相抵消）。

### 1.11 参数与局限

构造参数：`line_color` / `thresh` / `hsv_range` / `hsv_ranges` / `roi_ratio` / `min_area` / `lookahead_ratio` / `work_width`。
算法内常量：`ELBOW_ANGLE_THRESH` / `ELBOW_WINDOW` / `ELBOW_MIN_NEAR_ARM_PX` / `ELBOW_MIN_FAR_ARM_PX` / `FIT_MIN_RY_SPAN` / `FIT_MIN_POINTS` / `FIT_MAX_RMS` / `LOOKAHEAD_CLAMP`（详见《视觉调试指南.md》）。

局限：连续小半径曲线与密集折角受车长/步进/转弯半径限制，应「跟随段 + 拐角触发转向 + AprilTag 定位兜底」；corner 方向假设「线从底部来、向一侧折」；交叉处按分支点断成多段；`lookahead_x` 在拐角/短线段处不可靠，改用 `lateral_offset`。

## 2. ColorBlobDetector —— 颜色 / 球体

### 2.1 原理概述

把「找目标」变成「按颜色抠图 + 几何度量」：先用 HSV 阈值把目标颜色的像素抠出来，再用轮廓量出位置与「圆不圆」。

### 2.2 颜色空间：BGR → HSV

BGR 三个通道都含亮度，光照一变三个都变，阈值难设。HSV 把颜色拆成：

- **H（Hue 色相）**：颜色类型，0~360°（OpenCV 存 0~180）；
- **S（Saturation 饱和度）**：颜色纯度，0~255；
- **V（Value 明度）**：亮度，0~255。

**关键**：目标「是什么颜色」几乎只由 H 决定，受阴影影响的主要是 V。因此对 H、S 设窄阈值、对 V 设宽阈值，就能在光照变化下稳定命中同一颜色。

### 2.3 阈值分割：cv2.inRange

对每个像素，若 `h_L ≤ H ≤ h_H` 且 `s_L ≤ S ≤ s_H` 且 `v_L ≤ V ≤ v_H` 则置白，否则置黑：

```
mask = (lower_h ≤ H ≤ upper_h) ∧ (lower_s ≤ S ≤ upper_s) ∧ (lower_v ≤ V ≤ upper_v)
```

得到二值掩膜，白色 = 目标颜色。

### 2.4 形态学开运算

`erode`（腐蚀）再 `dilate`（膨胀）＝ 开运算：消除孤立噪点、断开细的连接，不改变主体大小。

### 2.5 轮廓 + 面积过滤

`findContours(RETR_EXTERNAL)` 找每个连通域的轮廓；`contourArea < min_area` 的丢弃；`boundingRect` 得外包矩形 `(x, y, w, h)`，中心 `(x+w/2, y+h/2)`。

### 2.6 圆形度（判断「是不是球」）

```
circularity = 4π·A / p²     （A=面积，p=周长）
```

- 完美圆 = 1.0；正方形 ≈ π/4 ≈ 0.785；越扁越小。
- 作为 `Detection.confidence` 输出，关卡设阈值（如 `>0.7`）判断「确实是个球」。

### 2.7 参数与局限

参数：`hsv_range`（颜色范围）、`label`（类别名）、`min_area`。

局限：颜色接近的物体误检；光照剧变时 H/S 仍可能漂移，需现场标定；圆形度只能分「圆 vs 不圆」，分不出「球 vs 圆盘」（那是立体问题）。

## 3. DigitRecognizer —— 数字识别

### 3.1 原理概述

「把每个数字切出来，再和模板比相似度」：二值化 → 连通域分割 → 左到右排序 → 归一化 → 模板匹配。

### 3.2 二值化 + OTSU

灰度化后 `THRESH_BINARY_INV`（暗字白底 → 白字黑底）。`thresh=None` 用 **OTSU 大津法**自动选阈值：

把像素按阈值 t 分成两类 C0/C1，类间方差 `σ_b²(t) = ω0·ω1·(μ0 − μ1)²`（ω=类占比，μ=类均值），选使 `σ_b²(t)` 最大的 t*。类间方差越大，说明两类分得越开，阈值越好。

### 3.3 连通域分割 + 排序

`findContours` 把每个数字切成独立连通域，`min_area` 过滤噪点；按 **x 从左到右**排序，保证「42」读成「42」而非「24」。

### 3.4 归一化

每个数字连通域 `resize` 到统一 28×28，消除尺度差异，使模板匹配不受数字大小影响。

### 3.5 模板匹配：TM_CCOEFF_NORMED

与每张模板算归一化互相关：

```
R = Σ(T'·I') / sqrt( Σ T'² · Σ I'² )
其中 T' = T − mean(T)，I' = I − mean(I)
```

`R ∈ [−1, 1]`，1 = 完全匹配。因为分子分母都做了去均值，该度量对**线性光照变化（整体变亮/变暗）不变**——所以模板和待匹配都用白字黑底即可。每个数字取 `R` 最大的模板字符，拼成 `digits`；`confidence` = 各数字分数的均值。

### 3.6 参数与局限

参数：`templates`（{字符: 模板图}，关卡注入）、`thresh`、`min_area`。

局限：模板对**字体/字号/旋转**敏感，换字体需换模板（`gen_digit_templates.py` 生成）；**粘连数字**（两数字连一起）会被当成一个框。**升级路径**：若现场字体/光照复杂导致模板不稳，用同一 `detect()` 接口换成 OCR（PaddleOCR/Tesseract）或小 CNN 后端，关卡零改动。

## 4. YoloDetector —— YOLO 目标检测

### 4.1 单阶段检测原理

YOLO（You Only Look Once）把检测当作**单次前向的回归问题**，与两阶段（先提区域再分类，如 R-CNN）相比更快。

1. **网格划分**：输入图缩放到固定尺寸（如 640×640），划分成 S×S 网格；
2. **每个网格预测 B 个边界框 + C 个类别概率**，每个框输出：
   - 中心相对网格的偏移、宽高相对 anchor 的比例；
   - **置信度** `= P(object) × IoU(pred, truth)`（有目标 × 框准不准）；
   - 类别概率 `P(class_i | object)`（给定有目标时属于哪类）；
3. **最终得分** = 置信度 × 类别概率；
4. **NMS 非极大值抑制**：按得分排序，去掉与高得分框 IoU 超过阈值的重叠框（`IoU = 交集面积 / 并集面积`）。

训练靠标注框的**定位损失 + 置信度损失 + 分类损失**共同优化，特征由 CNN 自动学得——因此鲁棒性强，但依赖训练数据、对训练域敏感。

### 4.2 本地后端 `LocalYoloBackend`

`ultralytics.YOLO(model_path)` 懒加载模型，`predict(frame, conf, iou, device)` 推理，解析 `r.boxes` 成 `Detection`。RPi 上优先用 n/s 小模型或 onnx/int8 量化。

### 4.3 远程后端 `RemoteYoloBackend`

`cv2.imencode(".jpg")` 编码 → `urllib` POST 原始 JPEG（`Content-Type: image/jpeg`）到算力端（KV260/PC 的 Flask），返回 JSON：

```json
{"detections": [{"cls": "ball", "confidence": 0.9, "bbox": [x, y, w, h]}, ...]}
```

网络异常时打印告警并返回空列表。**切换后端只换 `backend` 对象，关卡代码不变。**

### 4.4 训练 / 微调

比赛道具通常不在 COCO 等公开类别里，应「**预训练底座 + 自定义小数据集微调**」，而非从零训练。远程算力端统一部署权重，供多关卡复用。

### 4.5 参数与局限

参数：本地 `model_path` / `conf` / `iou` / `device`；远程 `url` / `timeout`。

局限：需要标注数据；换场地/光照可能退化；黑盒难现场排查；RPi 本地推理慢。**适用**：障碍物、复杂道具、外观多变的标识等难以用颜色/形状描述的目标。

## 5. 公共议题

### 5.1 内参 K 与畸变

- **内参 K**（焦距 fx/fy、主点 cx/cy）只在「像素 ↔ 物理坐标」换算时使用，**识别阶段完全不碰**。
- **畸变**（k1≈−0.384 桶形）只在画面**边缘**明显，中心（主点附近）≈0。

### 5.2 识别前是否去畸变

| 任务                                                       | 是否去畸变                                        |
| ---------------------------------------------------------- | ------------------------------------------------- |
| 纯分类 / 存在性 / 左右判断（巡线偏移、有没有球、数字是几） | ❌ 不去                                            |
| 形状度量（圆形度/模板匹配）且目标可能在边缘                | ⚠️ 局部去（`undistortPoints` 或裁局部）            |
| 像素 → 世界坐标投影（`world_xy`）                          | ✅ 必须去；或复用现有 `solvePnP`（已内置畸变系数） |

**结论**：识别一律在像素空间做，默认不去畸变；只有「形状度量在边缘」和「要 world_xy 投影」两处才校正。全图 `cv2.undistort` 在 2592×1944 上代价高且引入黑边伪影，不值。

### 5.3 传统 CV vs YOLO 选型

| 任务                       | 用谁                              |
| -------------------------- | --------------------------------- |
| 巡线、颜色球体、规整数字   | 传统 CV（毫秒级、免训练、可解释） |
| 障碍物、复杂道具、多变标识 | YOLO（或外接模型）                |

### 5.4 外接现成模型

- 数字：优先现成 OCR（PaddleOCR/Tesseract）；
- 目标检测：预训练 YOLO 底座 + 微调；
- 两者都走已有 `backend` 接口（`RemoteYoloBackend` 即「外接任意服务」的钩子）。
