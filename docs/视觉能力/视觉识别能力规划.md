# 视觉识别能力规划（YOLO 等）

> 目标：在不破坏「core / 关卡 / 模拟」三层架构与「core 宁少勿多、关卡自治」原则的前提下，
> 为机器人加入 **YOLO 目标检测、巡线、数字识别、颜色/球体识别** 等通用视觉能力，
> 为攻克尚未确定的其它关卡做能力储备。
>
> 📌 **当前状态：已实现**。`vision/` 包 + 四个检测器 + 取帧入口 + 模拟器桩 + 调试工具均已落地，
> P1~P4 完成、P5（实机关卡接入）待做。实现细节见《视觉识别算法详解.md》（算法原理）、
> 《视觉接入说明.md》（调用）、《视觉调试指南.md》（调参）。

---

## 1. 背景与目标

现有 `goodluck` 关卡只用了一种视觉能力：**AprilTag + PnP 定位**（`core/robot_core.py` 的 `solve_pnp`）。
其余关卡大概率需要新的「识别」能力，而不是「定位」。已知方向：

- 巡线（沿地面线走）
- 识别数字（地面/标牌数字）
- 识别球体（彩色球）
- 通用目标检测（YOLO，识别道具/障碍/标识等）

**目标**：把这批能力做成「**core 层的通用基础能力**」，供任意关卡按需选用；识别结果的**语义解释与决策**仍留在关卡层，避免跨关卡混乱。

---

## 2. 能力清单

| 能力 | 检测器 | 输出 | 技术方案 | 部署 | 状态 |
|------|--------|------|---------|------|------|
| 巡线 | `LineDetector` | 中心线分类(follow/cross/corner) + 前视点 | 中心线 + 骨架化 + 拟合 + 纯追踪 | RPi 本地 | ✅ |
| 颜色/球体 | `ColorBlobDetector` | 位置 + 圆形度 | HSV 阈值 + 轮廓 | RPi 本地 | ✅ |
| 数字识别 | `DigitRecognizer` | 数字串 + 置信度 | 连通域分割 + 模板匹配 | RPi 本地 | ✅ |
| 目标检测 | `YoloDetector` | 类别 + 置信度 + 包围盒 | YOLOv8 本地/远程双后端 | 远程优先 | ✅ 骨架 |

## 3. 架构设计

### 3.1 分层原则（与 AprilTag 定位一致）

1. **基础能力入 core**：检测器接口 + 通用检测器 + 拍照链路 → `vision/` 包 + `robot_core.capture_frame()`。
2. **关卡自治**：关卡**选**检测器、**配**阈值、**写**决策。
3. **模拟可覆盖**：`SimRobotState` 覆盖 `capture_frame()` 返回合成帧，检测器零改动。

> 关键类比：core 给 `locate_with_retry()`（定位能力），关卡在 `navigate_to_target` 里决定怎么用位置；
> 同理 core 给「检测器」，关卡决定「检测到 X 后怎么走」。

### 3.2 实际目录结构（已实现）

```
robot-dev/
├── core/
│   └── robot_core.py        # RobotState：capture_frame() 取帧入口（复用拍照链路）
├── vision/                  # 视觉识别包（core 侧通用能力）
│   ├── __init__.py          # Detector 接口 + 数据模型导出
│   ├── detection.py         # Detection / LineSegment / LineResult / DigitResult
│   ├── line_detector.py     # 巡线
│   ├── color_detector.py    # 颜色/球体
│   ├── digit_recognizer.py  # 数字（模板匹配 tier1）
│   └── yolo_detector.py     # YOLO（本地/远程双后端）
├── tools/
│   ├── debug_vision.py        # 离线调参工具
│   └── gen_digit_templates.py # 数字模板生成
├── levels/
│   └── goodluck.py          # 现有关卡（不依赖 vision）
└── sim/
    └── goodluck_sim.py  # 模拟器：SimRobotState.capture_frame() 桩
```

> 说明：早期规划里的 `robot_vision.py` 未单独建，改为 `vision/` 包 + `core.robot_core.capture_frame()` 一个入口，更贴合「宁少勿多」。

### 3.3 挂载方式（实际）

`RobotState` 只新增**一个**方法 `capture_frame()`（取帧）；检测器是**独立无状态类**，关卡直接构造并使用：

```python
from vision.line_detector import LineDetector

line = LineDetector(hsv_range=..., roi_ratio=0.5)
lr = line.detect(state.capture_frame())
```

这样 `RobotState` 保持精简，检测器可插拔，换检测器/换后端/仿真替换都无感。

## 4. 数据模型与接口

数据模型见《视觉接入说明.md》§3：`Detection`（通用目标）、`LineSegment` + `LineResult`（巡线）、`DigitResult`（数字）。
检测器统一实现 `detect(frame)` 方法，返回各自的结果类型。

| 能力 | 变换方式 |
|------|---------|
| 巡线 | 纯像素：`lookahead_x`（前视点横向偏移）作误差量 |
| 颜色/球体 | `center_px` + bbox 大小估距 |
| YOLO 目标 | 画面有 AprilTag 时复用 `solve_pnp` 求位姿再投影 |
| 数字 | 只需读出 + 大致方位 |

## 6. YOLO 双后端（本地 / 远程异构）

`YoloDetector(backend)` 持有后端之一，`detect()` 委托给后端：

| 后端 | 实现 |
|------|------|
| `LocalYoloBackend` | ultralytics 懒加载，`model_path` / `conf` / `iou` / `device` |
| `RemoteYoloBackend` | urllib POST 原始 JPEG（Content-Type: image/jpeg）到算力端 Flask，返回 JSON |

切换只换 `backend` 对象，关卡代码不变。

## 10. 风险与缓解

| 风险 | 说明 | 缓解 |
|------|------|------|
| RPi 算力不足 | YOLO 本地推理慢、帧率低 | 小模型 + 量化；重活走远程后端 |
| 网络/延迟（远程后端） | 图片传输 + 推理增加延迟 | 子线程异步发送，主线程不阻塞；必要时降分辨率 |
| 光照/颜色漂移 | HSV 阈值换场地后失效 | 阈值关卡化 + 现场标定 |
| 跨关卡混乱 | 检测器/阈值散落各关卡 | 检测器集中 core 侧；阈值与决策归关卡 |

---

## 11. 一句话总结

> 视觉识别已落地为「core 侧 `vision/` 包（统一接口 + 可插拔检测器）+ `capture_frame()` 取帧 + 双后端」，
> 关卡只做「选检测器 + 配阈值 + 写决策」，模拟器覆盖 `capture_frame()` 返回合成结果。
> 既复用现有分层与 override 机制，又守住「core 提供基础能力、关卡自治、无跨关卡混乱」的边界。
