# 共面歧义治理（C3 架构）+ 危险区兜底（修复 A）

## Step 0：真机数据歧义普查（离线，只读已有 npz）
用 12 站位数据对每帧做 IPPE 双支枚举，统计：
- 双支位置间隔分布（定阈值：预期 4cm 附近，以触发率 <20% 为准）；
- 过全部门控后活分支数（验证"多数帧只有一支活"的设计假设）；
- ITERATIVE 单解落在哪支、与 survey 站位真值的偏差（量化真实错误率）；
- 期望选支策略在序列帧上的回放正确率。
**产出：阈值定值 + 设计假设的实证确认。若假设被推翻（如活分支几乎总是两支），回来修订方案再施工。**

## Step 1：修复 A（已批准）——危险区最优一步兜底
decide_panning_action 加 escaping 参数；escaping 且全候选被 13cm 过滤排除时，返回"预测离墙距离最大"的动作而非 None。危险区内永不按兵不动。

## Step 2：C3 三层歧义治理（robot_core._locate_pose_once + locate_with_scan）
1. **门控筛分支**：共面帧改用 frame_pose_candidates（IPPE）枚举两支，每支独立过全套门控；仅一支活 → 接受（多数情况，零额外成本）。
2. **期望选支**：两支都活且间隔 > 阈值(Step 0 定)时，若存在位置期望且能干脆区分（近支在预算+裕度内、远支在外、边距>2cm）→ 选近支，双距离写日志 `[歧义消解] A支距期望x.xcm / B支x.xcm，选X`。
3. **联合裁决**：区分不开/无期望/两支均在外 → 本档结果暂存（两支都缓存），继续扫描下一档；两帧在手后跑 solve_joint_3dof（标定外参）仲裁，联合过门控则采用；仍失败回落到现有全档流程。多平面帧完全跳过整套逻辑（几何无歧义）。
4. 帧救援路径（逐标签剔除子集）同样经 IPPE 枚举，规则一致。

## Step 3：验证
1. 事故重放单测：合成真值 (32,40) 朝北的 153+154 帧（带实测幅度的标签不一致扰动），验证三层逻辑选中 ~32 而非 ~37.4；上次 (22,38)/(34,41) 场景同样重放。
2. 期望失效场景：无期望（首轮定位）时两支都活 → 走联合裁决路径。
3. 角点桩全程回归 + 消歧/帧救援既有单测复跑；对比定位次数（C3 额外拍照应 <20% 帧，耗时影响 <15s）。
4. 完成后同步 robot_core.py + levels/goodluck.py，等你真机验证。

## 不做
- 恒多帧联合（C4，速度不可接受）、航位推算期望（C2，列入二期）、任何"否决类"逻辑、门控阈值调整、你手调的 OBSTACLE=13 与 bypass。

## 风险与边界
- 联合裁决依赖外参与标签一致性（~5px 地板）——对 4~5cm 级歧义分辨裕度充足；
- 额外拍照的触发率由 Step 0 实测控制，若真机 trace 显示超预期（>30% 帧），升阈值或收紧"干脆区分"的边距；
- 两支均在外（真实跳变/被搬动）时交由联合层处理，不做历史否决。
