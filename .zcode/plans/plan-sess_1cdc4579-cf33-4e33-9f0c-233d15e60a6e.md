# 红绿灯控制关卡 · 预研报告

> 参考材料：`reference code/红绿灯控制/` —— README.md（规则最全）、关卡说明书 docx、机器人端 baseline `traffic_light_complete.py`（642 行）、评分端 `scoring_system.c`（ESP32 固件）
> 结论一句话：**这是一场"响应延迟"考试**。baseline 是一份"参数宝库、架构反面教材"——它的现场调参可直接继承，它的取流/去抖/决策链路需要按本仓库架构重写为 `levels/traffic_light.py`。

## 0. TL;DR

1. 灯环随机循环**红 15~18s → 绿 2~4s → 黄 3s**；绿灯窗口最短仅 2s；红灯亮起 1s 后移动 >3cm 即扣 3 分。谁的"看见→动作"链路快、停车刹得住，谁得分。
2. baseline 致命伤：每帧开关摄像头（秒级延迟）、1 帧确认无去抖、unknown 锁存不自愈、"检测不到 Tag 就直接冲"高危分支、过线后纯开环 12 快步。
3. 我方路线：复用仓库分层（RobotState 标定内参 PnP 测距、ColorBlobDetector、已标定步长表），识别改多帧投票，运动改**三段降速**（巡航→慢凑→2cm 小步蠕行，末段单步位移 <3cm 免罚阈值），过线判定后**无条件冲刺不再看灯**；新增**黄灯识别**吃掉"错过绿灯后的第二次通行机会"。
4. 头号待解矛盾：仓库主链路 fswebcam 拍 2592×1944 实测 2~4s/张，与 2s 绿灯窗口冲突。首选实测 fswebcam 降 640×480 单帧耗时（预期 <1s，且保住 debug_server 被动镜像链路）；不达标切 V4L2 常驻流+定期落盘。

## 1. 关卡要求

### 1.1 场景与任务（docx + README）

模拟城市路口：场地 1m×1m、赛道前后贯通，依次为入口 → 接近段 → 停止线（黑线 + **AprilTag ID 75**）→ 信号灯（WS2812B 16 灯珠灯环）→ 出口。机器人从入口驶入，按"**自身相对停止线位置 × 灯色**"决策：

- **停止线前**：红灯停车等待，绿灯安全通行，黄灯可通行；
- **停止线后**：直接通行不受灯色影响——docx 特别强调"**不能在红灯时依旧停止**"。

考察能力（docx）：动态信号灯感知（时序随机）、精确停车控制、车辆三态位置判断（未到线/在线上/已过线）、响应延迟（绿灯响应越快越好）。

### 1.2 评分规则（满分 10 分，扣分制）

| 评分项 | 分值 | 扣分条件 | 扣分 |
|---|---|---|---|
| 入口识别 | 1 | 触发即得 | — |
| 红灯停车 | 5 | 未到线时，红灯亮 **1s 后**移动 **>3cm**（线上移动不扣） | 首次 -3，再犯 -2（至多 2 次） |
| 绿灯通行 | 1 | 绿灯亮起后静止 <0.3cm 持续 >1s（前 3 次有效数据为稳定期） | -1（仅一次） |
| 过线后通行 | 2 | 已过线后红灯期间静止 <1cm 持续 >1s | -2（仅一次） |
| 出口完成 | 1 | 未触发出口传感器 | -1 |

距离 >100cm 视为无效；入口/出口 50ms 防抖。

### 1.3 灯时序与评分端硬件（scoring_system.c 源码核实）

红 `random(15000,18001)`ms → 绿 `random(2000,4001)`ms → 黄 3000ms 固定，循环不止；VL53L0X 激光测距判"是否停止"（-10mm 偏移修正）；E18-D80NK 红外驱动停止线三态（ARRIVED/AT_LINE/CROSSED）；入口/出口 E3F-DS30C4 光电。

### 1.4 由规则反推的机器人侧硬约束

| # | 约束 | 推导 |
|---|---|---|
| C1 | 绿灯响应链路 ≤ ~1.5s | 绿灯窗口最短 2s；错过仅 -1 但要再等红 15~18s |
| C2 | 红灯感知+刹停 ≤1s，且末段单步位移 <3cm | 评分宽限恰 1s；go_forward 一步 5cm>3cm 必吃罚，末段必须换 2cm 小步（2cm<3cm，红灯杀到也免罚） |
| C3 | 过线判定后禁止一切停止 | 过线后红灯期静止 1s 即 -2；黄灯固定 3s，过线后紧接着就是红 |
| C4 | 灯序可预测 | 黄灯固定 3s → 见黄即知红将至；见转绿即知 5~7s 后（绿 2~4 + 黄 3）转红，可用于步序规划 |

## 2. 当前逻辑（baseline `traffic_light_complete.py`）

### 2.1 架构
单文件脚本，三态状态机 APPROACH → FAST_PASS → FINISHED；主循环按帧数驱动（>800 帧超时），异常打印后 sleep 0.3s 继续。

### 2.2 取流（:102-118）
**每帧开关摄像头**：`VideoCapture(CAP_V4L2)` 打开 → 连设 11 项参数（640×480、饱和度 150、对比度 140、亮度 80、关自动白平衡、色温 4500K、曝光 0.04、增益 40…）→ 读 1 帧 → release；再通道增益去偏色 B×0.6/G×0.7/R×1.1（:134-143）。拍照失败则 `sudo fuser -k` 杀进程重扫设备。

### 2.3 红绿灯识别（TrafficLightDetector, :280-396）
固定 ROI（画面中上 y 12.5%~37.5%、x 25%~75%）→ 2 倍放大+线性增强 → HSV；红双区间 [0,12]∪[155,180]、绿 [40,80]；红绿像素均 <50 判 unknown，否则占比主色（≥1.5×）判定、不足时像素数 2 倍回退；另有"上帧 >1000 像素、本帧骤降 40%"的切换启发式（:358-373）。**决策 1 帧确认**（`CONSECUTIVE_THRESHOLD=1`，且该变量从未参与比较），unknown 帧锁存返回上一非 unknown 决策（:386-392）。

### 2.4 停止线与过线（:199-277, :511-540）
AprilTag tag36h11 过滤 ID 75；距离 = 40mm × **550px 经验焦距** ÷ Tag 平均像素边长（未标定）。过线五条件任一：① 距离 <300mm；② 见过完整 Tag 后 Tag 消失；③ Tag 不完整（出画 15px）且 <500mm；④ 灯环像素双低且最近距离 <500mm；⑤ **distance=0（没测到 Tag）→ 直接快速通过**（:512-518）。

### 2.5 决策与运动（:463-617）
红灯 → `stand` 停车；绿灯 → 继续；unknown ≤5 帧继续走、超限快速通过（:571-576）；红灯停车中丢灯 → `red_to_unknown_mode` **边盲走边识别**（:470-473）。运动仅 stand / go_forward / go_forward_fast 三个开环动作组，无转向、无循迹、无定位闭环。FAST_PASS：每轮 `go_forward_fast`×3、计数 +3、上限 10 → **实际跑 4 轮 = 12 快步**（:608-614），不检测出口。

### 2.6 评分端（了解规则用）
ESP32 非阻塞轮询：灯序状态机 + 入口防抖 0.5s 宽容 → 开始评分 → 停止线三态 + VL53L0X 移动检测 → 扣分 → 出口触发上传 JSON → 10s 后重置。

## 3. 不足之处

### A. 响应延迟（直接丢分）
1. **每帧开关摄像头**：单帧数百 ms~1s+，叠加阻塞动作组（go_forward 一步约 1~2s），决策周期约 2~3s（需实测）。对照 C1/C2：绿灯一个窗口只够看 1~2 帧；红灯亮起后 2~3s 才刹住、超出 1s 宽限，一步 5cm 当场被抓 -3。
2. 超时按帧数而非墙钟（:619），实际超时不可控。

### B. 识别链路脆弱
3. **1 帧确认无去抖**：单帧噪声误判绿 → 闯红灯 -3。
4. **unknown 锁存**（:386-392, :363-365）：一旦误判绿灯，后续反光/模糊产生的 unknown 帧全部返回陈旧 green——恰在最容易连片 unknown 的场景里无法自愈。
5. **骤降启发式可凭空造灯色**（:358-373）：运动模糊、曝光跳变即可触发假"切换"。
6. **无黄灯处理**：黄必然落 unknown，靠 5 帧容忍赌命；黄灯 3s 本是错过绿灯后的"第二次通行机会"（说明书明示可通行），白白浪费。
7. **四级参数串联过拟合单场地**：相机参数→去偏色→ROI 增强→HSV 阈值，一处变动全链失效；README 自认"需现场调整"。

### C. 高危决策分支
8. **distance=0 直接冲**（:512-518）：开局逆光/距离远导致 Tag 漏检，就在灯色未知时闯红灯——最危险分支；且 `has_tag=False` 时 distance 恒 0，与"真过线后 Tag 出画"不可区分。
9. **红灯盲走模式**（:470-473）：停车中丢灯就边走边找——若未到线，评分端 VL53L0X 直接看到 >3cm 位移 -3；还可能盲走出线，之后遇红再停触发"过线后停车" -2。
10. **过线后纯开环 12 快步**：少一步停在关卡内 -1（出口），多一步冲出 1m 场地；中途动作组失败停住，正撞"过线后红灯静止" -2。

### D. 工程质量
11. 无转向/循迹闭环：双足步态漂移同时破坏 Tag 观测角与灯环 ROI 取景（ROI 与 1550 抬头角、灯环安装高度强耦合）。
12. 停车无位置管理：红灯在哪抓到就停哪，不按距离降速、不检查压线。
13. 裸 except 吞异常继续跑（十余处）；相机持续失败时每帧重走 `fuser -k`（可能误杀进程）。
14. 死代码：`CONSECUTIVE_THRESHOLD`（:296）、`light_history`/`LIGHT_SEEN_THRESHOLD`（:446-448）声明即终。
15. 测距无标定无滤波：单帧噪声直接触发过线判定。
16. 视觉/决策/运动全耦合单文件 while，不可单测、不可仿真。

评分端小瑕疵（预研了解）：WiFi 阻塞+凭据硬编码；"未触发出口扣 1 分"为不可达死分支（:479-481 仅在出口已触发时调用）；VL53L0X 阻塞测距拖慢主循环；测试程序与主程序库/黄色 RGB 不一致；timestamp 为开机秒数。启示：**评分端源码在手 = 扣分阈值全部已知，可自建仿真评分器离线回放验证策略**。

### baseline 可取之处
三态状态机骨架贴合评分规则；过线多条件兜底思路正确；整套现场调参（HSV、相机参数、焦距 550/Tag 40mm/300mm）是宝贵初值；灯时序与扣分阈值可从源码精确复得。

## 4. 我的方案

### 4.1 目标与验收
- **策略优先级：绝不闯红灯 > 过线不停车 > 抢绿灯**（期望损失 -3 > -2 > -1；错过一个绿灯只 -1，闯一次红灯 -3）。
- 响应指标：绿灯亮起 → 首步 ≤1.5s；红灯亮起 → 1s 宽限内刹停（末段单步 ≤2cm）。
- 交付：`levels/traffic_light.py` + `main.py` 注册一行；本报告归档；（可选）回放评分器。

### 4.2 架构：复用仓库分层，只新增关卡文件
```
levels/traffic_light.py      ← 唯一新代码：FSM + 评分策略 + 阈值
 ├ vision.ColorBlobDetector  ← 红绿黄 HSV（红色双段合并已有先例）
 ├ core.RobotState.detect_apriltag + solve_pnp ← Tag75 测距（标定内参替代 550px）
 ├ core.RobotState.act       ← 已标定步长表（go_forward 5cm / one_step 2cm / 转向 22°~25.7°）
 └ main.py LEVELS["traffic_light"] 注册
```
不重写底层：相机内参与动作步长是两关卡实机标定资产；vision 层只做"看图→给结果"，阈值与决策留在关卡文件（仓库分层铁律）。

### 4.3 取流链路（头号决策点）
- 现状矛盾：主链路 fswebcam 2592×1944 实测 2~4s/张（九宫格教训），绿灯窗口仅 2~4s。
- **方案 a（首选）**：fswebcam 降 640×480 + `-S 1`，上机实测单帧耗时，预期 <1s；好处是全链路不动、debug_server 被动镜像（监听 photo_*.jpg）继续可用。
- **方案 b（兜底）**：V4L2 常驻流（同 baseline），每 N 帧落盘一张 photo_*.jpg 保住调试镜像；或接受关卡运行期调试降级（调试图落盘+离线回放）。
- **流水线优化**：动作组执行期间后台线程预拍下一帧（fswebcam 走 USB、动作组走舵机串口，互不冲突），把决策周期从"走+拍"叠加变为 max(走， 拍)。
- 定案动作：现场用 `exec_on_robot.py` 实测两档耗时，数据说话。

### 4.4 感知层
- **灯色**：ColorBlobDetector 三套 HSV——红双段、绿、**黄 [20,35] 新增**（错过 2~4s 绿灯后，3s 黄灯是第二次通行机会）。HSV 初值抄 baseline，现场抓图用 `tools/debug_vision.py` 离线调；ROI 用"pitch 档位 → 灯环落点"一次性标定（沿用 nine_grid 双 pitch 档经验），运行期头部不动。
- **停止线**：detect_apriltag(ID75) + solve_pnp 标定内参测距（640×480 下内参按 2592 缩放），滑窗中值滤波。距离分档：>55cm 巡航（go_forward）→ 55~30cm 慢凑（one_step 2cm）→ <30cm 停车点保持，保证红灯亮起时最后一步 ≤2cm<3cm 免罚。停车点距离现场标定。
- **升级备选**（仅当现场光照下 HSV 不稳）：按 ball_v1 全流程训练 traffic_light_v1 YOLO（采集→标注→容器云训练→onnx→models/README 登记→bench ≤1000ms 验收）；OnnxYoloBackend 必须显式传 `names={0:red,1:green,2:yellow}`。

### 4.5 决策层：多帧投票 + 三态跟踪 + 保守 unknown
- **灯色投票**：滑窗 3 帧多数决 + 换色需连续 2 帧新色；unknown **不锁存旧色**，按位置降级——未到线按红灯处理（安全侧），过线后无视灯色（冲刺中）。
- **内部跟踪评分端三态**（未到线/在线上/已过线，baseline 完全没有）：由 Tag 距离+完整性+消失时序推断，留安全余量（评分端以 E18-D80NK 为准）。
- **红灯**：分档降速已保证末段小步；停稳 = stand + 位移零点重置，此后原地只识别不动。
- **绿灯/黄灯确认** → 立即 go_forward 起步（5cm 步幅 >> 0.3cm 阈值），目标 1.5s 内启动；起步后连续行走直至过线，过线即 CROSS 无条件冲刺（不看灯不停步，杜绝 -2）。
- **步序纪律（利用 C4 可预测性）**：确认红灯后是安全的迈步窗口（红 ≥15s 剩余）；见黄灯未到线时二选一——够近则 3s 内冲刺过线，不够近则停车点等红（合规）；将巡航步约 7%/步的红灯起步风险压到最低。
- **unknown 兜底**：未到线且 unknown → 停车点等待（等错最多 -1，走错最少 -3）；全程从未见过灯环 → 先做 pitch 重标定重试，仍失败则停在停车点保 8 分底（10 - 绿灯 1 - 出口 1），好过盲闯最多 -5。
- 看门狗：全局限时按墙钟，超时安全停车。

### 4.6 测试与上机路径
1. PC 离线：现场抓图 → debug_vision.py 调三色 HSV 与 ROI；
2. （可选）回放评分器：把 scoring_system.c 扣分规则复刻成 Python，对录制的（灯色序列 × 动作时序）离线算分，调投票窗口与降速档；
3. 真机分阶段：① 定点识别（测取流延迟+识别率，**关卡门禁**）→ ② 无灯接近与停车点控制 → ③ 全流程连跑；
4. 部署：sync_to_robot.py 同步、exec_on_robot.py 远跑、debug_server 被动看图。

### 4.7 风险与开放问题

| 风险 | 应对 |
|---|---|
| fswebcam 640×480 仍 >1.5s/帧 | 切方案 b 常驻流 |
| 场地地板打滑致 go_forward 不可用（九宫格先例） | 现场判定，全程退化 one_step 小步 |
| 灯环安装高度/视角与参考不同 | pitch 一次性重标定 |
| Tag75 与物理停止线相对位置未知 | 现场量尺 + 定点试停标定 |
| 现场光照使 HSV 失效 | 启动 YOLO 备选链路（4.4） |
