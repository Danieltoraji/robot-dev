# 攻克"数字宫格"关卡实施方案

## 一、原算法分析（reference code 九宫格视觉导航，清华队已验收方案）

### 优点（直接继承）
1. **三信息融合**：颜色权重 0.7 主判 + HOG+SVM 数字 0.2 + 洞分析 0.1，符合关卡"颜色为主、数字为辅"的设计意图；
2. **视觉闭环范式**：每步动作→重拍→重识别→修正，无里程计，天然抗打滑累积误差；
3. **自适应小转向**：EMA(α=0.3) 在线估计每次小转的实际角度，低于 0.5°/次判"被地面吞掉"即升级大转——这正是打滑地面的标准补偿，比本机"直接弃用小转"更优；
4. **卡滞恢复**：目标框 proximity 无改善 → 后退+越障脱困；
5. **到达判定三段式**：低头看颜色"出现→压过→消失"，不需精确测距；
6. 双姿态（前视/低头）搜索、per-id 阈值表现场可调。

### 不足（本次改造点）
1. **两套 HSV 阈值并存**（identify.py 与 extract_digit_roi.py 数值不一致）→ 收敛为单一阈值源；
2. **位姿估计粗糙**：`yaw = -(dx/W)×FOV` 线性近似 + proximity=bbox 宽，无透视/畸变校正（本机实测边缘畸变 12~13%）→ 改用地面单应；
3. **紫色(6号)阈值 0.002/0.003 极敏感**，靠特判防死锁 → 用统一色块几何校验替代纯占比阈值；
4. **无超时/无时间预算**，`while True` 裸奔 → 加全局与分阶段预算；
5. **无布局先验**，每个目标原地旋转搜索，转向次数多（打滑场地高风险）→ 开局全场布局预扫；
6. **停点靠后**："压过颜色消失"在 33cm 小面板上可能走出面板 → 改为单应定位中心+蹭步冗余；
7. 其机器上小步转向有效，但**本机曾实测不可靠**（levels/goodluck.py 已弃用）→ 不能照抄，列入 P3 实测项，用参考方案的 EMA 自适应做在线裁决。

## 二、视觉方案（回答"数字还是颜色 / HSV 还是 RGB / 矩形中心"）

**主判 = 颜色，用 HSV，不用 RGB**。理由：关卡设计即颜色↔数字一一映射（1红…7粉），色块占面板 2/3 面积，远距可识别；HSV 把亮度 V 分离，H 色相对光照/白平衡鲁棒，RGB 在反光下三通道同变区分度差；仓库全部先例（ColorBlobDetector/LineDetector/参考方案/HSV 标定工具）均为 HSV。吸收参考教训：绿色不用简单长方体（H∈[100°,160°] 且 S/V≥1.15），蓝色用 H 条件动态 S 阈值，现场用 trackbar 工具 3 分钟重标。

**数字仲裁 = 复用参考 HOG+SVM pkl（已选定）**。黑色数字 mask 用参考的"主色 HSV 距离 + Otsu"相对阈值提取（对光照稳），HOG 参数必须与 pkl 训练一致（64×64、orientations=9、cell 8×8、L2-Hys）。角色定位：**只仲裁否决，不作主判**——颜色判 k 而 SVM 强支持 j≠k 时把该格标记"待近距复核"，接近时低头多帧投票再定。

**矩形中心 = 地面单应（逆透视）**，正面回答内参/畸变影响：
- 管线：色块轮廓点 → `cv2.undistortPoints`（用 core/camera_config.py 现有内参+畸变系数）→ 归一化平面 → 单应 H → **地面坐标系** → 对地面多边形取质心/minAreaRect 中心 → 输出目标面板中心在机器人系的 (x, y, 方位角)。
- 透视收缩与径向畸变在这一步一次性校正，精度远超 bbox 宽度近似；且直接给出距离/横偏，取代 proximity 启发式。
- H 标定：机器人站固定标定位、俯仰档固定（前视 1200 / 低头 1040 各一套），对 4+ 个已知地面坐标点（宫格网格交点）点击标定、最小二乘求解，存 JSON。不做全图 warpPerspective（符合仓库"识别在像素空间、仅度量校正"的既定决策，计算量也小）。
- **开局布局预扫**：入口处高俯角档头部扫描 3~5 位，经单应一次性解出 3×3 全场地图（每格颜色→数字+地面坐标+SVM 校验状态），后续每格导航带先验，大幅减少打滑高风险的原地转向搜索。

## 三、运动方案（小幅度动作 + 大容差算法）

**动作白名单**（全部小幅度，位移用本机实测值）：`go_forward_one_step`(2.0cm，主前进)、`go_forward`(5.0cm，仅远距)、`left_move`/`right_move`(1.9/2.2cm，横向微调)、`back_one_step`(3.2cm，脱困/蹭步)、`turn_left`/`turn_right`(22°/25.7°，兜底)、`turn_*_small_step`(P3 实测后决定，EMA 在线估计失效即弃)、`stand`。**禁用**：`go_forward_fast`、任何批量>3 次、面板上方批量直行。

**FSM（每个目标 k=1..7）**：SEEK（布局地图先验+视觉确认）→ ALIGN（自适应小转批，<0.5°/次失效升级大转）→ APPROACH（闭环小步前进；d>25cm 且航向差<4° 才允许批量 ≤2 次 go_forward）→ ENTER（低头档，横移纠正横偏，one_step 进入面板）→ CONFIRM（足底投影覆盖中心判据 + 蹭步 back_one_step+go_forward_one_step 来回压过微动开关，多帧确认）→ 下一格。

**容错设计**：
- 每步闭环，最大开环段受门控限制（距离+角度+步数三重）；
- 在线动作再标定：EMA 估计每个动作实际位移/转角，打滑自动下调批量与预算；
- 进度守卫：每阶段步数/时间预算；卡滞（连续 2 步距离改善<0.5cm）→ 后退 1 步重识别，卡死才升级 `over_hurdle`（climb_stairs 仅作最后手段）；
- 丢失守卫：停→低头扫→前视扫→回退 1 步→小角转扫，用布局地图重投影找回；
- 缝隙/高低差/变形：只用小步进出面板；不在面板边缘 1/3 区转向；大转尽量安排在空格/入口区；
- 全局时间预算：15min = 布局预扫 ~30s + 每格 ~110s；超时只降级动作幅度，**绝不跳格**（跳格断 70 分计分链；已读 .ino 确认顺序错/重复只日志不断链，借道穿越其他面板计分安全）。

## 五、实施阶段

1. **P1 PC 离线**：检测器 + 单应数学 + 单测；用参考代码 ipynb 内嵌照片/现场照片经 tools/debug_vision.py 调参；
2. **P2 FSM + 仿真**：sim/goodluck_sim.py 的 SimRobotState 合成帧验证 FSM 与容错逻辑；
3. **P3 机器人标定**（需机器人在场）：本机动作实测（小转可靠性、one_step 实际位移）+ HSV 阈值 3 分钟重标 + 单应 4 点标定；
4. **P4 联调固化**：单格 go_to 验证 → 1→7 全流程计时 → 参数固化 → 文档收尾（sync_to_robot.py 同步，exec_on_robot.py 远程验证）。

## 六、验收标准

- 视觉：照片集七色分类正确；数字仲裁低误报；中心定位误差 <2cm @1m 距离；
- 运动：单格到达成功率可重复；全流程 <15min（目标 <12min，给 30 分完成分留余量）；
- 容错：人为挪偏面板/模拟打滑后能自恢复，全程无摔倒。
