# 调试工具链计划：被动镜像调试服务器 + PC 端 YOLO 检查器

## 架构总览（回答三个问题的设计结论）

```
机器人（关卡正常运行，零改动）              PC 浏览器
┌─────────────────────────┐          ┌──────────────────────┐
│ 关卡: 拍照→落盘 photo_*.jpg│  ~1s 轮询  │  <img> 原始照片        │
│      → AprilTag/YOLO 定位 │ ◄──────► │  <canvas> 叠加层绘制   │
│                           │  HTTP    │  ☑tag ☑yolo ☑digit   │
│ debug_server.py(独立进程)  │          │  状态栏: 时间/延迟/定位 │
│  · 看门狗: 监视新照片       │          └──────────────────────┘
│  · 分析器: tag/yolo/digit  │
│  · HTTP: /photo /api/state │
└─────────────────────────┘
```

**Q1 答案**：服务器是独立进程，**永不打开摄像头**——只监视关卡正常落盘的照片（`/home/pi/Pictures/photo_*.jpg`）。关卡零改动；浏览器轮询最新照片 + 结果 JSON（与你的设想一致）。
**Q2 答案**：图像分析在**机器人端**做（它有模型和标定上下文，结果就是部署真实形态）；**叠加绘制在 PC 浏览器**（服务器只发原图 JPEG + 坐标 JSON，前端 canvas 画框，勾选框按能力开/关各图层，机器人零绘制负担）。
**Q3 答案**：另建 PC 端 `tools/yolo_inspect.py`——cv2 窗口 GUI，专验模型本身，与机器人完全解耦。

## 性能预算（明确写进设计）

分析器独立开关（网页 POST /config 实时生效），**只处理新到的照片**（事件驱动，一张只分析一次；无新照片时看门狗只扫目录名，≈0 开销）：

| 分析器 | 单张耗时（RPi5 量级） | 默认 |
|---|---|---|
| tag（apriltag + PnP 定位） | ~100-150ms | 开 |
| yolo（OnnxYoloBackend 640） | 157ms（实测） | 开 |
| digit（数字模板匹配） | ~50-100ms | 关（缺模板自动跳过） |
| 红线循迹 | — | **v1 不含**（巡线关卡专用，需要时按同接口加分析器即可） |

三开最坏 ~400ms/张 vs 关卡拍照间隔 2~5s：独立进程、单核占空比 ~15%，对闯关零影响。**debug_server 未启动 = 服务器侧零分析**。浏览器轮询只取缓存，不触发分析。

## 交付物 1：`tools/debug_server.py`（机器人端，~300 行，纯标准库 HTTP）

- **看门狗线程**：每 0.5s 扫描 `photo_*.jpg` 取 mtime 最新者；**写完整性判定**（大小稳定 + JPEG 尾标记 FFD9——复用 capture_dataset 踩坑经验，杜绝读到半张照片）；仅新照片触发分析
- **三个分析器**（懒加载、独立开关）：
  - **tag**：apriltag 检测 → 每标签 id + 4 角点像素坐标；尝试 PnP 定位（复用 `solve_pnp_pose` + `levels.goodluck.tag_poses` + `TAG_CORNER_PERM`，try/except 优雅降级）→ 输出位置(cm)/朝向/重投影误差/合理性门控
  - **yolo**：`OnnxYoloBackend(models/football_goal_ball_v1_640.onnx, conf=0.45)` → Detection 列表
  - **digit**：`DigitRecognizer`（模板缺失自动跳过并提示）
- **HTTP 端点**（stdlib ThreadingHTTPServer，复用 camera_preview 骨架）：`GET /`（内联 HTML+JS 页面，无外部依赖）、`GET /photo`（最新原图 no-cache）、`GET /api/state`（结果 JSON + 照片时间戳/年龄/各分析器状态）、`POST /config`（分析器开关）
- **前端**：图片 + canvas 叠加；勾选框两组——「分析器开关」（控制机器人端是否跑）与「图层显示」（tag 角点/tag id/定位文本/YOLO 框/conf/digit，纯前端显隐）；状态栏：照片年龄、检出计数、定位坐标
- **部署**：sync_to_robot 同步；运行 `/home/pi/jupyter-env/bin/python3 tools/debug_server.py --port 8081`（apriltag/onnxruntime/cv2 都在 jupyter-env；8081 避开 camera_preview 的 8080 与 Jupyter 的 8888）

## 交付物 2：`tools/yolo_inspect.py`（PC 端，~150 行）

- cv2.imshow 窗口：`--dir` 图片文件夹 + `--model`（默认 models/football_goal_ball_v1_640.onnx），逐张 `OnnxYoloBackend` 推理
- 显示：框 + `label conf`；trackbar 实时调 conf 阈值；序号/检出数信息
- 快捷键：`D`/`A` 翻图、`S` 保存标注图、`Q`/`ESC` 退出
- 用途单一：**离线验证模型本身**（任意图片文件夹皆可，含实拍新样本），与机器人解耦

## 交付物 3：文档

`docs/视觉能力/视觉调试指南.md` 增加"三工具分工"小节：camera_preview（机器人空闲时实时直播，独占相机）/ debug_server（闯关运行中被动镜像，不占相机）/ yolo_inspect（PC 离线验模型）。

## 不做的事

- 不改 core/levels/main.py 任何一行（零侵入）
- 不做 MJPEG 实时视频流（照片节奏 1~2s，轮询足够）
- 不做历史回放、多客户端同步；红线循迹分析器 v1 不含
